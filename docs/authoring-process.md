## 0. Подготовка

npm install

node tools/e2e/checks/platform.mjs   # «Всё прошло»

Прочитать: строки главы в `course-plan.md`, что глава добавляет в магазин (`project-app.md`), последний шаг прошлой главы целиком (`npm run step content/<глава>/<последний шаг>/solution`), библиотеки главы в `libraries.md`, пункты главы в `modern-react.md` («Ожидается — проверить»).

## 1. Сверка API до написания кода

Никаких утверждений по памяти: память модели — это в основном React 16–18 и старые мажорные версии библиотек. Для каждой библиотеки главы:

```bash
cat node_modules/<пакет>/package.json | grep '"version"'
node -e "console.log(Object.keys(require('<пакет>')).sort().join('\n'))"   # CJS-экспорты
ls node_modules/<пакет>/dist                                                # ESM — читать .d.ts
```

Проверять: сигнатуры, **значения по умолчанию**, стабильность (`canary.d.ts`, `experimental.d.ts`, префикс `unstable_`), поведение (development-сборка). Если библиотека новая для превью — сначала добавить её в vendor (`scripts/copy-vendor.mjs`), типы — в Monaco, и прогнать `checks/preview.mjs`. Проверенное — в `modern-react.md`, таблица «Проверено».

## 3. Проверка запуском до текста

Как в angular-learn (`run-dir.mjs`, `exp.mjs`, скриншот глазами). Дополнительно для React:

- **считать рендеры и порядок эффектов логом**, а не рассуждением; помнить, что в превью StrictMode (если он в `main.tsx`) удваивает рендер и цикл эффектов — в тексте говорить, с StrictMode число или без;
- консоль без предупреждений React (`key`, неуправляемое → управляемое поле, `act`, гидратация) — кроме тех, что шаг показывает намеренно;
- для глав с запросами — проверять гонки и отмену по вкладке «Сеть» с задержкой 1000–3000 мс.
