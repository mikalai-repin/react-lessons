# Как писать уроки

Основа — `../angular-learn/docs/writing-guide.md` (тон, структура шага, размер превью, проверка фактов). Здесь — то же, адаптированное под React, и правила для кода.

## Читатель

Разработчик, который уверенно пишет на JS/TS и знает веб, но **не писал на React** (или писал поверхностно). Цель — уровень senior: понимать механизм, а не только API.

- JS/TS, `async/await`, модули, DOM, CSS **не объясняем**. Исключение — то, что в React используется особенно часто: неизменяемые операции с массивами (`toSorted`, `with`, spread), замыкания (в связи с «устаревшими замыканиями» в эффектах) — коротко, при первой встрече.
- Всё про React и библиотеки объясняем с нуля, каждый термин — при первом появлении (по `glossary.md`).
- Сравнения с Angular/Vue — только во врезках `::: tip` и когда помогают («`useMemo` похож на `computed` в Angular, но зависимости вы перечисляете сами — пока не включён компилятор»).
- Не пишем «просто», «очевидно», «как известно», «магия».

## Тон

- Обращаемся на «вы», дружелюбно, без канцелярита. Короткие предложения. Один абзац — одна мысль.
- Сначала **проблема, видимая в превью**, потом решение («Мы нажали „В корзину“ трижды, а счётчик вырос на 1. Почему?»).
- Имена API не переводим: `useState`, `Suspense`, `QueryClient`.
- «ё», «ёлочки», тире «—». Название проекта — «Ход конём».

## Структура шага

Как в angular-learn: **зачем → объяснение (со схемой для деревьев и потоков: дерево компонентов, рендер/commit, поток данных, жизненный цикл эффекта, кэш запросов) → код с подсветкой новых строк → `::: task` → что получилось (превью, консоль, «Сеть») → эксперимент → как в настоящем проекте → `::: deep` / `::: legacy`**. Шаг — 300–900 слов, одна новая идея. Шаг 1 главы — вводный. Практикум: `::: task` со списком, `::: hint` от общего к конкретному, «Проверьте себя», «Итоги главы» с мостиком к следующей.

**Главный инструмент React-курса — эксперимент с логом:** «добавьте `console.log('render GameCard', id)` и нажмите кнопку — сколько строк появилось?». Количество рендеров, порядок эффектов, повторный запуск в StrictMode — показывать, а не утверждать. Каждое число в тексте — увиденное в консоли.

## Правила для кода

- **Только современный React 19 и актуальные версии библиотек.** Запрещённое и замены — `docs/modern-react.md`. Устаревшее — только в `::: legacy` после современного варианта.
- Функциональные компоненты, именованный экспорт: `export function GameCard({ game, onAdd }: GameCardProps)`. Без `React.FC`.
- Props типизируются `type XProps = { … }` рядом с компонентом. `children` — явно `children: ReactNode`.
- Обработчики в props — `onX` (`onAdd`, `onChange`), функции внутри — `handleX` (`handleAddClick`). Проверить, нет ли в официальной документации иной рекомендации.
- Состояние — минимальное; производное — вычисляется при рендере. Эффект — только для синхронизации с внешней системой (в тексте каждого эффекта ответить: «с чем синхронизируем?»).
- Неизменяемые обновления; мутация допустима только внутри Immer/RTK, и это объясняется.
- До главы 16 — без `useMemo`/`useCallback`/`memo`, кроме случаев, когда шаг объясняет, зачем они нужны (стабильная зависимость эффекта и т. п.).
- Импорты именованные: `import { useState } from 'react'`. `import React` не нужен.
- TypeScript строгий, без лишних аннотаций: типизируем props, публичное API хуков и сторов, модели данных (`api/models.ts`), действия редьюсеров (discriminated union).
- Ключи списков — устойчивые id из данных, не индекс (кроме шага-эксперимента).
- Доступность — с самого начала: `<button>` для действий, `<label>` у полей, `alt` у картинок, роли там, где нужно. Тесты в главе 17 опираются на роли.
- Комментарии — на русском, короткие, объясняют «зачем». Тексты интерфейса — на русском; цены — `Intl.NumberFormat('ru-RU', …)` (с главы 2 — функция `formatPrice` в `shared/format.ts`).
- Магические числа и строки — в константы.
- Код шага растёт постепенно: не больше ~30 новых строк за шаг.

## Размер превью

Как в angular-learn: около **500 × 600**; вёрстка «от мобильной», сетка карточек `auto-fill`. Компоненты antd (глава 15+) проверять в этой ширине — таблицы antd широкие (`scroll={{ x }}`, адаптивные колонки).

## Квиз главы

Формат — `docs/lesson-format.md`, «Квиз главы». Квиз закрепляет главное из главы, а не мелочи и формулировки.

- 10–15 вопросов, шаги главы покрыты примерно поровну; треть — с коротким фрагментом кода («что отрисуется», «что выведет», «где ошибка»).
- **Каждый факт, от которого зависит ответ, уже есть в тексте уроков этой главы** (а значит, проверен запуском). Квиз не вводит новых фактов и не спрашивает о том, чего в главе не было. Ответ на «что выведет» — только из лога, который приведён в уроке.
- Ровно один верный ответ. Неверные варианты — типичные заблуждения (ожидания из Angular, React 16–18, «как в HTML»), но однозначно неверные.
- Варианты одинаковой длины и подробности: правильный не должен выделяться. Без «все перечисленные», «ни один из вариантов», «оба варианта» — варианты перемешиваются.
- `explanation` — почему верный ответ верен, при необходимости — чем плох популярный неверный; ссылка на шаг словами.

## Проверка фактов

- Любое утверждение об API — по типам и исходникам установленной версии (`docs/modern-react.md`, «Как искать в исходниках»), при сомнениях — экспериментом в превью.
- Осторожно со значениями по умолчанию библиотек (`staleTime: 0`, `retry: 3` в Query; `mode: 'onSubmit'` в RHF и т. п.) — проверять в установленной версии.
- Стабильность API (`canary`, `experimental`, «unstable_») — говорим ученику прямо.
- Тексты предупреждений и ошибок React — только увиденные в консоли превью.
- **Отличия превью от настоящего проекта** называем явно: dev-сборка (предупреждения, StrictMode), нет HMR (перезапуск целиком), нет линтера, нет SSR.
