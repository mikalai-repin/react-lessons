Этот шаг необязательный. Магазин стал деревом из шести видов компонентов. Разберёмся, что происходит, когда React его рисует: кто кого вызывает, в каком порядке и что React запоминает между рендерами. Это основа для всего, что будет дальше: состояния (глава 4), сохранения и сброса состояния (глава 5), эффектов (глава 6).

## Элементы — описание, а не вызов

Вспомните главу 1: JSX — это вызов `jsxDEV`, который возвращает объект-элемент. Посмотрим, что возвращает `App`:

```tsx
jsxDEV(Section, {
  title: 'Хиты',
  extra: jsxDEV(Badge, { tone: 'dark', children: hits.length }),
  children: jsxDEV('div', { className: 'grid', children: … }),
})
```

В элементе `Section` лежит **сама функция** `Section` в поле `type` и её будущие props. Функцию никто не вызывал: `App` только описал, что здесь должен быть раздел с такими props. Это легко проверить — добавьте в конец `main.tsx`:

```tsx main.tsx
const element = App();
console.log(element.type, element.props.children.map((c) => c.type.name ?? c.type));
```

В консоли — `Symbol(react.fragment) ["Header", "main"]`: `App` вернул фрагмент с двумя детьми. Ни шапки, ни карточек в этом результате нет — только элемент с типом `Header` и элемент `main`, внутри которого описаны разделы. (Редактор подчеркнёт `c` — у параметра нет типа; для эксперимента это неважно.) Уберите строки.

Так что «дерево элементов» никогда не существует целиком. Каждый компонент возвращает свой кусочек — один уровень своих элементов. Раскрывает дерево React.

## Обход в глубину

Добавьте `console.log` в начало каждого компонента: `'App'`, `'Header'`, `'Section', title`, `'GameCard', game.title`, `'Badge', children`, `'Button'`. Первые строки лога (строгий режим удваивает каждую — смотрите на счётчик):

```
App
Header
Section Хиты
Badge 3
GameCard Остров сокровищ
Badge ["−", 20, "%"]
Badge Хит
Button
GameCard Ночной экспресс
…
```

React вызвал `App`, получил элементы и пошёл по ним **в глубину**: встретил `Header` — вызвал, у шапки нет дочерних компонентов — вернулся и пошёл к `main`, внутри — `Section` «Хиты». Раздел вернул шапку с бейджем и сетку карточек, поэтому `Badge 3` идёт **раньше** карточек: он стоит в разметке раздела первым. Затем первая карточка и всё, что внутри неё, и только потом вторая. Уберите `console.log`.

## Файберы — что React хранит

Для каждого элемента, который он встретил, React создаёт и хранит объект — **файбер** (fiber, «волокно»). Файбер помнит:

- `type` — функцию компонента или имя тега;
- `key` и props последнего рендера;
- для тега — настоящий DOM-узел;
- ссылки на родителя (`return`), первого ребёнка (`child`) и соседа (`sibling`);
- состояние компонента — о нём в главе 4.

Дерево файберов и есть **дерево компонентов**: оно живёт между рендерами, а элементы — одноразовые описания, которые создаются заново при каждом вызове. Загляните в него — React хранит ссылку на файбер прямо в DOM-узле, в поле `__reactFiber$…`. Добавьте в конец `App.tsx`:

```tsx App.tsx
setTimeout(() => {
  const button = document.querySelector('button');
  const key = Object.keys(button!).find((k) => k.startsWith('__reactFiber'))!;
  let fiber = (button as any)[key];
  const path: string[] = [];
  while (fiber) {
    const t = fiber.type;
    path.push(typeof t === 'function' ? t.name : typeof t === 'string' ? t : String(t?.description ?? t));
    fiber = fiber.return;
  }
  console.log(path.join(' ← '));
}, 100);
```

От первой кнопки вверх по ссылкам `return`:

```
button ← Button ← article ← GameCard ← div
← section ← Section ← main ← App
← react.strict_mode ← null
```

В этой цепочке есть всё, чего нет в DOM: компоненты `Button`, `GameCard`, `Section`, `App`, строгий режим и корень (`null` — файбер, созданный `createRoot`). А фрагмента `<>` из `App` нет: фрагмент на верхнем уровне компонента React не превращает в отдельный файбер. Уберите эксперимент.

```
дерево компонентов        DOM
(файберы)
App                       ─
├─ Header                 ─
│  └─ header              <header>
└─ main                   <main>
   └─ Section             ─
      └─ section          <section>
         └─ div.grid      <div>
            └─ GameCard   ─
               └─ article <article>
```

## Зачем это знать

При следующем рендере React снова вызовет компоненты и получит новые элементы. Их он **сверяет** с файберами — так же, как списки в главе 2: на том же месте тот же `type` и тот же `key` — файбер остаётся, обновляются props и DOM. Другой `type` — старый файбер вместе со всем поддеревом удаляется, создаётся новый. Отсюда два правила этой главы:

- **компонент внутри компонента** (шаг 1) — при каждом рендере новая функция, новый `type`, и React пересоздаёт поддерево;
- **`key`** — идентичность файбера среди соседей.

## Компонент — не просто функция

Раз компонент — функция, почему бы не вызвать её самому? Замените в разделе «Хиты» список на `{hits.map((game) => GameCard({ game }))}`. Карточки на месте. Но запустите эксперимент с файберами — путь стал короче:

```
button ← Button ← article ← div ← section
← Section ← …
```

`GameCard` исчез из дерева компонентов. Вы вызвали функцию сами, и её результат — `<article>` — для React выглядит так, будто его вернул `App`. Об этом говорит и предупреждение в консоли: ``Each child in a list should have a unique "key" prop. Check the render method of `App`.`` Ключа нет у `<article>`, а «виноват» `App`. Пока разница незаметна, но в главе 4 у компонентов появится состояние, и оно хранится в файбере компонента. Нет файбера — состояние карточки достанется `App`. Компоненты не вызывают вручную — их рисуют через JSX. Верните `<GameCard key={game.id} game={game} />`.

::: warning
`__reactFiber$…` — внутренности React: имя поля и устройство файбера могут измениться в любой версии. Это инструмент для эксперимента, не для кода. В настоящем проекте то же дерево показывает вкладка **Components** расширения React DevTools — с props, состоянием и тем, какой компонент кого отрисовал. В превью расширение не работает (оно не видит iframe), поэтому мы смотрели вручную.
:::

::: tip
В Angular дерево компонентов — это дерево экземпляров классов, которые создаются один раз. В React дерево компонентов — это дерево файберов, а сами компоненты — функции, которые React вызывает снова и снова. Всё, что должно жить между вызовами, React хранит в файбере, а не в функции.
:::
