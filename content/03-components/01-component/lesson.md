Весь магазин пока живёт в одном компоненте `App`: шапка, акция и сто строк карточки игры. Читать такой код трудно, а использовать кусок разметки во втором месте нельзя — только копировать. В React интерфейс собирают из **компонентов**: небольших функций, каждая из которых отвечает за свой кусочек экрана.

В этой главе `App` превратится в дерево компонентов:

```
App
├─ Header           шапка
├─ Section «Хиты»
│  └─ GameCard × 3  карточка игры
│     ├─ Badge      «−20%», «Хит»
│     ├─ Rating     звёзды
│     └─ Button     «В корзину»
└─ Section «Все игры»
   └─ GameCard × 6
```

По пути разберёмся, как компоненты получают данные (props), как передать в компонент разметку (`children` и «слоты»), почему данные текут только сверху вниз и как типизировать компоненты в TypeScript.

## Что появилось в шаге

Начнём с самого простого куска — шапки. В проекте новая папка `layout` с двумя файлами:

- `Header.module.css` — готовые стили шапки, те же классы `header` и `title`, что в `App.module.css`;
- `Header.tsx` — пока только комментарий `TODO`. Здесь будет компонент.

## Компонент — это функция

Вы уже написали один компонент — `App`. Любой другой устроен так же: функция с именем **с большой буквы**, которая возвращает JSX.

```tsx layout/Header.tsx
import { games } from '../data/games';
import styles from './Header.module.css';

// Шапка магазина: логотип и подпись с числом игр
export function Header() {
  return (
    <header className={styles.header}>
      <h1 className={styles.title}>♞ Ход конём</h1>
      <p className="muted">
        Магазин настольных игр · в каталоге {games.length} игр
      </p>
    </header>
  );
}
```

Разметка перенесена из `App` без изменений. Компоненту нужны массив `games` и стили — он импортирует их сам, теперь из своей папки: `../data/games` и `./Header.module.css`.


`<Header />` — тот самый JSX-элемент, который вы разбирали в главе 1: объект, у которого `type` — функция `Header`. Встретив такой элемент, React вызывает функцию и рисует то, что она вернула.

Регистрировать компонент нигде не нужно. Достаточно импорта: `Header` — обычная переменная модуля, и JSX ссылается на неё по имени.

::: task
1. В `layout/Header.tsx` объявите и экспортируйте функцию `Header`. Перенесите в неё `<header>` целиком из `App.tsx`.
2. Импортируйте в `Header.tsx` всё, что нужно разметке: `games` из `../data/games` и `styles` из `./Header.module.css`.
3. В `App.tsx` импортируйте `Header` и поставьте `<Header />` на место старой шапки.
4. Удалите из `App.module.css` классы `title`, `header` и правило `.header p` — теперь они живут в `Header.module.css`.
:::

## Что получилось

Внешне ничего не изменилось — так и должно быть. Но шапка теперь отдельный компонент. Добавьте в конец `App.tsx`:

```tsx
setTimeout(() => console.log(document.querySelector('header')?.outerHTML), 100);
```

В консоли — `<header class="Header_header_…">`: имена классов CSS Modules начинаются с имени файла стилей, а не `App`. Стили шапки больше не смешаны со стилями страницы. А самого компонента `Header` в разметке нет: в DOM попадает только то, что он вернул. Уберите строку.

Эксперименты:

- **Напишите `<header />` с маленькой буквы** вместо `<Header />`. Шапка пропала, а в консоли — ни одного сообщения. С маленькой буквы JSX считает имя HTML-тегом, а `<header>` — настоящий тег: React честно нарисовал пустой `<header></header>`. Подскажет только редактор: импорт `Header` подчеркнут, `'Header' is declared but its value is never read.` Верните большую букву.
- **Уберите `export`** перед `function Header`. Редактор подчеркнёт импорт в `App.tsx`: `Module '"./layout/Header"' declares 'Header' locally, but it is not exported.` Приложение не запустится: браузер не найдёт такого экспорта при загрузке модулей — `SyntaxError: The requested module 'layout/Header.tsx' does not provide an export named 'Header'`. Верните `export`.

::: warning Не объявляйте компонент внутри компонента
Функцию `Header` можно было бы написать прямо внутри `App` — код бы заработал. Но так делать нельзя: при каждом рендере `App` создавал бы **новую** функцию `Header`, и для React это был бы каждый раз новый тип компонента. Старую шапку он удалял бы из DOM и создавал заново — вместе со всем, что в ней было: текстом в полях, фокусом, состоянием компонента (о нём — в главе 4). Мы проверили: поле ввода внутри такого компонента теряет набранный текст при каждой перерисовке родителя. Компоненты объявляют на верхнем уровне модуля. В настоящем проекте такую ошибку подчеркнёт линтер — правило `react-hooks/static-components` (глава 23).
:::

## Как в настоящем проекте

- **Один компонент — один файл** с тем же именем: `Header.tsx`, рядом `Header.module.css`. Маленький вспомогательный компонент, который нужен только одному соседу, иногда оставляют в том же файле, но тоже на верхнем уровне.
- **Именованный экспорт** (`export function Header`) — так в этом курсе. Встретите и `export default function Header` с импортом `import Header from …`: работает так же, но имя при импорте можно написать любое, и переименовывать такой компонент по проекту сложнее.
- Папки — по смыслу: `layout/` — каркас страницы, `shared/` — общие компоненты. В главе 20 разложим проект по функциям магазина.

::: tip
В Angular компоненту нужны декоратор `@Component`, селектор `app-header` и запись в `imports` того компонента, который его использует. В React ничего этого нет: компонент — функция, а JSX-тег ссылается на неё как на обычную переменную. Нет импорта — TypeScript скажет, что имени `Header` не существует.
:::
