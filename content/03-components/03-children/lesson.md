В карточке три бейджа, и все три собраны вручную: `<span className={styles.badge}>`. Стоит захотеть бейджам разные цвета — придётся править три места, а в магазине бейджи появятся ещё и в корзине, и на странице игры. Нужен компонент `Badge`. Но как передать ему текст? Пропом `text="Хит"` неудобно: в бейдже «Осталось 3 шт.» текст смешан с числом, а завтра понадобится иконка. Хочется писать, как в HTML: `<Badge>Хит</Badge>`.

## children — то, что между тегами

Всё, что стоит между открывающим и закрывающим тегом компонента, React передаёт в специальном пропе **`children`**:

```tsx
<Badge tone="warning">Осталось {game.inStock} шт.</Badge>
//                    └──── props.children ────┘
```

Компонент сам решает, куда поставить `children` в своей разметке:

```tsx shared/Badge.tsx {4-7,10-13,15-17}
import type { ReactNode } from 'react';
import styles from './Badge.module.css';

type BadgeProps = {
  children: ReactNode;
  tone?: 'accent' | 'dark' | 'warning';
};

// Бейдж: короткая метка на цветной плашке — «−20%», «Хит»
export function Badge({
  children,
  tone = 'accent',
}: BadgeProps) {
  return (
    <span className={`${styles.badge} ${styles[tone]}`}>
      {children}
    </span>
  );
}
```

Тип `children` — **`ReactNode`** из `react`: всё, что React умеет нарисовать. Строки, числа, элементы, массивы из них, а ещё `null`, `undefined` и логические значения, которые не рисуются (глава 2). В курсе `children` всегда объявляем в типе props явно — так видно, что компонент принимает содержимое.

## Необязательные props и значения по умолчанию

Второй проп — **`tone`**, цвет бейджа. Знак `?` в типе делает его необязательным: `<Badge>Хит</Badge>` без `tone` — тоже правильный код. Тип — объединение строк: передать можно только один из трёх тонов.

Если `tone` не передали, в props его нет, и при деструктуризации получилось бы `undefined`. Поэтому в параметре стоит **значение по умолчанию**: `tone = 'accent'`. Это обычная деструктуризация JavaScript: значение подставляется, когда поле равно `undefined`.

По тону выбирается класс: `styles[tone]` — это `styles.accent`, `styles.dark` или `styles.warning` из `Badge.module.css` (стили уже готовы). Классов у бейджа два: общий `badge` и класс тона.

В карточке бейджи теперь читаются как текст:

```tsx shared/GameCard.tsx {3,7,9,12-14}
import { Fragment } from 'react';
import type { Game } from '../api/models';
import { Badge } from './Badge';
import { formatPrice } from './format';
…
        <div className={styles.badges}>
          {discount > 0 && <Badge>−{discount}%</Badge>}
          {game.rating >= HIT_RATING && (
            <Badge tone="dark">Хит</Badge>
          )}
          {game.inStock > 0 && game.inStock <= FEW_LEFT && (
            <Badge tone="warning">
              Осталось {game.inStock} шт.
            </Badge>
          )}
        </div>
```

::: task
1. В `shared/Badge.tsx` объявите тип `BadgeProps`: `children: ReactNode` и необязательный `tone` — `'accent' | 'dark' | 'warning'`.
2. Объявите и экспортируйте `Badge`: `<span>` с классами `styles.badge` и `styles[tone]`, внутри — `children`. Тон по умолчанию — `'accent'`.
3. В `GameCard.tsx` замените три `<span>` на `<Badge>`: скидка — с тоном по умолчанию, «Хит» — `tone="dark"`, «Осталось N шт.» — `tone="warning"`.
4. Удалите из `GameCard.module.css` класс `badge` — он переехал в `Badge.module.css`. Класс `badges` (контейнер в углу обложки) оставьте: где лежат бейджи, решает карточка.
:::

## Что получилось

Скидка — на красной плашке цвета бренда, «Хит» — на тёмной, «Осталось 3 шт.» — на жёлтой. Посмотрите, что именно получает бейдж. Добавьте в `Badge` перед `return`:

```tsx
console.log(children);
```

В консоли — по бейджу на строку, сверху вниз по карточкам (каждая строка дважды из-за строгого режима — консоль сворачивает повторы в счётчик):

```
["−", 20, "%"]
Хит
["−", 11, "%"]
Хит
["Осталось ", 3, " шт."]
["−", 13, "%"]
Хит
```

У «Хит» `children` — просто строка. А там, где текст перемешан с выражениями, — **массив**: каждый кусок текста и каждое `{…}` стали отдельным элементом. Поэтому не стоит полагаться на то, что `children` — строка: например, вызвать `children.toUpperCase()` можно не всегда. Компонент, который просто ставит `children` в разметку, работает с любым содержимым. Уберите `console.log`.

Эксперименты:

- **Передайте разметку**: `<Badge tone="dark"><b>Хит</b> ★</Badge>`. В бейдже — жирное «Хит» со звёздочкой: `children` может быть и элементом, и смесью элементов с текстом. Верните как было.
- **Оставьте бейдж пустым**: `<Badge tone="dark" />`. Ошибка типов: `Property 'children' is missing in type '{ tone: "dark"; }' but required in type 'BadgeProps'.` Мы объявили `children` обязательным — пустой бейдж не имеет смысла.
- **Передайте `children` атрибутом**: `<Badge tone="dark" children="Хит" />`. Работает и без ошибок типов — это тот же проп, просто записан иначе. Так не пишут, но это хорошо показывает: `children` — обычный проп, который JSX заполняет из содержимого тега.
- **Передайте несуществующий тон**: `tone="danger"`. Редактор: `Type '"danger"' is not assignable to type '"accent" | "dark" | "warning" | undefined'.` Если запустить, у бейджа будет класс `undefined` — такого ключа в `styles` нет. Union-тип в props ловит такие опечатки до запуска.

## Как в настоящем проекте

- **Композиция вместо наследования.** В React не наследуют компоненты друг от друга: «особенная кнопка» не расширяет класс кнопки, а **оборачивает** её или принимает содержимое через `children`. Бейдж не знает, что в нём «Хит», а карточка не знает, как бейдж выбирает цвет.
- Имена тонов — по смыслу, а не по цвету: `accent`, `warning` вместо `red`, `yellow`. Цвета поменяются, смысл останется.

::: tip
`children` — это проекция содержимого, как `<ng-content>` в Angular. Только в React содержимое — обычное значение: его можно вывести в консоль, проверить, обернуть или не показать вовсе (`{open && children}`).
:::

::: legacy Вы встретите в старом коде
Значения по умолчанию раньше задавали свойством функции: `Badge.defaultProps = { tone: 'accent' }`. В React 19 у функциональных компонентов `defaultProps` **не работают**, причём молча: мы проверили — без значения в деструктуризации тон остаётся `undefined`, и у бейджа класс `undefined` без единого предупреждения. Значения по умолчанию — только в деструктуризации. То же касается `Badge.propTypes`: React 19 их игнорирует, типы props проверяет TypeScript.
:::
