В этот шаг пробрались три ошибки. Превью не показывает магазин, а в консоли красная строка. Разберём, как читать сообщения: они бывают трёх видов, и у каждого своя метка и своё поведение.

## Ошибка сборки

Первая строка в консоли — с меткой **«Сборка»**:

```
App.tsx:9 — Expected corresponding JSX closing tag for 'h1'.
```

«Ожидался закрывающий тег для `h1`». Это **синтаксическая ошибка**: код не получается даже прочитать, поэтому приложение не запускается совсем, а превью сообщает, что сборка не прошла. Так же ведёт себя настоящий проект: Vite показывает ошибку и не запускает код, пока её не исправить.

Сообщение начинается с имени файла и номера строки — `App.tsx:9`. Откройте файл: в строке 9 заголовок открыт тегом `<h1>`, а закрыт `</h2>`.

Почините по очереди все три ошибки шага.

1. Исправьте закрывающий тег заголовка.
:::

## Ошибка во время рендера

Код собрался, приложение запустилось — и превью стало совсем пустым. В консоли две новые строки. Первая — предупреждение React:

```
An error occurred in the <App> component.

Consider adding an error boundary to your tree to customize error handling behavior.
```

«В компоненте `App` произошла ошибка». Вторая — сама ошибка:

```
TypeError: Cannot read properties of undefined (reading 'toUpperCase')
    at App (App.tsx:11:31)
    … (вызовы внутри библиотек)
```

Это **ошибка во время выполнения**: код правильный с точки зрения языка, но упал, когда React вызвал функцию `App`. Строки, которые начинаются с `at`, — **стек вызовов**: какая функция где выполнялась в момент ошибки, сверху — самая последняя. Первая строка ведёт прямо к месту: функция `App`, файл `App.tsx`, строка 11, символ 31. Вызовы внутри React превью сворачивает в одну строку — они вам не нужны.

В строке 11 — `hits[0].toUpperCase()`. Массив `hits` пустой, `hits[0]` — `undefined`, а у `undefined` нет метода `toUpperCase`. TypeScript эту ошибку не поймал: для него элемент массива `string[]` — это `string`.

Почему пропала вся страница, а не одна строка? Если компонент падает во время рендера, React не знает, что показать на его месте, и убирает всё дерево компонентов. Перехватывать такие ошибки и показывать запасной интерфейс умеют **границы ошибок** (error boundaries) — о них React и намекает словами «Consider adding an error boundary». Их мы сделаем в главе 11.

::: task
2. Хитов продаж пока нет: удалите строку «Хит недели» и константу `hits` вместе с комментарием над ней.
:::

## Ошибка типов

Магазин снова на экране. Но в консоли осталась строка с меткой **«TS»**:

```
main.tsx:14:10 — Type '{ title: string; }' is not assignable to type 'IntrinsicAttributes'. Property 'title' does not exist on type 'IntrinsicAttributes'.
```

Это **ошибка типов**: TypeScript нашёл несоответствие, но код всё равно запущен. В `main.tsx` компоненту передаётся `title="Ход конём"`, а `App` никаких входных данных не принимает. React на это не обращает внимания — лишнее значение просто никто не читает, — но TypeScript предупреждает: скорее всего, вы ошиблись. То же место подчёркнуто красным в редакторе; наведите на него курсор — появится то же сообщение.

Ошибки типов не останавливают приложение в превью, и так же ведёт себя Vite при разработке. Но проверка типов в настоящем проекте (`tsc` при сборке) не пропустит такой код.

::: task
3. Уберите `title="Ход конём"` в `main.tsx`.
:::

## Итого: три метки

| Метка | Что это | Приложение |
|---|---|---|
| «Сборка» | Синтаксис: код нельзя прочитать | не запускается |
| красная строка без метки | Ошибка во время выполнения, со стеком | падает дерево компонентов |
| «TS» | Ошибка типов | работает, но код подозрительный |

Сообщения React содержат ссылки на react.dev (например, `https://react.dev/link/error-boundaries`): консоль превью делает их кликабельными, и там подробное объяснение.

::: tip Как в настоящем проекте
В настоящем проекте установите расширение браузера **React Developer Tools**: оно показывает дерево компонентов, их данные и подсвечивает перерисовки. В превью курса оно не работает — приложение живёт внутри iframe платформы, — поэтому в главе 23 мы откроем его в проекте Vite.

В продакшен-сборке React сокращает сообщения до кода: `Minified React error #130; visit https://react.dev/errors/130 …` — полный текст по ссылке. Поэтому отлаживать удобнее в режиме разработки.
:::
