Компонент `App` готов, но сам по себе он ничего не делает: это просто функция. Кто-то должен её вызвать и превратить результат в элементы на странице. Это происходит в `main.tsx` — **точке входа** приложения, первом файле, который выполняется.

## Страница и корень

Приложение на React живёт внутри обычной HTML-страницы. В проекте Vite она лежит в файле `index.html`, и в ней почти ничего нет:

```html index.html
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.tsx"></script>
</body>
```

Пустой `<div id="root">` — место, куда React нарисует всё приложение. В превью курса такая страница уже есть, поэтому файла `index.html` в шаге нет.

Дальше работает `main.tsx`. Сейчас он записан одной строкой:

```tsx main.tsx
createRoot(document.getElementById('root')!).render(<App />);
```

В ней три действия:

1. `document.getElementById('root')` — найти элемент `#root` на странице. Это обычный DOM, React здесь ещё не участвует.
2. `createRoot(элемент)` — создать **корень** (root): объект, через который React управляет всем, что внутри этого элемента. Функция `createRoot` — из пакета `react-dom/client`: сам пакет `react` ничего не знает о браузере, а `react-dom` умеет рисовать в DOM.
3. `root.render(<App />)` — нарисовать в корне компонент `App`. React вызовет функцию `App`, получит её разметку и создаст по ней элементы `<main>`, `<h1>`, `<p>`.

Восклицательный знак после `getElementById('root')` — оператор TypeScript «здесь точно не `null`». Он ничего не проверяет: если элемента на странице не окажется, `createRoot` упадёт с непонятной ошибкой. Надёжнее проверить явно.

::: task
Перепишите `main.tsx` по шагам: найдите элемент `#root` и сохраните в `const container`; если его нет — бросьте ошибку `throw new Error('На странице нет элемента #root')`; создайте корень `const root = createRoot(container)` и вызовите `root.render(<App />)`.
:::

## Что получилось

На экране ничего не изменилось — так и должно быть: код делает то же самое, только понятнее. После проверки `if (!container) throw …` TypeScript знает, что дальше `container` — точно элемент, и `!` больше не нужен.

Поэкспериментируйте:

- **Ошибитесь в id**: `getElementById('app')`. Превью пустое, в консоли — ваша ошибка «На странице нет элемента #root». Верните `'root'`.
- **Посмотрите, когда React рисует.** Сразу после `root.render(<App />)` добавьте строку `console.log(container.innerHTML);` — в консоли пустая строка: элемента `<h1>` ещё нет. Теперь выведите то же через `setTimeout(() => console.log(container.innerHTML), 100);` — появится разметка `<main><h1>Ход конём</h1>…`. Вызов `render` не рисует сразу, а только просит React нарисовать: React запланировал работу и выполнит её чуть позже, когда текущий код закончится. Уберите эти строки.

::: deep Под капотом: почему render не рисует сразу
С React 18 обновления экрана **планируются**: React собирает их и выполняет отдельной задачей, а не посреди вашего кода. Так несколько изменений подряд превращаются в одну перерисовку, а срочные обновления (ввод в поле) могут обгонять несрочные. В превью разметка появилась даже позже, чем сработал `setTimeout` с нулевой задержкой, поэтому в эксперименте — 100 мс.

Нарисовать немедленно можно, обернув вызов во `flushSync` из `react-dom`: `flushSync(() => root.render(<App />))`. В приложениях это нужно редко — к планированию мы вернёмся в главе 12 и в части 3.
:::

::: legacy Вы встретите в старом коде: ReactDOM.render
До React 18 приложение запускали одной функцией:

```tsx
ReactDOM.render(<App />, document.getElementById('root'));
```

В React 19 её удалили. Если вы видите такой код, это проект на React 17 или старше.
:::
