Этот шаг необязательный: он о том, что происходит с JSX до того, как React нарисует страницу. Понимать это полезно — многие правила React перестанут выглядеть случайными.

## JSX — это вызовы функций

Браузер не понимает JSX. Перед запуском каждый файл `.tsx` проходит через компилятор TypeScript — в превью прямо в браузере, в проекте Vite при сборке. Компилятор заменяет каждый тег вызовом функции. Вот что получается из разметки `App` (без стилей, для краткости):

```tsx App.tsx
export function App() {
  return (
    <main className="page">
      <h1>Ход конём</h1>
      <p>Магазин настольных игр</p>
    </main>
  );
}
```

```js App.js
import { jsxDEV as _jsxDEV } from 'react/jsx-dev-runtime';
const _jsxFileName = 'App.tsx';
export function App() {
  return _jsxDEV('main', {
    className: 'page',
    children: [
      _jsxDEV('h1', { children: 'Ход конём' }, void 0, false,
        { fileName: _jsxFileName, lineNumber: 4, columnNumber: 7 }, this),
      _jsxDEV('p', { children: 'Магазин настольных игр' }, void 0, false,
        { fileName: _jsxFileName, lineNumber: 5, columnNumber: 7 }, this),
    ],
  }, void 0, true, { fileName: _jsxFileName, lineNumber: 3, columnNumber: 5 }, this);
}
```

Код переформатирован для чтения, а русские буквы в настоящем выводе записаны кодами (`\u0425\u043E…`) — компилятор так делает со всеми не-ASCII символами в строках.

Что здесь видно:

- **тег → вызов `jsxDEV(тип, props, …)`**. Тип — строка `'main'` для тегов HTML. Для компонента `<App />` тип — сама функция: `jsxDEV(App, {})`. Вот почему важна большая буква: со строчной компилятор написал бы `jsxDEV('app', {})` — строку, тег HTML;
- **атрибуты и вложенные элементы → один объект `props`**: `className` и `children` (содержимое тега) лежат рядом;
- **`fileName` и `lineNumber`** — их добавляет режим разработки (`jsxDEV`, а не `jsx`). По ним React показывает в предупреждениях, где в вашем коде создан элемент. В продакшен-сборке вызовы короче.

И ещё одно следствие: выражение `return (<h1/> <p/>)` — это попытка вернуть два вызова функции подряд, а так в JavaScript нельзя. Отсюда правило «один корневой элемент» из шага 1.2.

## React-элемент — обычный объект

Что возвращает `jsxDEV`? Не элемент страницы, а **React-элемент** — маленький объект-описание: «здесь должен быть `h1` с таким содержимым». Проверьте сами — добавьте в конец `App.tsx`:

```tsx App.tsx
const element = <h1 className="title">Ход конём</h1>;
console.log(element.type, element.props, element.key);
console.log(Object.keys(element), Object.isFrozen(element));
```

В консоли превью:

```
h1 { className: "title", children: "Ход конём" } null
["$$typeof", "type", "key", "props", "_owner", "_store"] true
```

- `type` — что рисовать: `'h1'` или функция-компонент;
- `props` — входные данные;
- `key` — ключ для списков, до него дойдём в главе 2;
- `$$typeof` — метка `Symbol(react.transitional.element)`: по ней React отличает свои элементы от любых других объектов, например пришедших из JSON с сервера;
- `_owner` и `_store` — служебные поля режима разработки;
- `Object.isFrozen` — `true`: элемент заморожен, изменить его нельзя. Чтобы показать другое, компонент возвращает новый элемент.

React-элементы дешёвые: создать тысячу объектов — быстро. Дорого менять страницу, поэтому React сначала получает от компонентов дерево элементов, сравнивает его с прошлым и только потом меняет в DOM то, что действительно изменилось. Это сравнение называется **сверкой** (reconciliation) — мы будем возвращаться к нему всю часть 1, а подробно разберём в главе 21. Уберите добавленные строки.

::: legacy Вы встретите в старом коде: React.createElement
До React 17 компилятор превращал JSX в вызовы `React.createElement`:

```js
// <h1 className="title">Ход конём</h1>
React.createElement('h1', { className: 'title' }, 'Ход конём');
```

Отличия от `jsxDEV` — только в том, как передаются аргументы. Вложенные элементы идут отдельными аргументами после props, и React сам собирает их в `props.children`. Ключ лежит в одном объекте с атрибутами, и React переносит его в `element.key`. Получается тот же React-элемент: те же поля, тот же `$$typeof`, тоже заморожен.

Поэтому в старых файлах первой строкой стоит `import React from 'react'`, хотя `React` в коде нигде не видно: к нему обращается скомпилированный код. Без импорта приложение падает с `ReferenceError: React is not defined`. С новым преобразованием JSX (React 17+, в TypeScript — `jsx: react-jsx`, так настроен шаблон Vite) этот импорт не нужен: компилятор сам импортирует `jsx` из `react/jsx-runtime`.

Сама функция `createElement` в React 19 есть и работает. Её вызывают вручную, когда элемент нужно создать без JSX:

```tsx
import { createElement } from 'react';

const title = createElement('h1', { className: 'title' }, 'Ход конём');
```
:::

## Итоги главы

- React — библиотека для интерфейсов; роутинг, данные, формы — экосистема, её мы изучаем вместе с React.
- Компонент — функция с большой буквы, которая возвращает JSX с одним корневым элементом.
- Приложение запускает `main.tsx`: `createRoot` на элементе `#root` и `root.render(<App />)`; рисует React не сразу, а по плану.
- `StrictMode` в разработке вызывает компоненты дважды, чтобы найти нечистые.
- Стили: глобальные — импортом в `main.tsx`, стили компонента — CSS Modules и `className={styles.x}`.
- Консоль: «Сборка» — код не запущен, ошибка со стеком — упал рендер, «TS» — ошибка типов.
- JSX — вызовы `jsxDEV()` (в продакшене — `jsx()`), которые создают React-элементы — замороженные объекты-описания.

В следующей главе разберём JSX подробно: выражения, атрибуты, условия и списки — и нарисуем каталог игр.
