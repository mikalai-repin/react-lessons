Строка «Игроков: 2–5 · 45 мин» тесная, а у «Нард» и вовсе «2–2». Сделаем из неё список характеристик «термин — значение»: для этого в HTML есть `<dl>` с парами `<dt>` и `<dd>`. И сразу наткнёмся на правило «один корневой элемент»: каждая пара — это **два** элемента, а функция в `map` может вернуть только один.

## Фрагмент — обёртка, которой нет в DOM

Обернуть пару в `<div>`? В нашей вёрстке это сломает раскладку — проверим в эксперименте. Нужна обёртка, которая собирает элементы в один для React, но не появляется на странице. Это **фрагмент**:

```tsx
import { Fragment } from 'react';

<dl className={styles.specs}>
  {specs.map((spec) => (
    <Fragment key={spec.label}>
      <dt>{spec.label}</dt>
      <dd>{spec.value}</dd>
    </Fragment>
  ))}
</dl>
```

`Fragment` возвращает свои дочерние элементы как есть: в DOM внутри `<dl>` окажутся `dt`, `dd`, `dt`, `dd`… без промежуточных обёрток. А раз это элемент списка, ему нужен `key` — ставится прямо на `Fragment`.

## Короткая запись <>…</>

Чаще фрагмент пишут короче — пустым тегом `<>…</>`. Пригодится нашему корню: у страницы появляется шапка, а в ней заголовок и подпись. `<header>` и `<main>` — два соседних элемента, и вместо лишнего `<div>` их можно объединить фрагментом:

```tsx
return (
  <>
    <header className={styles.header}>…</header>
    <main className={styles.page}>…</main>
  </>
);
```

У короткой записи одно ограничение: в ней **нельзя написать `key`** или другие атрибуты. В списке — только `<Fragment key={…}>`.

## Тело функции в map

Характеристики нужно подготовить для каждой игры: «2» или «2–5» в зависимости от того, совпадают ли `min` и `max`. Готовить данные в разметке неудобно, поэтому стрелочная функция в `map` получает **тело с фигурными скобками** и явный `return` — как у самого компонента:

```tsx App.tsx {1,10-18,20-32,39-46,49-53}
import { Fragment } from 'react';
import { games } from './data/games';
import { formatPrice } from './shared/format';
import styles from './App.module.css';

const MAX_RATING = 5;

export function App() {
  return (
    <>
      <header className={styles.header}>
        <h1 className={styles.title}>♞ Ход конём</h1>
        <p className="muted">
          Магазин настольных игр · в каталоге {games.length} игр
        </p>
      </header>

      <main className={styles.page}>
        <div className="grid">
          {games.map((game) => {
            const { min, max } = game.players;
            // Характеристики карточки: пары «термин — значение»
            const specs = [
              {
                label: 'Игроки',
                value: min === max ? `${min}` : `${min}–${max}`,
              },
              { label: 'Время', value: `${game.playTime} мин` },
              { label: 'Возраст', value: `${game.age}+` },
            ];

            return (
              <article
                key={game.id}
                className={styles.card}
                data-category={game.category}
              >
                {/* … обложка, название, цена без изменений … */}
                <dl className={styles.specs}>
                  {specs.map((spec) => (
                    <Fragment key={spec.label}>
                      <dt>{spec.label}</dt>
                      <dd>{spec.value}</dd>
                    </Fragment>
                  ))}
                </dl>
                {/* … рейтинг и кнопка без изменений … */}
              </article>
            );
          })}
        </div>
      </main>
    </>
  );
}
```

Строки съехали вправо — карточка вложена уже на шесть уровней. Это сигнал, что её пора выносить в отдельный компонент; этим откроем главу 3.

## Что получилось

В каждой карточке — аккуратная табличка из двух колонок: «Игроки 2–5», «Время 45 мин», «Возраст 8+». У «Нард» — «Игроки 2». На вид шапка не изменилась, но в разметке теперь `<header>` и `<main>` — это пригодится, когда в шапке появится корзина.

Убедитесь, что фрагменты не попадают в DOM, — добавьте в конец `App.tsx`:

```tsx
setTimeout(() => console.log([...document.getElementById('root')!.children].map((el) => el.tagName)), 100);
```

В консоли `["HEADER", "MAIN"]`: внутри `#root` два элемента, никакой обёртки. Уберите строку.

Эксперименты:

- **Замените `Fragment` на `<div key={spec.label}>`.** Табличка рассыпалась: «Игроки» и «Время» встали рядом, значения — под ними. Стили раскладывают по двум колонкам **дочерние элементы** `<dl>`, а теперь их три — по `<div>` на пару, — и каждый занял одну клетку. Лишняя обёртка ломает вёрстку, которая рассчитывает на прямых потомков: сетки, flex, таблицы (`<tr>` внутри `<div>` — ошибка разметки). Верните `Fragment`.
- **Напишите `<>…</>` вместо `<Fragment key>`** в списке. Работает, но в консоли знакомое ``Each child in a list should have a unique "key" prop.`` — у короткой записи ключа нет. Верните `Fragment`.
- **Уберите `<>` и `</>` вокруг шапки и `main`.** Ошибка сборки ``App.tsx:10 — JSX expressions must have one parent element.`` — та же, что в главе 1 без обёртки. Верните.

::: deep Что такое фрагмент для компилятора
`<>…</>` и `<Fragment>` компилируются одинаково: `jsxDEV(Fragment, { children: … })`. `Fragment` — специальный тип элемента, экспорт `react` (в выводе компилятора он импортируется из `react/jsx-dev-runtime`). При сверке React видит фрагмент как узел дерева, но DOM-элемента для него не создаёт: дочерние элементы фрагмента становятся детьми его родителя.
:::

::: tip
В Angular для того же служит `<ng-container>`, а во Vue — `<template>`: группирующий элемент, которого нет в итоговой разметке.
:::
