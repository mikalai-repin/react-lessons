В главе 1 магазин был просто вывеской: заголовок и подпись, всё написано прямо в разметке. Настоящий интерфейс показывает **данные**: названия, цены, остатки на складе. В этой главе мы нарисуем из данных каталог игр, а заодно разберём JSX целиком — выражения, атрибуты, условия, списки.

## Что появилось в шаге

В проекте новые готовые файлы — загляните в каждый:

- `api/models.ts` — тип `Game`: как выглядит одна игра (название, обложка, цена, старая цена, число игроков, остаток на складе и т. д.). Та же модель будет у учебного сервера в главе 11;
- `data/games.ts` — шесть игр массивом `games`. Пока данные лежат прямо в коде, загружать их с сервера мы научимся позже;
- `shared/format.ts` — функция `formatPrice`: `1990` → `1 990 ₽`;
- в `App.module.css` добавились стили карточки игры и всего, что мы нарисуем в этой главе. Классы будем подключать по мере надобности.

## Фигурные скобки — окно в JavaScript

В главе 1 вы уже писали `className={styles.title}`: фигурные скобки в JSX означают «здесь не текст, а значение из JavaScript». Внутри текста работают так же:

```tsx
<h2>{game.title}</h2>
```

React подставит значение `game.title` — «Остров сокровищ». В скобках может быть любое **выражение** JavaScript, то есть всё, что даёт значение: переменная, обращение к полю, арифметика, вызов функции, шаблонная строка, тернарный оператор.

```tsx
<p>{formatPrice(game.price)}</p>
<p>{game.players.max - game.players.min + 1} вариантов состава</p>
<p>{`${game.age}+`}</p>
```

А вот **инструкции** — `if`, `for`, `const`, `return` — внутри скобок писать нельзя: они ничего не возвращают. Вспомните шаг «Под капотом: JSX» из главы 1: JSX — это вызов `jsxDEV('h2', { children: game.title })`, а то, что в скобках, становится аргументом функции. В аргумент можно передать выражение, но не `if`.

Поэтому всё, что нужно подготовить, готовят **до `return`**, в теле компонента — это обычная функция, и там можно всё:

```tsx App.tsx {1-2,6,12,15-24}
import { games } from './data/games';
import { formatPrice } from './shared/format';
import styles from './App.module.css';

export function App() {
  const game = games[0];

  return (
    <main className={styles.page}>
      <h1 className={styles.title}>♞ Ход конём</h1>
      <p className="muted">
        Магазин настольных игр · в каталоге {games.length} игр
      </p>

      <article className={styles.card}>
        <h2 className={styles.cardTitle}>{game.title}</h2>
        <p className={styles.price}>
          {formatPrice(game.price)}
        </p>
        <p className="muted">
          Игроков: {game.players.min}–{game.players.max} ·{' '}
          {game.playTime} мин
        </p>
      </article>
    </main>
  );
}
```

Обратите внимание на `{' '}` в конце строки. JSX обращается с пробелами не так, как HTML: переносы строк вместе с отступами вокруг них он **выбрасывает**. Пробел в середине строки («`Игроков: {…}`») сохраняется, а вот пробел перед переносом пропадёт, и получится «·45 мин». Строка `{' '}` — явный пробел, который не выбросить. Добавлять её руками не придётся: так строку разбивает кнопка «Формат» и Prettier в настоящем проекте.

2. Перед `return` возьмите первую игру: `const game = games[0];`.
3. Допишите в подпись число игр: «Магазин настольных игр · в каталоге {games.length} игр».
4. После подписи добавьте карточку `<article className={styles.card}>`: заголовок `<h2>` с названием игры (класс `styles.cardTitle`), абзац с ценой через `formatPrice` (класс `styles.price`) и абзац с классом `muted`: «Игроков: 2–5 · 45 мин».

## Что получилось

Под подписью — карточка «Остров сокровищ» с ценой «1 990 ₽» и строкой «Игроков: 2–5 · 45 мин». Поменяйте `games[0]` на `games[1]` — карточка покажет «Драконью почту»: разметка та же, данные другие. Верните `games[0]`.

## Что React рисует, а что — нет

Значение в скобках не обязано быть строкой. Проверьте сами: добавьте в карточку строку

```tsx
<p>[{0}][{null}][{undefined}][{false}][{true}][{''}][{NaN}][{[1, 2, 3]}]</p>
```

На экране:

```
[0][][][][][][NaN][123]
```

| Значение | Что на экране |
|---|---|
| строка, число | как есть — и `0`, и `NaN` тоже |
| `null`, `undefined`, `true`, `false` | ничего |
| массив | все элементы подряд |

Правило «`null`, `undefined` и `false` ничего не рисуют» — основа условного рендера, до него дойдём через шаг. А то, что `0` рисуется, — источник самой известной ловушки JSX, её разберём там же. Массивы — основа списков. Уберите строку.

## Объект в скобках — ошибка

Попробуйте вывести не поле, а целый объект: в заголовке замените `{game.title}` на `{game.players}`.

Редактор сразу подчеркнёт выражение, а в консоли появится строка с меткой «TS»: `Type '{ min: number; max: number; }' is not assignable to type 'ReactNode'.` `ReactNode` — тип всего, что React умеет нарисовать: строки, числа, `null`, `undefined`, логические значения, React-элементы и массивы из них. Обычного объекта среди них нет.

Ошибки типов запуск не останавливают, поэтому React всё-таки попробует нарисовать объект — и упадёт:

```
Objects are not valid as a React child (found: object with keys {min, max}). If you meant to render a collection of children, use an array instead.
```

«Объекты нельзя использовать как дочерние элементы». Превью опустеет: ошибка при рендере роняет всё приложение (как в шаге про отладку). React не знает, как показать объект, — превратите его в строку сами: `{game.players.min}–{game.players.max}`. Верните `{game.title}`.

И последний эксперимент — инструкция вместо выражения. Замените `{formatPrice(game.price)}` на `{if (game.price > 0) formatPrice(game.price)}`. Код перестанет собираться: в консоли три ошибки с меткой «Сборка», первая — `App.tsx:18 — Expression expected.` («ожидалось выражение»). Верните как было.

::: tip
В Angular для того же служит интерполяция `{{ game.title }}`, а форматирование — пайпы (`{{ game.price | currency }}`). В JSX пайпов нет: форматирование — обычный вызов функции, как `formatPrice`. Зато и учить отдельный язык шаблонов не нужно — в скобках работает весь JavaScript, который вы знаете.
:::

::: tip Как в настоящем проекте
Функции форматирования (`formatPrice`, даты, склонения) обычно лежат в общей папке вроде `shared/` или `lib/` и не зависят от React — их легко проверить отдельно тестами. `Intl.NumberFormat` создаём один раз на модуль, а не при каждом вызове: создание форматтера заметно дороже, чем форматирование.
:::
