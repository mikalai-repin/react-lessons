Три мелочи, по которым отличают приложение «на роутере» от приложения, сделанного с заботой: форма не теряется от случайного щелчка, прокрутка ведёт себя как на обычном сайте, а переход между страницами не «щёлкает».

## Несохранённая форма

Покупатель заполнил имя и адрес, по привычке щёлкнул логотип — и всё пропало. Спросим его прежде, чем уйти. [`useBlocker`](https://reactrouter.com/api/hooks/useBlocker) задерживает переход внутри приложения, пока вы не решите, пускать ли:

```tsx checkout/CheckoutPage.tsx
  // Покупатель начал заполнять форму
  const [dirty, setDirty] = useState(false);
  // Уход на другую страницу с заполненной формой — спросить.
  // Отправка (тот же адрес /checkout) не блокируется
  const blocker = useBlocker(
    ({ currentLocation, nextLocation }) =>
      dirty &&
      currentLocation.pathname !== nextLocation.pathname,
  );
```

Функция получает, откуда и куда идёт переход, и возвращает `true` — «задержать». Отправка формы — тоже переход, на тот же `/checkout`; его пропускаем, сравнивая пути. А `dirty` ставит событие `onChange` всей формы: оно всплывает от любого поля.

```tsx checkout/CheckoutPage.tsx
      {blocker.state === 'blocked' && (
        <div className={styles.leave} role="alertdialog">
          <p>Уйти? Введённые данные пропадут.</p>
          <Button onClick={() => blocker.proceed()}>
            Уйти
          </Button>
          <Button onClick={() => blocker.reset()}>
            Остаться
          </Button>
        </div>
      )}
      <Form
        method="post"
        className={styles.form}
        onChange={() => setDirty(true)}
      >
```

Пока переход задержан, `blocker.state === 'blocked'`: показываем вопрос. `proceed()` — продолжить переход, `reset()` — отменить. Стиль плашки — в готовом `CheckoutPage.module.css`.

## Прокрутка

Прокрутите главную вниз и щёлкните игру в последнем ряду «Хитов». Страница игры откроется… прокрученной: браузер не знает, что «страница» сменилась, — документ тот же, сменилось содержимое. На обычном сайте новая страница всегда начинается сверху, а «назад» возвращает туда, где вы были.

Это делает компонент [`ScrollRestoration`](https://reactrouter.com/api/components/ScrollRestoration) — один на приложение, в макете:

```tsx layout/Layout.tsx
      <CartToast />
      {/* Прокрутка: новая страница — сверху, «назад» — где была */}
      <ScrollRestoration />
```

Он запоминает прокрутку для каждой записи истории и восстанавливает её после перехода, когда новая страница уже нарисована.

## Анимация перехода

Браузеры умеют плавно сменять «снимки» страницы — [View Transitions API](https://developer.mozilla.org/ru/docs/Web/API/View_Transition_API). Роутеру достаточно сказать, какие переходы анимировать:

```tsx shared/GameCard.tsx
        <Link
          to={`/games/${game.id}`}
          className={styles.titleLink}
          // Переход с анимацией браузера (View Transitions API)
          viewTransition
        >
```

С `viewTransition` роутер оборачивает обновление в `document.startViewTransition`: браузер делает снимок старой страницы, React рисует новую, и браузер плавно переходит от одного к другому. По умолчанию — растворение, а свою анимацию задают в CSS (`::view-transition-old`, `::view-transition-new`). Браузеры без поддержки просто переходят без анимации.

2. В `Layout` — `<ScrollRestoration />` после уведомления корзины.
3. В `GameCard` — `viewTransition` у ссылки на страницу игры.

## Что получилось

Положите игру в корзину, перейдите к оформлению, начните вводить имя и щёлкните логотип. Над формой — «Уйти? Введённые данные пропадут.», адрес по-прежнему `/checkout`. «Остаться» — плашка исчезла, имя на месте. Нажмите «назад» в превью — снова вопрос: блокируются и кнопки истории. «Уйти» — переход состоялся. А отправка заказа проходит без вопросов.

Прокрутите главную до конца и откройте последнюю игру «Хитов» — страница игры начинается сверху. «Назад» — главная прокручена, как была. Переход по названию игры плавно растворяется (в настоящем Chrome это заметно лучше, чем в маленьком превью).

## Эксперименты

1. **Без `ScrollRestoration`.** Уберите компонент и повторите: страница игры открывается прокрученной вниз. «Назад» в превью браузер восстановил сам, но в настоящем приложении, где данные новой страницы приходят после перехода, он часто восстанавливает прокрутку раньше, чем страница готова, — и промахивается. Верните компонент.
2. **Блокировка без условия на путь.** Замените функцию на `() => dirty`. Заполните форму и нажмите «Заказать»: вместо отправки — «Уйти?». Отправка `Form` — такой же переход, и блокировщик его задержал. Верните сравнение путей.

## Как в настоящем проекте

- `useBlocker` задерживает только переходы **внутри** приложения. Закрытие вкладки, ⟳ и ввод адреса в настоящей адресной строке он не видит. Для них — событие браузера `beforeunload` (у роутера есть хук `useBeforeUnload`): браузер покажет свой стандартный вопрос, текст задать нельзя.
- Не блокируйте без нужды: вопрос на каждой странице раздражает. Блокировка — для форм, где потерять ввод действительно жалко.
- `ScrollRestoration` умеет запоминать прокрутку не по записи истории, а по адресу (`getKey`), — тогда «Каталог» всегда открывается там, где его оставили, как бы на него ни пришли.
