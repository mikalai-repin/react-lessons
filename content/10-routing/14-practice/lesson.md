У магазина появилась глубина: «Кабинет → Настройки», страницы игр, оформление. Покупателю нужно видеть, где он, и одним щелчком подниматься выше. Сделайте **хлебные крошки** над страницей:

```
/catalog            Главная › Каталог
/games/4            Главная › Ночной экспресс
/account/settings   Главная › Кабинет › Настройки
```

Цепочка крошек — это цепочка совпавших маршрутов (шаг «Под капотом»). Знает её роутер: хук [`useMatches`](https://reactrouter.com/api/hooks/useMatches) возвращает совпадения от корня до листа. А подпись каждой крошки маршрут сообщает сам — в поле **`handle`**: туда можно положить что угодно, роутер передаст это в `useMatches` как есть.

Что уже в проекте:

- `layout/Breadcrumbs.tsx` — заготовка;
- `layout/Breadcrumbs.module.css` — стили: `.crumbs` для `<nav>`, разделитель «›» между пунктами `<li>`, приглушённый цвет у текущей страницы (`aria-current="page"`).

::: task
1. Дайте маршрутам `handle: { crumb: (data) => подпись }`: корню — «Главная», каталогу — «Каталог», игре — название игры из данных `loader`, корзине — «Корзина», оформлению — «Оформление заказа», кабинету — «Кабинет», настройкам — «Настройки».
2. В `layout/Breadcrumbs.tsx` напишите `Breadcrumbs`: совпадения из `useMatches()`, у которых в `handle` есть `crumb`, — пункты `<ol>` внутри `<nav className={styles.crumbs} aria-label="Хлебные крошки">`. Все, кроме последнего, — `Link` на `match.pathname`; последний — `<span aria-current="page">`. Если крошек меньше двух — ничего не рисовать.
3. Нарисуйте `<Breadcrumbs />` в `Layout` над `<Outlet />`.
:::

::: hint Подсказка 1: что лежит в совпадении
Каждый элемент `useMatches()` — объект `UIMatch`: `id` маршрута (годится в `key`), `pathname` — часть адреса до этого маршрута (`/account` для кабинета на `/account/settings`), `params`, `loaderData` — результат загрузчика и `handle`. Тип у `handle` — `unknown`: роутер не знает, что вы туда положили.
:::

::: hint Подсказка 2: тип handle
Опишите форму и проверьте её функцией-предикатом:

```tsx
/** Что маршрут кладёт в handle: подпись крошки из данных loader */
export type CrumbHandle = {
  crumb: (data: unknown) => string;
};

// handle у маршрута может быть каким угодно — проверяем форму
function hasCrumb(handle: unknown): handle is CrumbHandle {
  return (
    typeof handle === 'object' &&
    handle !== null &&
    'crumb' in handle
  );
}
```

Тогда `useMatches().flatMap((match) => hasCrumb(match.handle) ? [ … ] : [])` оставит только маршруты с крошками — безпутевая обёртка с границей ошибок и индексная вкладка «Избранное» в цепочку не попадут.
:::

::: hint Подсказка 3: название игры
`crumb` получает `match.loaderData` — у маршрута игры это объект `Game` из `gameLoader`: `crumb: (game: Game) => game.title`. Но откройте `/games/999`…
:::

::: hint Подсказка 4: а если загрузчик упал
На `/games/999` загрузчик бросил 404, страницу рисует граница ошибок, а маршрут игры **всё равно** в цепочке совпадений — только `loaderData` у него `undefined`. Крошка должна это пережить: `(game: Game | undefined) => game?.title ?? 'Игра не найдена'`. Иначе ошибка в `Breadcrumbs`, а он в макете — и корневая граница заменит весь магазин.
:::

## Проверьте себя

Нажмите **«✓ Проверить»** под редактором: платформа перезапустит магазин, пройдёт по нему сама и, если что-то не так, подскажет, куда смотреть. Пункты ниже — та же проверка руками, с объяснениями и экспериментами, которых кнопка не делает.

- Главная — крошек нет. `/catalog` — «Главная › Каталог», «Главная» — ссылка, «Каталог» — нет.
- Откройте «Ночной экспресс» — «Главная › Ночной экспресс»: подпись пришла из данных загрузчика.
- `/account/settings` — «Главная › Кабинет › Настройки»; щелчок по «Кабинет» — `/account`, крошки «Главная › Кабинет». Вкладке «Избранное» мы `crumb` не дали — и правильно: «Кабинет › Избранное» ничего бы не добавило.
- `/games/999` — «Главная › Игра не найдена» и «Такой страницы нет», шапка и подвал на месте. Уберите защиту от `undefined` в крошке игры — весь магазин сменится на «Что-то пошло не так»: ошибка в макете ловится уже корневой границей. Верните.
- Консоль пуста, ошибок типов нет.

## Итоги главы

У магазина появились адреса: главная, каталог с фильтрами в query-строке, страницы игр, корзина, оформление, кабинет с вкладками, 404.

| Запись | Что делает |
|---|---|
| `createBrowserRouter([…])` + `<RouterProvider router>` | роутер режима данных: маршруты-объекты вне React |
| `children`, `index`, `<Outlet />`, маршрут без `path` | вложенность: макеты, индексные страницы, общие границы |
| `Link`, `NavLink` (`aria-current`, `end`), `useNavigate` | переходы без перезагрузки, активная ссылка, переход из кода |
| `:id` + `useParams`, `useSearchParams` + `replace` | параметры пути и состояние в query-строке |
| `loader` + `useLoaderData`, `HydrateFallback`, `useNavigation` | данные до показа страницы и состояние перехода |
| `action` + `<Form>` + `useActionData`, `redirect` | изменение данных и переход после него |
| `useFetcher`, ресурсный маршрут | действие без перехода |
| `ErrorBoundary`, `useRouteError`, `isRouteErrorResponse`, `throw data(…)` | ошибки и 404 на уровне маршрута |
| `lazy` | код маршрута — при первом переходе |
| `redirect` в `loader`, `useBlocker`, `ScrollRestoration`, `viewTransition` | защита маршрута и мелочи удобства |
| `handle` + `useMatches` | данные маршрутов для макета: крошки |

И главные идеи:

- адрес — часть состояния: то, чем делятся и что должно пережить ⟳, живёт в пути и query-строке, а компонент **вычисляет** его из адреса; адрес набирает пользователь — каждое значение проверяется;
- в режиме данных роутер ведёт переход сам: сопоставляет адрес (по очкам, а не по порядку), параллельно грузит код и данные всей цепочки, отменяет устаревшие переходы и только потом меняет адрес и рисует страницу;
- `loader` читает, `action` меняет, после `action` загрузчики страницы перезагружаются; `Form` — переход, фетчер — действие на месте;
- ошибки — не забота каждой страницы: загрузчик бросает `data(…, { status })`, граница маршрута показывает. Граница внутри макета сохраняет шапку;
- защита маршрута — в `loader`, до рендера; защита в интерфейсе — удобство, а безопасность — на сервере.

Каталог по-прежнему — массив в коде, а `loader` игры не помнит прошлых ответов: каждое открытие — новый запрос. В главе 11 данные переедут на сервер целиком: сначала мы честно напишем загрузку в `useEffect` и найдём в ней гонки, затем подключим **TanStack Query** — серверный кэш, который хранит, обновляет и делит данные между страницами.
