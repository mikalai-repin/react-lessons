Страницы есть, а попасть на них можно только через адресную строку. Нужны ссылки: логотип ведёт на главную, «Корзина: 2» в шапке — в корзину, а со страницы «нет такого адреса» и из пустой корзины — обратно в каталог.

## Почему не `<a href>`

Обычная ссылка `<a href="/cart">` работает и с роутером — но браузер по ней **загружает страницу заново**: новый запрос `index.html`, новый запуск всего JavaScript, состояние в памяти пропадает. Это то, что одностраничное приложение (SPA) призвано не делать.

[`Link`](https://reactrouter.com/api/components/Link) из `react-router` рисует тот же `<a href>` — с адресом, который видно при наведении, который можно открыть в новой вкладке и прочитать программой чтения с экрана. Но обычный щелчок Link перехватывает: отменяет загрузку страницы, меняет адрес через History API (`history.pushState`) и сообщает роутеру. Роутер сопоставляет новый адрес с маршрутами и рисует другую страницу — без перезапуска.

```tsx layout/Header.tsx
      <h1 className={styles.title}>
        <Link to="/">♞ Ход конём</Link>
      </h1>
```

`to` — куда вести. Щелчок с Ctrl или ⌘, средней кнопкой — Link не трогает, и браузер открывает новую вкладку, как с любой ссылкой.

## NavLink

Сводке корзины в шапке хорошо бы выделяться, когда корзина открыта. Для навигации есть [`NavLink`](https://reactrouter.com/api/components/NavLink) — Link, который знает, открыт ли его адрес:

```tsx layout/Header.tsx
      {/* NavLink — ссылка, которая знает, открыт ли её адрес */}
      <NavLink to="/cart" className={styles.cart}>
        Корзина: {cartCount}
      </NavLink>
```

На `/cart` активный NavLink получает атрибут `aria-current="page"` — программа чтения с экрана скажет «текущая страница». Он же — удобная зацепка для стиля:

```css layout/Header.module.css
/* Ссылка на корзину, когда открыта корзина: NavLink ставит aria-current */
.cart[aria-current='page'] {
  background: var(--brand);
  color: var(--bg);
}
```

NavLink добавляет и класс `active`, но с CSS Modules он неудобен: наши классы превращаются в `Header_cart_…`, а `active` остаётся глобальным. Есть и третий способ — функция вместо строки: `className={({ isActive }) => (isActive ? styles.active : styles.cart)}`; так же работают `style` и `children`.

Ещё две ссылки — в тексте страниц:

```tsx layout/NotFoundPage.tsx
      <p className="muted">
        Проверьте адрес — или начните{' '}
        <Link to="/">с главной</Link>.
      </p>
```

```tsx cart/MiniCart.tsx
        <p className={`muted ${styles.empty}`}>
          Корзина пуста —{' '}
          <Link to="/">добавьте игру из каталога</Link>
        </p>
```

Стили ссылок уже готовы: в `Header.module.css` — для логотипа и активной корзины, в `styles.css` — цвет всех ссылок магазина.

::: task
1. В `Header` логотип — `Link` на `/` внутри `<h1>`, сводка корзины — `NavLink` на `/cart` с классом `styles.cart` вместо `<p>`.
2. На странице `NotFoundPage` — ссылка «с главной», в пустой мини-корзине — «добавьте игру из каталога», обе на `/`.
:::

## Что получилось

На главной сводка корзины — серая плашка, как раньше. Щёлкните по ней: адрес `/cart`, плашка стала цвета магазина. Щёлкните «добавьте игру из каталога» — снова главная, плашка серая. Логотип с любой страницы ведёт на главную.

## Эксперименты

1. **Без перезапуска.** Наберите что-нибудь в поле e-mail подписки и щёлкните «Корзина» в шапке. Текст в поле на месте — переход внутри приложения.
2. **`<a href>` вместо `NavLink`.** Замените ссылку корзины на `<a href="/cart" className={styles.cart}>`. Наберите e-mail и щёлкните: адрес тот же, а поле пустое. В настоящем браузере это загрузка страницы заново; превью курса ведёт себя так же — перезапускает приложение с адреса ссылки (как ⟳). Верните `NavLink`.
3. **`NavLink` у логотипа.** Сделайте логотип `NavLink` на `/` и откройте `/cart`. У логотипа нет `aria-current`: корневой адрес роутер сравнивает целиком — `/` активен только на `/`. Для остальных NavLink активен и на вложенных адресах (`/account` — на `/account/settings`); отключает это проп `end`. Вспомним о нём в шаге «Вложенные маршруты».

## Как в настоящем проекте

- Внутри приложения — только `Link`/`NavLink`; `<a href>` — для внешних сайтов (`https://…`), файлов для скачивания и случаев, когда перезагрузка нужна намеренно.
- Кнопка, которая что-то **делает**, — `<button>`; ссылка, которая **ведёт** куда-то, — `Link`. «Кнопка» с переходом в обработчике (`navigate`, следующий шаг) не откроется в новой вкладке и для программы чтения с экрана не ссылка.
- Меню сайта — `NavLink` внутри `<nav>`; активный пункт выделяют по `aria-current`, а не по своему классу: так стиль и доступность не разойдутся.
