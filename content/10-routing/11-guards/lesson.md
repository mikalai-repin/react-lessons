В шаге «Изменение данных» мы нашли дыру: после заказа «назад» открывает оформление с «0 шт. на 0 ₽», и форму можно отправить. Так же туда попадёт любой, кто наберёт `/checkout` руками. Оформлять пустую корзину не должно быть можно: такой покупатель должен оказаться в корзине.

«Пускать на страницу только при условии» — **защита маршрута** (в Angular — guard). В главе 14 так же закроем кабинет: только после входа.

## redirect из loader

`loader` выполняется **до** показа страницы — значит, в нём и решать, показывать ли её. Ответ `redirect` из загрузчика отменяет переход и ведёт по другому адресу:

```tsx routes.tsx
          {
            path: 'checkout',
            // Защита: с пустой корзиной оформлять нечего — в корзину.
            // Обычный loader, не ленивый: проверка не ждёт кода страницы
            loader: () => {
              if (useCartStore.getState().items.length === 0) {
                return redirect('/cart');
              }
              return null;
            },
            lazy: async () => { … },
          },
```

- Корзину читаем через `getState()` — загрузчик вне React, как `action` в шаге «Изменение данных».
- Загрузчик лежит прямо в маршруте, а не в ленивом модуле: так проверка начинается сразу, не дожидаясь кода страницы.
- `return null` — данных странице не нужно, загрузчик только сторожит.

Страница при этом ни разу не рендерится: роутер ещё не дошёл до компонента, когда получил `redirect`.

::: task
Добавьте маршруту `checkout` загрузчик: пустая корзина (`useCartStore.getState().items.length === 0`) — `redirect('/cart')`, иначе `null`.
:::

## Что получилось

С пустой корзиной введите в адресную строку `/checkout` — адрес сразу `/cart`, «Корзина пуста». Оформите заказ и на странице «Заказ оформлен» нажмите «назад»: снова корзина, а не форма.

## Эксперименты

1. **Гард компонентом.** Так защищали маршруты до режима данных. Уберите `loader`, а в `CheckoutPage` после `useNavigation` добавьте:

   ```tsx
   console.log('render CheckoutPage', count);
   if (count === 0) return <Navigate to="/cart" replace />;
   ```

   (и `Navigate` в импорт из `react-router`). С пустой корзиной откройте `/checkout` — тоже `/cart`, но в консоли `render CheckoutPage 0` дважды: страница успела отрендериться (со всеми хуками), и только потом `Navigate` в эффекте сменил адрес. Для корзины это мелочь. А для страницы с данными «гард» в компоненте — это загрузчик, который уже начал запрос, и мелькание запретной страницы. Защита в `loader` срабатывает до всего этого. Верните `loader`.
2. **Код всё равно грузится.** Верните лог `console.log('модуль оформления выполнен')` в `CheckoutPage.tsx` из прошлого шага и откройте `/checkout` с пустой корзиной: строка есть, хотя страницы вы не увидели. Роутер запускает `lazy` **параллельно** с загрузчиком, чтобы не терять время, — и не знает заранее, что загрузчик перенаправит. Защита решает, что **показать**, а не что скачать.

## Как в настоящем проекте

- Защита в интерфейсе — удобство, а не безопасность. Скрытая страница не мешает отправить запрос на сервер напрямую: сервер обязан проверять всё сам (`400 Пустой заказ` — как у нашего бэкенда). Подробно — глава 14.
- Одну проверку для целого раздела ставят на родительский маршрут: загрузчики вложенных маршрутов выполняются параллельно, но `redirect` любого из них отменяет весь переход. В главе 14 у кабинета будет общий загрузчик «войдите» и возврат обратно — `redirect('/login?returnUrl=/account')`.
- В React Router 8 есть и **middleware** маршрутов — функции, которые выполняются перед загрузчиками всей цепочки, по порядку, сверху вниз. Это место для проверок «один раз на раздел» и общих данных; в режиме данных с ним работают через `context` загрузчиков.
