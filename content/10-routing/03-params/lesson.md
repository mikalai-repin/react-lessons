Страница игры по-прежнему открывается состоянием `selectedId` в `HomePage`. Сделаем её настоящей страницей: у каждой игры — свой адрес `/games/1`, `/games/4`. Двенадцать маршрутов на двенадцать игр писать не будем: нужен один маршрут с **параметром**.

## Параметр в пути

```tsx routes.tsx
      // :id — параметр: часть адреса, которая меняется
      { path: 'games/:id', Component: GamePage },
```

`:id` подходит к любому одному сегменту адреса: `/games/4`, `/games/abc`, но не `/games` и не `/games/4/reviews`. Значение сегмента компонент получает хуком [`useParams`](https://reactrouter.com/api/hooks/useParams):

```tsx game/GamePage.tsx
// Страница игры: id — из адреса /games/:id
export function GamePage() {
  // Параметры адреса — всегда строки (или undefined)
  const { id } = useParams();
  const index = games.findIndex(
    (game) => String(game.id) === id,
  );

  if (index === -1) {
    return (
      <Section title="Игра не найдена">
        <p className="muted">
          В каталоге нет такой игры.{' '}
          <Link to="/">На главную</Link>
        </p>
      </Section>
    );
  }
  const game = games[index];
  // Следующая игра каталога; после последней — снова первая
  const next = games[(index + 1) % games.length];
  // key: другая игра — новый GameDetails со своим состоянием (глава 5)
  return (
    <GameDetails key={game.id} game={game} nextId={next.id} />
  );
}
```

Адрес — строка, которую мог набрать кто угодно, поэтому:

- `id` — **строка**, а не число: `'4'`, а не `4`. Сравниваем со `String(game.id)`;
- `id` может не найтись (`/games/999`) или быть мусором (`/games/abc`) — страница должна это пережить. Пока покажем «Игра не найдена»; настоящий ответ 404 — в шаге «Ошибки и 404».

## Ссылки на игру

Название в карточке становится ссылкой — вместо кнопки с `onSelect`:

```tsx shared/GameCard.tsx
        <Link
          to={`/games/${game.id}`}
          className={styles.titleLink}
        >
          {game.title}
        </Link>
```

У `GameCard` и `GameGrid` пропадает проп `onSelect`, а у `HomePage` — `selectedId`, `selectedGame`, `handleNext` и ветка с `GameDetails`: главная больше не знает о странице игры. Состояние «какая игра открыта» переехало в адрес.

## useNavigate

На странице игры две кнопки навигации. «Следующая игра →» — обычная ссылка на `/games/${nextId}`. А «← Назад» должна вести **туда, откуда пришли**: с главной — на главную, со следующей игры — на прошлую. Это шаг по истории браузера, а не ссылка на конкретный адрес. Переходы из кода делает [`useNavigate`](https://reactrouter.com/api/hooks/useNavigate):

```tsx game/GameDetails.tsx
  const navigate = useNavigate();
  const location = useLocation();

  // Назад по истории; если страницу открыли прямой ссылкой —
  // истории внутри магазина нет, ведём на главную
  function handleBack() {
    if (location.key === 'default') navigate('/');
    else navigate(-1);
  }
```

- `navigate('/catalog')` — переход по адресу, как Link; `navigate(-1)` — как кнопка «Назад» браузера.
- `location.key` — метка записи истории. У первой страницы, с которой открыли приложение, она `'default'`. Если покупатель пришёл по ссылке из мессенджера прямо на `/games/4`, `navigate(-1)` увёл бы его с сайта — поэтому в этом случае ведём на главную.

`useNavigate` — для переходов **после действия**: кнопка «Назад», закрытие окна по Esc, переход после сохранения. Если можно написать ссылкой — пишите ссылкой (шаг «Ссылки»).

## Что получилось

Щёлкните по названию «Острова сокровищ» — адрес `/games/1`, страница игры. «Следующая игра →» — `/games/2`. «← Назад» — снова `/games/1`, ещё раз — главная. Работают и кнопки «назад» и «вперёд» самого превью: история общая. Введите в адресной строке `/games/4` — сразу «Ночной экспресс»; «← Назад» с такой страницы ведёт на главную. `/games/999` и `/games/abc` — «Игра не найдена».

## Эксперименты

1. **Без `key`.** Уберите `key={game.id}` из `GamePage`. Откройте `/games/1`, отправьте отзыв — «Спасибо! Отзыв появится после проверки». Нажмите «Следующая игра →»: адрес `/games/2`, а «Спасибо!» осталось. Маршрут тот же, `GamePage` и `GameDetails` на тех же местах дерева — React сохранил их состояние, сменились только props. Ровно то, что мы видели в шаге «Сохранение и сброс состояния» главы 5. С `key` у каждой игры свой `GameDetails`. Верните `key`.
2. **Строка, а не число.** Замените сравнение на `game.id === id`:

   ```
   This comparison appears to be unintentional because the types 'number' and 'string | undefined' have no overlap.
   ```

   TypeScript помнит, что параметры адреса — строки. Без него сравнение молча давало бы `false`, и любая игра была бы «не найдена».

## Как в настоящем проекте

- Параметры часто бывают не числами, а «человеческими» строками — `slug`: `/games/treasure-island` читается лучше и не раскрывает, сколько у вас записей. У наших игр `slug` есть, учебный бэкенд ищет и по нему.
- Необязательный параметр — `:lang?` (`/:lang?/catalog`), «всё остальное» — `*` в конце пути (`/docs/*`, значение — `params['*']`).
- Проверять параметр — обязанность страницы (или `loader`, шаг «Загрузка данных»): адрес — пользовательский ввод.

::: tip Для тех, кто знает Angular
`useParams()` — аналог `ActivatedRoute.paramMap`, только без подписки: при смене параметра компонент просто рендерится заново. И, как в Angular, при переходе между `/games/1` и `/games/2` компонент **не пересоздаётся** — отсюда `key`.
:::
