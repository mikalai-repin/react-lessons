Игры у нас — массив в коде. В настоящем магазине страница игры берёт данные с сервера: остаток на складе меняется каждую минуту. Учебный бэкенд внутри превью отвечает на `GET /api/games/4` (как в шаге 1.1). Загрузим игру с него.

Первая мысль — `useEffect` с `fetch` в `GamePage`. Так долго и писали, и в главе 11 мы подробно разберём, чем это плохо: страница сначала рисуется пустой, запрос стартует только после отрисовки, гонки между запросами, отмена — вручную. У роутера в режиме данных есть способ лучше: **загрузить данные до показа страницы**.

## loader

У маршрута может быть функция `loader`. Роутер вызывает её, когда адрес совпал с маршрутом, — **ещё до рендера** страницы, — и ждёт результат:

```tsx game/GamePage.tsx
// Загрузка игры: роутер вызывает loader ДО показа страницы.
// signal отменит запрос, если покупатель уйдёт раньше ответа
export async function gameLoader({
  params,
  request,
}: LoaderFunctionArgs) {
  const response = await fetch(`/api/games/${params.id}`, {
    signal: request.signal,
  });
  if (!response.ok) return null;
  return (await response.json()) as Game;
}
```

- `params` — те же параметры, что у `useParams`: `params.id`.
- `request` — объект [`Request`](https://developer.mozilla.org/ru/docs/Web/API/Request) перехода: адрес, а для форм — данные (следующий шаг). Его `signal` роутер отменит, если переход прервётся, — передаём его в `fetch`.
- `loader` — обычная функция вне React: никаких хуков в ней нельзя, зато можно `await`.
- Игры нет (`404`) — пока вернём `null`. Как ответить настоящей ошибкой — шаг «Ошибки и 404».

Маршрут получает `loader`:

```tsx routes.tsx
      {
        path: 'games/:id',
        // Данные страницы: роутер загрузит их до показа
        loader: gameLoader,
        Component: GamePage,
      },
```

## useLoaderData

Компонент забирает результат хуком [`useLoaderData`](https://reactrouter.com/api/hooks/useLoaderData):

```tsx game/GamePage.tsx
// Страница игры: данные уже загружены — компонент их только рисует
export function GamePage() {
  const game = useLoaderData<typeof gameLoader>();

  if (game === null) {
    return ( … «Игра не найдена» … );
  }
  // Следующая игра каталога; после последней — снова первая
  const index = games.findIndex((item) => item.id === game.id);
  const next = games[(index + 1) % games.length];
  …
```

`useLoaderData<typeof gameLoader>()` выводит тип из функции: `Game | null`. Это **не проверка**: TypeScript верит `as Game` в загрузчике, а что пришло с сервера, он не знает (проверка схемой — глава 13). В компоненте нет ни `useState`, ни `useEffect`, ни флага «загружается» — к первому рендеру данные уже есть.

## Пока грузится

Если данные приходят до показа, что видит покупатель, пока они идут? Есть два случая.

**Переход внутри приложения.** Покупатель на главной щёлкнул «Остров сокровищ». Роутер вызвал `loader` и… оставил на экране **старую** страницу — и старый адрес — до ответа. Чтобы было видно, что щелчок услышан, макет читает состояние перехода [`useNavigation`](https://reactrouter.com/api/hooks/useNavigation):

```tsx layout/Layout.tsx
  // Состояние перехода: idle — ничего не происходит,
  // loading — грузятся данные следующей страницы
  const navigation = useNavigation();
  …
      <main
        className={styles.page}
        aria-busy={navigation.state === 'loading'}
      >
```

`aria-busy` скажет программе чтения с экрана «содержимое обновляется», а готовый стиль в `Layout.module.css` приглушит страницу.

**Первый заход.** Покупатель открыл `/games/4` по ссылке из мессенджера. Старой страницы нет — показывать нечего. Для этого у маршрута есть `HydrateFallback`:

```tsx routes.tsx
    path: '/',
    Component: Layout,
    // Первый заход сразу на страницу с loader: что показать, пока он идёт
    HydrateFallback: () => <p className="muted">Загружаем…</p>,
```

Он рисуется **вместо всего дерева** маршрутов, пока не выполнятся загрузчики первого адреса.

::: task
1. В `game/GamePage.tsx` напишите `gameLoader` (`fetch` с `request.signal`, `null` для ответа с ошибкой) и замените `useParams` на `useLoaderData<typeof gameLoader>()`.
2. В `routes.tsx` подключите `loader: gameLoader` к маршруту игры, а корневому маршруту дайте `HydrateFallback`.
3. В `Layout` — `useNavigation()` и `aria-busy` у `<main>`.
:::

## Что получилось

У шага задержка бэкенда — 1000 мс. Щёлкните «Остров сокровищ» на главной: секунду главная остаётся на месте и приглушена, адрес ещё `/`; потом — страница игры и `/games/1`. Во вкладке «Сеть» — `GET /api/games/1`. Введите в адресную строку `/games/4`: секунду только «Загружаем…» — ни шапки, ни подвала, — потом магазин. `/games/999` — бэкенд ответил `404`, на экране «Игра не найдена».

## Эксперименты

1. **Уйти раньше ответа.** Щёлкните «Остров сокровищ» и, пока страница приглушена, — «Корзина» в шапке. Откроется корзина, а в «Сети» запрос игры — **отменён**: роутер прервал переход и отменил `request.signal`. Без `signal` в `fetch` запрос дошёл бы до конца впустую.
2. **Без `HydrateFallback`.** Уберите его и откройте `/games/4`. Секунду пусто, а в консоли:

   ```
   No `HydrateFallback` element provided to render during initial hydration
   ```

   Верните.
3. **Нет кэша.** Откройте игру, вернитесь «← Назад» и откройте снова — в «Сети» второй запрос. `loader` выполняется при каждом переходе: он загружает, но не хранит. Кэш — задача главы 11.

## Как в настоящем проекте

- `loader` начинает загрузку в момент щелчка, а не после рендера: страница с данными открывается раньше, чем с `useEffect`, и без «мигания» пустого состояния. Это главный довод за режим данных.
- `loader` не заменяет серверный кэш: повторы, устаревание, общие данные нескольких страниц — дело TanStack Query (глава 11). В настоящих проектах их соединяют: `loader` **запускает** запрос в кэше (`queryClient.ensureQueryData`), а компонент читает его через `useQuery`.
- Медленный загрузчик держит пользователя на старой странице. Если данных много, а часть может подождать, `loader` возвращает обещание, а страница показывает его через `<Suspense>` и `use` (главы 11 и 12).
