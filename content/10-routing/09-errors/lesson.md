Включите во вкладке «Сеть» флажок «Ошибка 500» и откройте «Ночной экспресс». На странице — «Игра не найдена». Неправда: игра есть, просто сервер упал. Наш `loader` на любой неудачный ответ возвращает `null`, и страница не отличает «нет такой игры» от «сервер не ответил». А проверка `game === null` в каждом компоненте — шум.

Роутер предлагает другой путь: загрузчик **бросает** ошибку, а показывает её отдельный компонент — **граница ошибок** (error boundary) маршрута.

## Бросить ответ

```tsx game/GamePage.tsx
  // Нет игры или сервер упал — не страница, а ошибка маршрута:
  // её покажет ближайший ErrorBoundary
  if (!response.ok) {
    throw data(null, { status: response.status });
  }
  return (await response.json()) as Game;
```

[`data`](https://reactrouter.com/api/utils/data) создаёт ответ с кодом — как ответ сервера. Брошенный из `loader` или `action`, он прерывает загрузку, и роутер вместо страницы рисует `ErrorBoundary` ближайшего маршрута. Документация советует так поступать именно с ответами вроде 404: «не нашли — бросили 404 и пошли дальше».

Теперь `useLoaderData<typeof gameLoader>()` — просто `Game`, без `null`: если компонент рендерится, данные точно есть. Ветка «Игра не найдена» из `GamePage` уходит.

## Граница ошибок

```tsx layout/RouteError.tsx
// Граница ошибок маршрутов: что показать вместо страницы,
// если loader, action или сам компонент бросили ошибку
export function RouteError() {
  const error = useRouteError();
  // Повторить: роутер заново вызовет загрузчики страницы
  const revalidator = useRevalidator();

  // Ответ с кодом — его бросили намеренно: throw data(…, { status })
  if (isRouteErrorResponse(error) && error.status === 404) {
    return <NotFoundPage />;
  }
  return (
    <Section title="Что-то пошло не так">
      <p className="muted">
        {isRouteErrorResponse(error)
          ? `Сервер ответил ошибкой ${error.status}.`
          : 'Ошибка в приложении — мы уже знаем о ней.'}
      </p>
      <Button
        onClick={() => revalidator.revalidate()}
        disabled={revalidator.state === 'loading'}
      >
        Попробовать снова
      </Button>
    </Section>
  );
}
```

- [`useRouteError`](https://reactrouter.com/api/hooks/useRouteError) — что бросили. Тип — `unknown`: бросить можно что угодно.
- [`isRouteErrorResponse`](https://reactrouter.com/api/utils/isRouteErrorResponse) отличает **ответ** (`throw data(…)`, есть `status`) от **исключения** — ошибки в коде (`TypeError`, `throw new Error`).
- 404 — та же страница, что у маршрута `*`: одна «Такой страницы нет» на весь магазин.
- [`useRevalidator`](https://reactrouter.com/api/hooks/useRevalidator) — `revalidate()` заново вызывает загрузчики текущего адреса. Сервер ожил — страница откроется.

## Где поставить границу

```tsx routes.tsx {5,8-10}
  {
    path: '/',
    Component: Layout,
    // Ошибка в самом макете: страницы без шапки, но с объяснением
    ErrorBoundary: RouteError,
    children: [
      {
        // Маршрут без path: общая граница ошибок для всех страниц —
        // ошибка страницы не сносит шапку и подвал макета
        ErrorBoundary: RouteError,
        children: [
          { index: true, Component: HomePage },
          …
          { path: '*', Component: NotFoundPage },
        ],
      },
    ],
  },
```

Граница маршрута заменяет **его** компонент. Граница корневого маршрута заменила бы `Layout` — пропали бы шапка и подвал. Поэтому страницы обёрнуты в маршрут **без `path`** и без компонента: он ничего не рисует (вместо компонента — просто `<Outlet />`), не добавляет сегмента к адресу, зато несёт границу ошибок для всех детей. Корневая граница остаётся на случай, если сломается сам макет.

```
ошибка в GamePage
 └─ Layout ✓          шапка на месте
     └─ (без path) ✗  ← ErrorBoundary: RouteError
         └─ GamePage  не нарисован
```

::: task
1. В `gameLoader` на неудачный ответ бросайте `data(null, { status: response.status })`; ветку `game === null` в `GamePage` удалите.
2. В заготовке `layout/RouteError.tsx` напишите границу: 404 — `NotFoundPage`, иначе «Что-то пошло не так», текст для ответа сервера и для ошибки в коде, кнопка «Попробовать снова» через `useRevalidator`.
3. В `routes.tsx` дайте `ErrorBoundary: RouteError` корневому маршруту и оберните все страницы в маршрут без `path` с той же границей.
:::

## Что получилось

`/games/999` — «Такой страницы нет», шапка и подвал на месте. Включите «Ошибка 500» во вкладке «Сеть» и откройте любую игру — «Что-то пошло не так», «Сервер ответил ошибкой 500.». Снимите флажок и нажмите «Попробовать снова» — страница игры открылась без перехода и ⟳.

## Эксперименты

1. **Ошибка в компоненте.** Добавьте в начало `GameDetails` строку `if (game.id === 4) throw new Error('Бум');` и откройте «Ночной экспресс». Та же граница: «Ошибка в приложении — мы уже знаем о ней.» А в консоли — два сообщения: React пишет `The above error occurred in the <GameDetails> component.` и что пересоздаст дерево с границей `RenderErrorBoundary`, а роутер — `React Router caught the following error during render Error: Бум`. Граница маршрута ловит всё: ошибки загрузчиков, действий и рендера. Уберите строку.
2. **Только корневая граница.** Удалите `ErrorBoundary` у маршрута без `path` и откройте `/games/999`: «Такой страницы нет» — но без шапки и подвала. Ошибка поднялась до ближайшей границы, а это корневой маршрут — он заменил весь макет.
3. **Без границ.** Удалите и корневую: на `/games/999` — встроенная страница роутера `Unexpected Application Error!`. Она годится только разработчику. Верните обе.

## Как в настоящем проекте

- Минимум — граница у корневого маршрута; лучше — ещё одна внутри макета, как у нас, и у крупных разделов (кабинет, админка): ошибка в виджете кабинета не должна прятать меню кабинета.
- Ошибки в коде отправляют в сервис мониторинга (Sentry и подобные) — из границы или из `onError` у `RouterProvider`. Пользователю показывают человеческий текст, а не `error.message`: в нём бывают подробности, не предназначенные пользователю.
- Граница ошибок — не для ошибок форм. «Неверный пароль», «на складе только 0» — это ожидаемый результат действия: его возвращают из `action` (шаг «Изменение данных»), а не бросают.

::: deep Как это устроено
Граница маршрута — это граница ошибок React (error boundary): компонент, который ловит исключения при рендере своих детей. Свою такую границу в React можно написать только классом (`componentDidCatch`, `getDerivedStateFromError`) — функциональных аналогов нет, поэтому роутер держит готовую (`RenderErrorBoundary`) и показывает в ней ваш `ErrorBoundary`. Ошибки загрузчиков и действий React не видит вовсе — их ловит сам роутер и рисует ту же границу. В главе 11 появится библиотека `react-error-boundary` — граница без класса для мест без роутера.
:::
