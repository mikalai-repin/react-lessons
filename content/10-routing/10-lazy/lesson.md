`routes.tsx` импортирует все страницы магазина в начале файла. В настоящем проекте сборщик (Vite) соберёт их в один файл JavaScript, и покупатель, который зашёл посмотреть одну игру, скачает и код оформления заказа, и кабинет, а в главе 18 — ещё и админку с Ant Design. Чем больше приложение, тем дольше первый экран.

Решение — **разделение кода** (code splitting): редкие страницы грузить, только когда на них переходят. Возьмём оформление заказа: до него доходит малая часть посетителей.

## Динамический import

Обычный `import` в начале файла выполняется сразу. **Динамический** — `import('./checkout/CheckoutPage')` — это функция: она возвращает обещание модуля и загружает его, только когда её вызвали. Сборщики видят динамический импорт и выносят модуль (со всем, что нужно только ему) в отдельный файл — **чанк** (chunk).

## lazy

У маршрута вместо `Component` и `action` может быть `lazy` — функция, которая загрузит их при первом переходе:

```tsx routes.tsx
          {
            path: 'checkout',
            // Ленивый маршрут: код оформления загрузится при первом
            // переходе на /checkout — вместе с компонентом и action
            lazy: async () => {
              const { CheckoutPage, checkoutAction } =
                await import('./checkout/CheckoutPage');
              return {
                Component: CheckoutPage,
                action: checkoutAction,
              };
            },
          },
```

`lazy` возвращает свойства маршрута — `Component`, `loader`, `action`, `ErrorBoundary`, всё, кроме того, что нужно для **сопоставления** адреса: `path`, `index`, `children` остаются в `routes.tsx`. Роутер должен знать, что `/checkout` существует, ещё до загрузки кода.

Статический импорт `checkoutAction, CheckoutPage` из начала `routes.tsx` удалите. Если модуль импортирован где-то статически, сборщик положит его в основной файл, и разделения не будет.

## Что получилось

Снаружи — ничего не изменилось: оформление работает, заказ уходит. Чтобы увидеть разницу, добавьте в `checkout/CheckoutPage.tsx` после импортов `console.log('модуль оформления выполнен');`. При запуске магазина строки нет. Перейдите к оформлению — появилась. Уйдите и вернитесь — новой нет: модуль загружается один раз.

В превью курса все файлы шага уже в памяти, поэтому «загрузка» мгновенная, а во вкладке «Сеть» — только запросы к `/api`. В настоящем проекте после `npm run build` (глава 23) у оформления будет свой файл `CheckoutPage-….js`, и в Network браузера он появится в момент перехода на `/checkout`.

## Как в настоящем проекте

- Делят по крупным разделам: оформление, кабинет, админка, редкие страницы. Главную и каталог оставляют в основном файле — их видят все. Делить каждую мелкую страницу — получить десятки крошечных запросов.
- Почему `lazy` маршрута лучше `React.lazy` внутри страницы: роутер вызывает `lazy` **в момент перехода** и параллельно с загрузкой данных. `React.lazy` начал бы грузить код, только когда React попытается отрисовать компонент, — уже после того, как данные пришли: «водопад» из двух запросов подряд. `React.lazy` и `Suspense` — для частей страницы (тяжёлый редактор, график), глава 12.
- В режиме фреймворка разделение по маршрутам делается само: каждый файл маршрута — свой чанк.
