Покупатель хочет видеть, сколько он сэкономил на акции. Добавим в мини-корзину строку «Скидка по акции: 500 ₽» — и заодно разберёмся, где в приложении со стором считать **производное** — то, что вычисляется из состояния: число штук, итог, скидку, сколько осталось до бесплатной доставки.

## Хранить или вычислять

Правило из главы 5 («Вычислять, а не хранить») для стора не меняется: в сторе лежит **минимум** — позиции `items`. Итог в состоянии стора пришлось бы обновлять в каждом действии, и однажды его забудут обновить. А вычислить его можно всегда.

Вычислять можно в двух местах.

- **В селекторе**, если результат — примитив. `selectCartCount` возвращает число: шапка рендерится, только когда число штук изменилось.
- **При рендере**, если результат — новый объект или массив. Компонент выбирает из стора `items` (тот же массив, пока корзина не менялась) и считает из него всё остальное.

## Селекторы рядом со стором

Шапка считала штуки прямо в селекторе. Вынесем селектор в отдельный модуль и дадим ему имя — пригодится в других местах и в тестах (глава 17):

```tsx store/cartSelectors.ts
// С какой суммы доставка бесплатная, ₽
export const FREE_DELIVERY = 5000;

/** Селектор: сколько штук в корзине. Число — сравнивается Object.is */
export const selectCartCount = (state: CartState) =>
  state.items.reduce((sum, item) => sum + item.quantity, 0);
```

```tsx layout/Header.tsx
  const cartCount = useCartStore(selectCartCount);
```

Именованный селектор — функция модуля, а не новая стрелочная функция при каждом рендере. Для React разницы нет (переподписки и так не было), но читать `useCartStore(selectCartCount)` проще.

## Итоги — при рендере

Всё, что мини-корзина считала в теле компонента, переезжает в чистую функцию `summarizeCart(items, games)`: позиции вместе с играми, число штук, итог, скидка и остаток до бесплатной доставки.

```tsx store/cartSelectors.ts {21-31}
/** Итоги корзины из позиций и каталога. Не селектор: возвращает
 *  новый объект — вызываем при рендере, уже выбрав items */
export function summarizeCart(
  items: CartState['items'],
  games: Game[],
) {
  // Позиции вместе с играми: название, цена, остаток.
  // В корзину попадают только игры каталога — find найдёт игру всегда
  const lines = items.map((item) => ({
    ...item,
    game: games.find((game) => game.id === item.gameId)!,
  }));
  const count = lines.reduce(
    (sum, line) => sum + line.quantity,
    0,
  );
  const total = lines.reduce(
    (sum, line) => sum + line.game.price * line.quantity,
    0,
  );
  // Сколько сэкономил покупатель: разница со старой ценой
  const savings = lines.reduce(
    (sum, line) =>
      sum +
      ((line.game.oldPrice ?? line.game.price) -
        line.game.price) *
        line.quantity,
    0,
  );
  const toFreeDelivery = Math.max(FREE_DELIVERY - total, 0);
  return { lines, count, total, savings, toFreeDelivery };
}
```

Функция не знает ни о React, ни о Zustand: на входе — данные, на выходе — итоги. Каталог передаём аргументом, а не импортируем: в главе 11 игры придут с сервера, и функция не изменится.

В `MiniCart` вместо вычислений — один вызов, а под итогом — новая строка:

```tsx cart/MiniCart.tsx
  const items = useCartStore((state) => state.items);
  …
  // Итоги считаем при рендере из выбранных позиций
  const { lines, count, total, savings, toFreeDelivery } =
    summarizeCart(items, games);
```

```tsx cart/MiniCart.tsx
      {savings > 0 && (
        <p className={`muted ${styles.delivery}`}>
          Скидка по акции: {formatPrice(savings)}
        </p>
      )}
      <p className={`muted ${styles.delivery}`}>
        {toFreeDelivery === 0
          ? 'Доставка бесплатно'
          : `До бесплатной доставки — ${formatPrice(toFreeDelivery)}`}
      </p>
```

## Что получилось

Два «Острова сокровищ» в корзине: «Итого: 3 980 ₽», «Скидка по акции: 1 000 ₽», «До бесплатной доставки — 1 020 ₽». Добавьте «Драконью почту» (у неё нет старой цены): итог 5 270 ₽, скидка та же, «Доставка бесплатно».

## Эксперименты

1. **Итоги в селекторе.** Соблазн — посчитать всё прямо в селекторе и не выбирать `items`:

   ```tsx
   const { lines, count, total, savings, toFreeDelivery } =
     useCartStore((state) => summarizeCart(state.items, games));
   ```

   Магазин пропал: `The result of getSnapshot should be cached…` и `Maximum update depth exceeded`. Каждый вызов `summarizeCart` возвращает новый объект.

2. **И `useShallow` не поможет.** Оберните тот же селектор в `useShallow(…)` — та же ошибка. `useShallow` сравнивает поля: `count`, `total`, `savings` — числа и совпадают, а `lines` — **новый массив** из `map`, и поле «изменилось». Поверхностное сравнение спасает, только когда поля — то, что уже лежит в состоянии (как действия в `MiniCart`), или примитивы.

Верните `useCartStore((state) => state.items)` и вызов при рендере.

## Как в настоящем проекте

- Именованные селекторы (`selectCartCount`, `selectIsInCart(id)`) — рядом со стором; сложные вычисления — чистыми функциями, которые легко проверить тестом без React.
- Вычисление при рендере повторяется на каждом рендере компонента. Для корзины из пяти позиций это ничто. Тяжёлое (сортировка тысячи товаров) запоминают `useMemo` по `items` — или React Compiler сделает это сам (глава 16).
- Есть библиотеки для запоминания селекторов — например, `reselect` (его `createSelector` входит в Redux Toolkit, глава 19). С Zustand они нужны редко: выбрать исходные данные и посчитать при рендере проще.
- Производное, которое зависит от нескольких сторов и нужно многим компонентам, — повод взглянуть на атомы: у них производные значения встроены в модель (шаг «Атомы»).
