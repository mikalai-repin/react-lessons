Две задачи от отдела продаж.

**Склад.** Сейчас «Ночной экспресс» нельзя положить в корзину больше трёх раз, потому что кнопка выключается: `disabled={quantity >= game.inStock}`. Это правило повторено в трёх местах — в карточке, на странице игры и в «+» мини-корзины. Добавят четвёртое место (кнопку в избранном, бота в мессенджере) — и правило забудут. Правила предметной области живут в **сторе**: кнопки просто зовут `add`, а `add` решает, можно ли.

**Промокод.** Код `ХОДКОНЁМ` даёт 10 % скидки на корзину от 3 000 ₽. Если покупатель применил код, а потом убрал игры и сумма стала меньше 3 000 ₽, — промокод снимается сам.

Что уже в проекте:

- `data/promo.ts` — `PROMO_CODE`, `PROMO_PERCENT = 10`, `PROMO_MIN_TOTAL = 3000`;
- в `MiniCart.module.css` — классы `.promo` (поле и кнопка в строку) и `.promoError` (текст ошибки);
- срезы, селекторы и `persist` из этой главы.

::: task
1. **Склад.** Уберите `disabled` по остатку из `GameCard`, `GameDetails` и кнопки «+» в `MiniCart` («Нет в наличии» оставьте). В `add` среза корзины: если в корзине уже столько штук, сколько на складе, — не добавлять и показать уведомление «Больше нет: на складе 3 шт.» (число — `inStock` игры).
2. **Состояние промокода.** В срез корзины — поле `promo: string | null` и действие `applyPromo(code)`: код сравнивается без учёта регистра и пробелов по краям; неверный — вернуть текст «Нет такого промокода»; сумма меньше порога — «Промокод действует от 3 000 ₽»; иначе — записать `PROMO_CODE` в `promo` и вернуть `null`.
3. **Снятие.** После каждого изменения позиций: если промокод применён, а сумма меньше порога, — `promo: null` и уведомление «Промокод снят: сумма меньше 3 000 ₽».
4. **Итоги.** `summarizeCart(items, games, promo)` считает ещё `promoDiscount` (10 % от суммы, `Math.round`) и `payable` (к оплате).
5. **Мини-корзина.** Без промокода — форма: поле `name="promo"` с `aria-label="Промокод"` и кнопка «Применить»; ошибку из `applyPromo` — под формой в `<p role="alert">`. С промокодом — вместо формы строки «Промокод ХОДКОНЁМ: −957 ₽» и «К оплате: 8 613 ₽».
6. **Сохранение.** Промокод переживает перезапуск вместе с позициями.
:::

::: hint Подсказка 1: где проверять склад и порог
Оба правила — в `store/cartSlice.ts`. Остаток — `inStock` игры из `games`, количество в корзине — `quantityInCart(get().items, gameId)` из главы 8. Порог проверяйте в `dispatch` — после `set` позиций: через него проходят все четыре действия, и правило не забудется ни в одном.
:::

::: hint Подсказка 2: сумма в сторе
Сумма — производное, хранить её не нужно. В сторе посчитайте её той же функцией, что и мини-корзина: `summarizeCart(get().items, games, null).total`. Срез может импортировать `cartSelectors.ts` — круга нет: селекторы импортируют из стора только тип.
:::

::: hint Подсказка 3: ошибка формы — не в сторе
Текст ошибки нужен только форме, пока она на экране, — это локальное состояние `MiniCart`: `useState<string | null>(null)`. Форма — неуправляемая (глава 5):

```tsx
function handlePromoSubmit(e: SubmitEvent<HTMLFormElement>) {
  e.preventDefault();
  const code = new FormData(e.currentTarget).get('promo');
  setPromoError(applyPromo(String(code)));
}
```

`applyPromo` вернёт `null` при успехе — и ошибка заодно сбросится.
:::

::: hint Подсказка 4: сохранение
`partialize` решает, что попадёт в `localStorage`: добавьте туда `promo`. Поднимать `version` не обязательно: старые записи без `promo` при чтении сольются с начальным состоянием, и `promo` будет `null`.
:::

## Проверьте себя

Нажмите **«✓ Проверить»** под редактором: платформа перезапустит магазин, пройдёт по нему сама и, если что-то не так, подскажет, куда смотреть. Пункты ниже — та же проверка руками, с объяснениями и экспериментами, которых кнопка не делает.

- Нажмите «В корзину» у «Ночного экспресса» четыре раза: в корзине 3 шт., внизу — «Больше нет: на складе 3 шт.», а кнопка не выключается. В мини-корзине «+» у экспресса делает то же самое: правило одно, в сторе.
- Введите «скидка» и нажмите «Применить» — «Нет такого промокода». Введите « ходконём » (строчными, с пробелами) — «Промокод ХОДКОНЁМ: −957 ₽», «К оплате: 8 613 ₽», формы нет. Сумма 9 570 ₽ складывается из цен со скидкой по акции: промокод действует поверх неё.
- Нажмите ⟳ — промокод на месте. В Application под ключом `cart`: `{"state":{"items":[{"gameId":4,"quantity":3}],"promo":"ХОДКОНЁМ"},"version":1}`.
- Уберите два экспресса: остался один, 3 190 ₽ — промокод ещё действует («К оплате: 2 871 ₽»). Уберите последний — промокод снят, внизу «Промокод снят: сумма меньше 3 000 ₽».
- Положите два «Острова сокровищ» (3 980 ₽), примените код, нажмите «−»: 1 990 ₽ — промокод снят. Попробуйте применить снова — «Промокод действует от 3 000 ₽».
- **Действие без кнопки.** В `main.tsx` после импортов: `setTimeout(() => { for (let i = 0; i < 5; i++) useCartStore.getState().add(4); }, 500);` (и импорт `useCartStore`). В корзине всё равно 3 экспресса: правило склада не зависит от того, кто зовёт действие. Уберите код.
- Консоль пуста, ошибок типов нет.

## Итоги главы

Корзина переехала из контекста во внешнее хранилище: сначала самодельное, потом Zustand с сохранением, срезами и журналом действий. Фильтры витрины стали атомами Jotai.

| Запись | Что делает |
|---|---|
| `useSyncExternalStore(subscribe, getSnapshot)` | подписка компонента на внешнее хранилище, снимок сравнивается `Object.is` |
| `create<T>()((set, get) => ({ … }))` | стор Zustand: данные и действия, возвращает хук |
| `useCartStore((state) => state.items)` | селектор: рендер, только когда изменилась выбранная часть |
| `useShallow((state) => ({ a, b }))` | несколько значений одним селектором |
| `useCartStore.getState()`, `.subscribe` | стор вне React |
| `persist(…, { name, partialize, version, migrate })` | сохранение в `localStorage`, что сохранять, миграция формата |
| `StateCreator<…>` + `(...api) => ({ ...a(...api), ...b(...api) })` | стор из срезов |
| `devtools(…, { name })`, `set(…, undefined, 'cart/added')` | журнал в Redux DevTools |
| `atom(value)`, `atom((get) => …)`, `atom(null, (get, set) => …)` | атом, производный атом, атом-действие Jotai |
| `useAtom`, `useAtomValue`, `useSetAtom` | чтение и запись атомов |

И главные идеи:

- внешний стор — состояние вне дерева React: модуль с подпиской, который читают компоненты и зовут любые модули. Провайдер не нужен;
- селектор решает цену стора: компонент рендерится, только когда изменился **его** снимок. Возвращайте то, что уже лежит в состоянии, или примитив — новый объект из селектора даёт бесконечный цикл, и `useShallow` спасает только от новой обёртки, а не от новых данных внутри;
- в сторе — минимум, производное считается при рендере или чистыми функциями; правила предметной области (склад, промокод) — в действиях стора, а не в кнопках;
- `persist` сохраняет то, что вернул `partialize`; изменили формат — поднимите `version` и напишите `migrate`;
- `useSyncExternalStore` защищает от пропущенных изменений и от разрыва в прерываемом рендере; Zustand построен на нём, Jotai — на `useReducer` со своей сверкой;
- где жить состоянию, решают по карте: серверные данные — серверный кэш, то, чем делятся ссылкой, — адрес, формы — форма, остальное — от `useState` до стора.

В главе 10 у магазина появятся настоящие страницы: React Router 8, адреса `/games/8` и `/catalog?category=family`. Фильтры уедут из атомов в адрес, а `selectedId` — в параметр маршрута.
