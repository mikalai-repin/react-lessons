Положите «Остров сокровищ» в корзину и нажмите ⟳ в адресной строке превью. Корзина пуста: состояние стора живёт в памяти страницы, а перезапуск начинает модуль заново. Покупатель, который случайно закрыл вкладку, будет недоволен.

В главе 7 мы сохраняли черновик отзыва своим хуком `useLocalStorage`. У Zustand для этого есть промежуточные слои (**middleware**) — обёртки вокруг функции, которую получает `create`. Middleware перехватывает `set` и добавляет стору поведение: сохранение, журнал для отладки, Immer. Сохранение делает [`persist`](https://zustand.docs.pmnd.rs/reference/middlewares/persist).

## persist

Оберните функцию стора в `persist` и дайте ключ для `localStorage`:

```tsx store/cartStore.ts
import { persist } from 'zustand/middleware';

// persist сохраняет корзину в localStorage: она переживает перезапуск
export const useCartStore = create<CartState>()(
  persist(
    (set) => {
      … // тело без изменений
    },
    {
      // Ключ в localStorage
      name: 'cart',
    },
  ),
);
```

Теперь каждый `set` записывает состояние в `localStorage`, а при создании стора `persist` читает сохранённое и сливает с начальным. Запись — JSON, функции (наши действия) в него не попадают и после перезапуска берутся из начального состояния.

Почему `'cart'`, а не, скажем, `'hod-konem-cart'`? Хранилище превью общее для всех шагов курса, и демо-магазин шага 1.1 уже хранит под `hod-konem-cart` свою корзину — с позициями другой формы (`{ game, quantity }`). Тот же ключ — и наш стор прочитал бы чужие данные. В настоящем проекте ключ тоже выбирают так, чтобы он не совпал с чужим на том же домене.

Положите «Остров» в корзину и нажмите ⟳. Корзина на месте — и в первом же рендере: `localStorage` читается синхронно, и `persist` успевает до того, как React вызовет компоненты. Но внизу висит «Добавлено: Остров сокровищ» — и не гаснет ни через три секунды, ни через минуту.

## partialize

Посмотрите, что сохранилось: инструменты разработчика → Application (Приложение) → Local Storage → адрес превью → ключ `cart`:

```json
{"state":{"items":[{"gameId":1,"quantity":1}],"toast":"Добавлено: Остров сокровищ"},"version":0}
```

`persist` сохранил **всё** состояние, и текст уведомления тоже. После перезапуска он вернулся, а таймер, который его гасит, остался в прошлой жизни страницы. Уведомление — не данные корзины, сохранять его не нужно. Что сохранять, говорит `partialize`:

```tsx store/cartStore.ts
      // Сохраняем только позиции: уведомление после перезапуска не нужно
      partialize: (state) => ({ items: state.items }),
```

Нажмите ⟳. Уведомление… всё ещё висит. В хранилище — старая запись с `toast`: `partialize` решает, что **записывать**, а прочитали мы то, что записала прошлая версия кода. Перезапишется запись только при следующем `set`. У ваших покупателей в браузерах тоже лежат данные прошлой версии магазина — так что «положите ещё что-нибудь в корзину» не выход.

## version и migrate

У сохранённой записи есть номер формата — `"version":0` (по умолчанию). Мы изменили формат: теперь в записи только позиции. Поднимем версию и объясним `persist`, как переделать старые данные:

```tsx store/cartStore.ts
      // Версия формата сохранённых данных: меняется — нужна миграция
      version: 1,
      // Версия 0 сохраняла всё состояние — берём из него только позиции
      migrate: (persisted) => {
        const { items } = persisted as { items: CartItem[] };
        return { items };
      },
```

При чтении `persist` сравнивает версию записи со своей. Не совпала — зовёт `migrate(сохранённое, версияЗаписи)`, сливает результат с начальным состоянием и **сразу перезаписывает** хранилище в новом формате. Тип у `persisted` — `unknown`: TypeScript не знает, что лежит в чужом браузере, поэтому форму называем явно через `as`. Если версий станет несколько, второй аргумент подскажет, с какой начинать: `if (version < 2) …`.

::: task
1. Оберните функцию стора в `persist` с `name: 'cart'`. Положите игру в корзину, нажмите ⟳ — корзина на месте, а уведомление застряло.
2. Добавьте `partialize`, чтобы сохранялись только позиции, и снова ⟳ — уведомление всё ещё висит.
3. Поднимите `version` до `1` и напишите `migrate`, который берёт из старой записи только `items`.

## Что получилось

⟳ — корзина на месте, уведомления нет. В Application под ключом `cart` новая запись:

```json
{"state":{"items":[{"gameId":1,"quantity":1}]},"version":1}
```

Корзина теперь переживает и переход между шагами курса: хранилище общее, а кнопка «Сброс» кода его не трогает. Очистить корзину можно в самом магазине или удалив ключ `cart` в Application.

## Эксперименты

1. **Версия без миграции.** Поставьте `version: 2` и удалите `migrate`. После ⟳ в консоли:

   ```
   State loaded from storage couldn't be migrated since no migrate function was provided
   ```

   и пустая корзина: `persist` не знает, как читать запись версии 1, и начинает с начального состояния. Ошибку видит только разработчик, а покупатель просто потерял корзину. Верните `version: 1` и `migrate` — после ⟳ корзина снова на месте: неудачная миграция запись в хранилище не трогает.

2. **Действия не сохраняются.** Посмотрите запись в Application ещё раз: в ней нет `add`, `remove` — JSON не умеет хранить функции. Даже без `partialize` действия после перезапуска брались бы из кода, а не из хранилища: `persist` сливает сохранённое с начальным состоянием на один уровень.

## Как в настоящем проекте

- `partialize` пишут сразу: в сторе почти всегда есть временное (уведомления, открытые окна, флаги загрузки), которое не должно переживать перезапуск.
- Изменили форму сохраняемого (переименовали поле, добавили обязательное) — поднимите `version` и напишите `migrate`. Иначе у пользователей с данными старой версии приложение может упасть на `undefined`.
- Хранилище не только `localStorage`: `storage: createJSONStorage(() => sessionStorage)` — до закрытия вкладки; асинхронные хранилища (IndexedDB, React Native) читаются не сразу, и первый рендер будет с пустой корзиной. Узнать, что данные прочитаны, помогают `useCartStore.persist.hasHydrated()` и `onFinishHydration`.
- При серверном рендеринге (часть 3) на сервере нет `localStorage`: HTML рисуется с пустой корзиной, и после чтения хранилища в браузере экран меняется. Для этого у `persist` есть `skipHydration` и ручной `rehydrate()`.
- Данные, которые должны жить у пользователя на всех устройствах, хранят на сервере, а не в браузере: `localStorage` — только этот браузер на этом устройстве.
