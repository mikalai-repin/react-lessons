Эффекты удобны, и у новичков в React быстро появляется привычка: «что-то изменилось — сделаю это в эффекте». Пока вы разбирались со строгим режимом, коллега так и поступил — добавил в магазин три эффекта. Всё работает… почти. Найдём, что с ними не так, и уберём все три.

Что изменилось в старте:

- `cart/MiniCart.tsx`: итог корзины `total` теперь состояние, которое пересчитывает эффект при изменении `items`;
- `game/GameDetails.tsx`: отзыв очищает эффект «при смене игры», а `key={selectedGame.id}` из `App` убран;
- `App.tsx`: `handleAdd` запоминает id последней добавленной игры в состоянии `lastAdded`, а уведомление показывает эффект, который следит за `lastAdded`.

## Главный вопрос

Эффект — для синхронизации с **внешней системой** (шаг 4). Перед каждым эффектом спросите: «С чем я синхронизирую?» Если ответ — «с другим состоянием» или «с действием пользователя», эффект лишний. Ни в одном из трёх случаев внешней системы нет.

## 1. Производное значение в эффекте

```tsx cart/MiniCart.tsx
  // Итог пересчитываем, когда изменилась корзина
  const [total, setTotal] = useState(0);
  useEffect(() => {
    setTotal(
      items.reduce(
        (sum, item) =>
          sum +
          games.find((game) => game.id === item.gameId)!.price *
            item.quantity,
        0,
      ),
    );
  }, [items, games]);
```

Это ровно тот случай, о котором предупреждал шаг «Вычислять, а не хранить» в главе 5. Добавьте в начало `MiniCart` строку `console.log('render MiniCart');` и нажмите «В корзину» у «Острова сокровищ». Что происходит:

```
рендер: total = 0      → фиксация: «Итого: 0 ₽»
эффект: setTotal(1990) → ещё рендер
рендер: total = 1990   → фиксация: «Итого: 1 990 ₽»
```

В консоли четыре строки `render MiniCart` — два рендера, каждый дважды из-за строгого режима. А в DOM на мгновение попал неверный итог «Итого: 0 ₽» и «До бесплатной доставки — 5 000 ₽». Глазом вы его не увидите: после щелчка React выполняет эффекты до того, как браузер нарисует кадр (разберём в шаге «Под капотом»). Но после таймера или ответа сервера браузер может успеть нарисовать и промежуточный вариант.

**Исправление** — вычислить при рендере, как было:

```tsx cart/MiniCart.tsx
  const total = lines.reduce(
    (sum, line) => sum + line.game.price * line.quantity,
    0,
  );
```

Две строки `render MiniCart` на щелчок, неверного итога в DOM нет. `useEffect` и `useState` уберите из импорта (`useRef` остаётся).

## 2. Сброс состояния в эффекте

```tsx game/GameDetails.tsx
  // Сменилась игра — очищаем отзыв
  useEffect(() => {
    setReview('');
    setSent(false);
  }, [game.id]);
```

А `key` у `<GameDetails>` в `App` убран. Откройте «Остров сокровищ», напишите «Отличная игра» и нажмите «Следующая игра →». Поле очистилось — эффект работает. Но с логом `console.log('render GameDetails', game.title)` видно цену: четыре строки `render GameDetails Драконья почта` вместо двух. Первый рендер «Драконьей почты» прошёл со **старым** отзывом: в DOM побывал счётчик «13 / 300» у игры, о которой никто не писал, и только эффект запустил второй рендер с пустым полем.

К тому же эффект сбрасывает только то, что в нём перечислено. Появится у страницы новое состояние — его придётся не забыть добавить сюда же.

**Исправление** — `key`, как в главе 5: другая игра — другой компонент, всё его состояние начинается заново.

```tsx App.tsx {2}
          <GameDetails
            key={selectedGame.id}
            game={selectedGame}
```

Эффект из `GameDetails` удалите, импорт `useEffect` — тоже.

## 3. Логика события в эффекте

```tsx App.tsx
  // Какую игру добавили последней — для уведомления
  const [lastAdded, setLastAdded] = useState<number | null>(null);

  // Добавили игру — показываем уведомление
  useEffect(() => {
    if (lastAdded === null) return;
    const { title } = games.find((game) => game.id === lastAdded)!;
    showToast(`Добавлено: ${title}`);
  }, [lastAdded]);

  function handleAdd(gameId: number) {
    dispatch({ type: 'added', gameId });
    setLastAdded(gameId);
  }
```

Нажмите «В корзину» у «Острова сокровищ», а через полторы секунды — ещё раз у него же. Уведомление исчезнет примерно через секунду после второго щелчка: таймер не начался заново. Второй щелчок записал в `lastAdded` то же `1`, зависимость не изменилась — эффект не запустился.

Эффект отвечает на вопрос «что сейчас **на экране**?», а не «что **произошло**?». Уведомление показывается не потому, что `lastAdded` стало каким-то, а потому, что покупатель **нажал кнопку**. У этого кода есть точное место — обработчик события, в котором известно, что произошло.

**Исправление** — вернуть вызов в обработчик, состояние `lastAdded` и эффект удалить:

```tsx App.tsx
  function handleAdd(gameId: number) {
    dispatch({ type: 'added', gameId });
    const { title } = games.find((game) => game.id === gameId)!;
    showToast(`Добавлено: ${title}`);
  }
```

::: task
1. В `MiniCart` замените состояние `total` и эффект вычислением при рендере.
2. В `GameDetails` удалите эффект сброса, а в `App` верните `key={selectedGame.id}` странице игры.
3. В `App` удалите `lastAdded` и эффект уведомления, вызовите `showToast` прямо в `handleAdd`.
4. Уберите лишние импорты: `useEffect` больше нигде, кроме `Countdown`, не нужен.
:::

## Что получилось

Магазин ведёт себя как до прихода коллеги: верный итог с первого рендера, пустой отзыв у каждой новой игры, повторный щелчок по той же игре продлевает уведомление. Эффект в приложении снова один — таймер скидки в `Countdown`: вот у него внешняя система есть.

## Как узнать лишний эффект

| Если эффект… | Вместо него |
|---|---|
| вычисляет значение из props и состояния и кладёт в состояние | вычисление при рендере |
| сбрасывает состояние при смене props | `key` |
| поправляет часть состояния при смене props | вычисление при рендере; в крайнем случае — `set` во время рендера с проверкой (react.dev) |
| реагирует на действие пользователя (отправить, показать уведомление, перейти) | обработчик события |
| уведомляет родителя об изменении состояния (`onChange` в эффекте) | вызвать `onChange` в том же обработчике, где меняется состояние |
| запускает следующий эффект, тот — следующий (цепочка) | вычислить всё в одном обработчике или при рендере |

Цепочка — частый итог привычки «всё через эффекты»: эффект по `card` ставит `goldCount`, эффект по `goldCount` ставит `round`, эффект по `round` — `isGameOver`. Каждое звено — лишний рендер и ещё одно место, где состояние на мгновение противоречиво. Всё это вычисляется в одном обработчике хода.

Эффект **нужен**, когда код должен выполниться потому, что компонент **показан**: таймер, подписка на событие окна, подключение к серверу, сторонний виджет, аналитика показа страницы (следующий шаг).

## Как в настоящем проекте

Правило линтера `react-hooks/set-state-in-effect` (в наборе `recommended` плагина `eslint-plugin-react-hooks` 7) находит все три эффекта из старта: «Calling setState synchronously within an effect can trigger cascading renders». Предупреждение — повод задать главный вопрос: с какой внешней системой синхронизирует этот эффект?

Подробный разбор с примерами — статья [You Might Not Need an Effect](https://react.dev/learn/you-might-not-need-an-effect) в документации React.
