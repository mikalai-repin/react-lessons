Выберите в каталоге категорию «Детские»: игр нет, на месте сетки — «Ничего не нашлось» и кнопка «Сбросить фильтры». Нажмите её с клавиатуры (Tab до кнопки, затем Enter). Игры вернулись, а фокус пропал: кнопка исчезла вместе с пустой витриной, и браузер отправил фокус на `<body>`. Тот, кто работает с клавиатурой или экранным диктором, оказался «нигде» и должен снова добираться до поиска табуляцией.

Правильно — после сброса поставить фокус в поле поиска. В браузере для этого есть `input.focus()`. Но как получить сам элемент `<input>`, если его создаёт React?

## ref на элементе

DOM-элемент можно положить в ссылку из прошлого шага. Создайте её с `null` и передайте элементу атрибутом `ref`:

```tsx
const searchRef = useRef<HTMLInputElement>(null);
…
<input ref={searchRef} type="search" />
```

После того как React создаст элемент и вставит его в DOM (фаза фиксации, глава 4), он запишет элемент в `searchRef.current`. Когда элемент уйдёт со страницы, React вернёт туда `null`. Тип `useRef<HTMLInputElement>(null)` — `RefObject<HTMLInputElement | null>`: TypeScript напоминает, что элемента может и не быть, поэтому обращаемся к нему через `?.`.

```
рендер:   searchRef.current === null
фиксация: React создал <input>
          → searchRef.current = <input>
щелчок:   searchRef.current.focus()
```

Читать ссылку на DOM можно в обработчиках событий и эффектах — тогда, когда фиксация уже прошла.

## ref — обычный проп

Поле поиска рисует не `App`, а `CatalogFilters`. Значит, ссылку нужно передать компоненту, а он отдаст её своему `<input>`. В React 19 `ref` у функционального компонента — **обычный проп**: объявите его в типе props и деструктурируйте, как любой другой.

```tsx catalog/CatalogFilters.tsx {1,7-8,14,18}
import type { Ref } from 'react';
…
type CatalogFiltersProps = {
  filters: Filters;
  // Покупатель изменил фильтр — новый объект фильтров целиком
  onChange: (filters: Filters) => void;
  // Ссылка на поле поиска — для фокуса снаружи
  ref?: Ref<HTMLInputElement>;
};

export function CatalogFilters({
  filters,
  onChange,
  ref,
}: CatalogFiltersProps) {
  …
        <input
          ref={ref}
          type="search"
```

`Ref<T>` — общий тип для всего, что можно передать в атрибут `ref`: объект из `useRef` или функция (о ней ниже).

Теперь `App` создаёт ссылку, отдаёт её панели и ставит фокус в обработчике сброса:

```tsx App.tsx {2-10}
  const visibleGames = filterGames(games, filters);
  // Поле поиска в DOM: React положит его сюда после фиксации
  const searchRef = useRef<HTMLInputElement>(null);

  // Сброс фильтров: кнопка исчезнет вместе с пустой витриной —
  // фокус переводим в поиск, чтобы он не потерялся
  function handleReset() {
    setFilters(INITIAL_FILTERS);
    searchRef.current?.focus();
  }
```

```tsx App.tsx {2}
              <CatalogFilters
                ref={searchRef}
                filters={filters}
                onChange={setFilters}
              />
              …
                  <Button onClick={handleReset}>
                    Сбросить фильтры
                  </Button>
```

Поле поиска есть на странице и до, и после сброса, поэтому `focus()` можно вызвать прямо в обработчике.

::: task
1. В `CatalogFilters` добавьте в props `ref?: Ref<HTMLInputElement>` и передайте `ref` полю поиска.
2. В `App` создайте `searchRef` и передайте его `<CatalogFilters ref={searchRef}>`.
3. Напишите `handleReset`: сбросить фильтры и поставить фокус в поиск. Подключите его к кнопке «Сбросить фильтры».
:::

## Что получилось

«Детские» → «Сбросить фильтры»: шесть игр, курсор мигает в поле поиска, можно сразу печатать — и с клавиатуры, и после щелчка мышью.

## Эксперименты

1. **Без `focus()`.** Уберите строку `searchRef.current?.focus();` и повторите сброс. Сразу после сброса начните печатать — буквы никуда не попадут, фокус снова на `<body>`. Верните строку.
2. **`ref` без типа.** Уберите `ref` из типа props, из деструктуризации и с `<input>`. Редактор подчеркнёт `<CatalogFilters ref={searchRef}>`: `Property 'ref' does not exist on type 'IntrinsicAttributes & CatalogFiltersProps'.` Запустите всё равно: консоль молчит, фокус не ставится. React передал `ref` в props, но компонент его никуда не отдал. Верните код.
3. **Ссылка во время рендера.** Добавьте в `App` сразу после `useRef` строку `console.log('render App, поле:', searchRef.current);`. При запуске — две строки `render App, поле: null` (строгий режим вызывает рендер дважды): при рендере `<input>` ещё не создан. Введите букву в поиск — `render App, поле: <input>`. Значение ссылки зависит от того, была ли уже фиксация, — поэтому при рендере её не читают. Уберите строку.

## Колбэк-ref

В атрибут `ref` можно передать и **функцию**. React вызовет её с элементом, когда подключит его, а если функция вернула другую функцию — вызовет её как **очистку**, когда отключит элемент (это появилось в React 19):

```tsx
<input
  ref={(node) => {
    console.log('ref:', node);
    return () => console.log('очистка ref');
  }}
/>
```

Подставьте это в `CatalogFilters` вместо `ref={ref}` и посмотрите в консоль:

- при запуске: `ref: <input>`, `очистка ref`, `ref: <input>` — строгий режим подключает ссылку, отключает и подключает снова (зачем — в шаге 5);
- на каждую букву в поиске: `очистка ref`, `ref: <input>`. Стрелочная функция при каждом рендере новая, и React честно отключает старую и подключает новую;
- при переходе на страницу игры: `очистка ref` — каталог ушёл со страницы.

Без `return` React при отключении вызовет саму функцию с `null`: `ref: <input>`, `ref: null`, `ref: <input>`.

Колбэк-ref нужен, когда при появлении элемента надо что-то **сделать**: подключить к нему стороннюю библиотеку, `ResizeObserver`, измерить его. Очистка — место, где это отключают. Если важен только сам элемент, хватит `useRef`.

TypeScript следит за тем, что возвращает колбэк. Сокращённая запись `ref={(node) => (input = node)}` возвращает элемент, а не функцию очистки: `Type 'HTMLInputElement | null' is not assignable to type 'void | (() => VoidOrUndefinedOnly)'.` Пишите тело в фигурных скобках. Верните `ref={ref}`.

## Как в настоящем проекте

- Типичные ссылки на DOM: фокус, прокрутка к элементу (`scrollIntoView`), выделение текста, размеры элемента, управление `<video>`, подключение сторонних библиотек к узлу.
- Ссылка на DOM — запасной выход. Всё, что можно описать разметкой (`disabled`, `value`, классы), описывайте разметкой: если менять DOM в обход React, при следующем рендере он может перезаписать ваши изменения.
- Для фокуса при появлении элемента есть атрибут `autoFocus`; ссылка нужна, когда фокус ставится в ответ на действие.

::: legacy
До React 19 функциональный компонент не принимал `ref` как проп: React забирал его из props, как `key`. Чтобы передать ссылку дальше, компонент оборачивали в `forwardRef`:

```tsx
const CatalogFilters = forwardRef<HTMLInputElement, Props>(
  function CatalogFilters({ filters, onChange }, ref) { … },
);
```

`forwardRef` в React 19 работает, но не нужен. А колбэк-ref до React 19 не умел возвращать очистку: при отключении его всегда вызывали с `null`.
:::
