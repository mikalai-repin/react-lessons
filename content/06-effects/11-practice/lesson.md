В каталоге шесть игр, но в настоящем магазине их сотни, и рисовать все сразу незачем. Покажем каталог **порциями**: сначала три игры, а когда покупатель докрутит до конца сетки — следующие три. Для тех, кто пользуется клавиатурой или чей браузер не умеет следить за прокруткой, под сеткой будет кнопка «Показать ещё».

Узнать, что элемент появился на экране, поможет браузерный [`IntersectionObserver`](https://developer.mozilla.org/ru/docs/Web/API/IntersectionObserver): он следит за элементом и вызывает колбэк, когда тот входит в видимую область или выходит из неё. Это внешняя система — значит, эффект с очисткой.

Что уже в проекте:

- `catalog/LoadMore.module.css` — стиль полосы под сеткой `.loadMore`;
- `catalog/LoadMore.tsx` — только комментарий `TODO`.

::: task
1. В `catalog/LoadMore.tsx` напишите компонент `LoadMore({ onLoad })`: `<div className={styles.loadMore}>` с кнопкой `<Button>` «Показать ещё», которая вызывает `onLoad`.
2. В `LoadMore` добавьте эффект: создайте `IntersectionObserver`, который вызывает `onLoad`, когда полоса стала видна (`entry.isIntersecting`), начните наблюдать за `<div>` через ссылку, в очистке — `observer.disconnect()`. Эффект не должен перезапускаться, когда `onLoad` новая.
3. В `App` заведите константу `PAGE_SIZE = 3` и состояние `limit` (начальное — `PAGE_SIZE`). В сетке «Всех игр» рисуйте только первые `limit` найденных игр, а под сеткой — `<LoadMore>`, если найдено больше. `onLoad` прибавляет к `limit` ещё порцию.
4. Новые фильтры — новый список: при любом изменении фильтров (и при «Сбросить фильтры») показывайте первую порцию. Без эффектов.
5. Бейдж у «Все игры» по-прежнему показывает, сколько игр **найдено**, а не сколько показано.
:::

::: hint Подсказка 1: с чего начать
Начните с `App` и кнопки — без наблюдателя. `const shownGames = visibleGames.slice(0, limit);` и `shownGames.map(…)` в сетке. Сетку и `LoadMore` оберните во фрагмент: в тернарном операторе пустой витрины должна быть одна ветка. Когда кнопка работает, добавляйте эффект.
:::

::: hint Подсказка 2: IntersectionObserver
```tsx
const observer = new IntersectionObserver(([entry]) => {
  if (entry.isIntersecting) …;
});
observer.observe(ref.current!);
return () => observer.disconnect();
```

Колбэк получает массив записей — по одной на наблюдаемый элемент; у нас он один. Сразу после `observe` колбэк вызывается один раз с текущим состоянием — при запуске полоса внизу страницы, и `isIntersecting` будет `false`.
:::

::: hint Подсказка 3: почему onLoad через useEffectEvent
`App` передаёт `onLoad` стрелочной функцией — при каждом рендере `App` новой. Если поставить `onLoad` в зависимости эффекта, наблюдатель будет пересоздаваться после каждого рендера магазина: щелчок «В корзину» — новый наблюдатель. А вызывать `onLoad` нужно свежую. Это нереактивная часть эффекта — событие эффекта (шаг 7):

```tsx
const onVisible = useEffectEvent(() => onLoad());
useEffect(() => {
  …
  if (entry.isIntersecting) onVisible();
  …
}, []);
```
:::

::: hint Подсказка 4: сброс порции без эффекта
Соблазн — `useEffect(() => setLimit(PAGE_SIZE), [filters])`. Но это «сброс в эффекте» из шага 6: лишний рендер, и первый рендер с новыми фильтрами пройдёт со старым `limit`. Фильтры меняются в одном месте — в обработчике. Сделайте свой:

```tsx
function handleFiltersChange(next: Filters) {
  setFilters(next);
  setLimit(PAGE_SIZE);
}
```

Передайте его в `<CatalogFilters onChange={handleFiltersChange}>`, а в `handleReset` вызовите `handleFiltersChange(INITIAL_FILTERS)`. Тип `Filters` импортируйте из `./catalog/filters`.
:::

::: hint Подсказка 5: прибавить порцию
`limit` меняется от предыдущего значения — функция обновления (глава 4):

```tsx
{limit < visibleGames.length && (
  <LoadMore
    onLoad={() => setLimit((n) => n + PAGE_SIZE)}
  />
)}
```

Когда показаны все найденные игры, `LoadMore` уходит со страницы — и его очистка отключает наблюдатель.
:::

## Проверьте себя

- При запуске в «Все игры» бейдж «6», а в сетке три игры: «Остров сокровищ», «Драконья почта», «Ночной экспресс». Под ними — «Показать ещё».
- Прокрутите превью до конца — появились ещё три игры, кнопки больше нет.
- Добавьте в эффект `LoadMore` логи `наблюдение: старт` (перед `observe`) и `наблюдение: стоп` (в очистке). При запуске: `старт`, `стоп`, `старт` — строгий режим проверяет очистку. Докрутите до конца: `наблюдение: стоп` — все игры показаны, `LoadMore` ушёл. Нажмите «В корзину» у любой игры, пока полоса на странице: новых строк нет — наблюдатель не пересоздаётся.
- Выберите «Семейные» — три игры, кнопки нет: больше не найдено. Верните «Все» — снова три игры и «Показать ещё». Нажмите кнопку — шесть.
- «Детские» → «Сбросить фильтры» — первая порция, фокус в поиске.
- Уберите из эффекта очистку и поставьте `PAGE_SIZE = 2`. Одна прокрутка до конца — и вместо четырёх игр сразу шесть: строгий режим оставил два наблюдателя, и оба вызвали `onLoad`. Верните очистку и `3`.
- Консоль пуста, ошибок типов нет.

## Итоги главы

Магазин научился работать с внешним миром: уведомление с таймером, фокус после сброса фильтров, модальное окно подтверждения, таймер скидки, аналитика просмотра, подсказка у края окна, предупреждение о сети и каталог порциями.

| Запись | Что делает |
|---|---|
| `const ref = useRef(initial)` | значение между рендерами без рендера: `ref.current` |
| `<input ref={ref}>` | DOM-элемент в `ref.current` после фиксации |
| `ref?: Ref<HTMLInputElement>` в props | `ref` — обычный проп компонента (React 19) |
| `ref={(node) => { …; return () => … }}` | колбэк-ref с очисткой |
| `useImperativeHandle(ref, () => ({ open }))` | своё API компонента вместо DOM-элемента |
| `useEffect(() => { …; return () => … }, [deps])` | синхронизация с внешней системой, очистка |
| `useEffectEvent(() => …)` | нереактивная часть эффекта: свежие значения без перезапуска |
| `useLayoutEffect(…)` | замер и положение до отрисовки |
| `createPortal(children, document.body)` | нарисовать в другом DOM-узле, оставаясь в дереве React |
| `useSyncExternalStore(subscribe, getSnapshot)` | значение внешнего хранилища с подпиской |

И главные идеи:

- ссылка — для того, что не рисуется; состояние — для того, что на экране;
- эффект отвечает на вопрос «с какой внешней системой синхронизируем?». Нет внешней системы — нет эффекта: производное — при рендере, сброс — `key`, реакция на действие — в обработчике;
- зависимости диктует код эффекта; не хотите перезапуска — меняйте код (или выносите чтение в `useEffectEvent`), а не массив;
- настройка → очистка → настройка должны давать тот же результат, что одна настройка. Строгий режим проверяет это при первом запуске;
- порядок: рендер сверху вниз, фиксация и эффекты — снизу вверх; после щелчка эффекты выполняются до кадра, в остальных случаях — отдельной задачей; что должно быть верным в первом кадре — `useLayoutEffect`.

Таймер скидки, подписка на сеть, наблюдение за видимостью — всё это логика, которую хочется переиспользовать, а она живёт внутри компонентов вперемешку с разметкой. В главе 7 мы вынесем её в **собственные хуки**: `useCountdown`, `useMediaQuery`, `useInView` — и разберём правила хуков: почему их нельзя вызывать в условиях и где React хранит их между рендерами.
