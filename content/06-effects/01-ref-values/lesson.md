До сих пор всё в магазине жило внутри React: состояние, рендер, DOM, который React строит сам. Но настоящему приложению нужен и **внешний мир**: таймеры браузера, фокус в поле, модальные окна, сеть, размер окна. В этой главе мы научимся работать с ним — и узнаем правило, которое отличает нужный эффект от лишнего.

Начнём с маленькой задачи. После щелчка «В корзину» внизу окна должно появляться уведомление «Добавлено: Остров сокровищ» и через 2,5 секунды исчезать.

## Уведомление и таймер

Текст уведомления виден на экране — значит, это состояние: `toast`, `null` — уведомления нет. Спрятать его через 2,5 секунды поможет `setTimeout`:

```tsx
setToast(`Добавлено: ${title}`);
setTimeout(() => setToast(null), TOAST_MS);
```

Но покупатель может нажать «В корзину» ещё раз, пока первое уведомление на экране. Второе уведомление должно провисеть свои 2,5 секунды, а таймер от первого щелчка спрячет его раньше. Значит, при новом щелчке старый таймер нужно отменить: `clearTimeout(id)`. А для этого id таймера нужно где-то **сохранить до следующего щелчка**.

Где?

- **Переменная `let` внутри компонента** не подходит. Каждый рендер — новый вызов функции `App`, и все её локальные переменные создаются заново. К следующему щелчку id из прошлого рендера потерян.
- **Состояние** сохранится, но id таймера не нужен на экране. Состояние — это то, что React рисует: каждое его изменение означает рендер. Хранить в нём служебное значение — лишняя работа и путаница.

Нужна «коробка», которая переживает рендеры, как состояние, но не вызывает их.

## useRef

[`useRef`](https://react.dev/reference/react/useRef) возвращает объект с одним свойством `current`:

```tsx
const toastTimer = useRef<number | null>(null);
toastTimer.current;          // null — начальное значение
toastTimer.current = 42;     // можно менять напрямую
```

React создаёт этот объект при первом рендере и потом возвращает **тот же самый** объект при каждом следующем. Что вы положите в `current`, то там и останется — до следующей записи или до ухода компонента со страницы. А запись в `current` React не замечает: рендера не будет.

| | `useState` | `useRef` |
|---|---|---|
| Переживает рендеры | да | да |
| Изменение вызывает рендер | да | нет |
| Как менять | `setX(новое)` | `ref.current = новое` |
| Значение в текущем рендере | снимок | всегда последнее записанное |

Эта «коробка» называется **ссылкой** (ref). В следующем шаге в неё положит DOM-элемент сам React — отсюда и название.

```tsx App.tsx {1,6-7,11-27,32-33}
import { useRef, useState } from 'react';
…
const PROMO_HTML =
  'Неделя семейных игр: скидки до <b>20%</b> на «Остров сокровищ» и «Нарды»';

// Сколько показывается уведомление «Добавлено», мс
const TOAST_MS = 2500;

export function App() {
  …
  // Текст уведомления; null — уведомления нет
  const [toast, setToast] = useState<string | null>(null);
  // id таймера, который спрячет уведомление: нужен между рендерами,
  // но не на экране — поэтому ref, а не состояние
  const toastTimer = useRef<number | null>(null);

  function showToast(text: string) {
    setToast(text);
    // Прошлый таймер отменяем: отсчёт начинается заново
    if (toastTimer.current !== null) {
      clearTimeout(toastTimer.current);
    }
    toastTimer.current = setTimeout(
      () => setToast(null),
      TOAST_MS,
    );
  }

  // Обработчики сообщают, что случилось; менять — дело редьюсера
  function handleAdd(gameId: number) {
    dispatch({ type: 'added', gameId });
    const { title } = games.find((game) => game.id === gameId)!;
    showToast(`Добавлено: ${title}`);
  }
```

Само уведомление — в конце разметки `App`, после `<Footer />`. Стиль `.toast` уже в `App.module.css`: он прижимает уведомление к низу окна. `role="status"` подскажет экранному диктору, что текст нужно прочитать вслух, не переводя фокус:

```tsx App.tsx
      <Footer />
      {toast !== null && (
        <p className={styles.toast} role="status">
          {toast}
        </p>
      )}
    </>
```

`setTimeout` в браузере возвращает число — номер таймера, поэтому тип ссылки `number | null`.

2. Напишите функцию `showToast(text)`: показать текст, отменить прошлый таймер, если он есть, запустить новый и сохранить его id в `toastTimer.current`.
3. В `handleAdd` после `dispatch` найдите название игры и вызовите `showToast`.

## Что получилось

Нажмите «В корзину» у «Острова сокровищ» — внизу «Добавлено: Остров сокровищ», через 2,5 секунды оно исчезнет. Плюс в мини-корзине тоже вызывает `handleAdd` — и тоже показывает уведомление.

Теперь быстро: «В корзину» у «Острова», через секунду-полторы — у «Драконьей почты». Уведомление сменилось на «Драконью почту» и провисело полные 2,5 секунды после второго щелчка: первый таймер отменён.

## Эксперимент: переменная вместо ссылки

Замените ссылку обычной переменной: `let toastTimer: number | null = null;`, а `toastTimer.current` — на `toastTimer` (импорт `useRef` уберите). Ошибок типов нет, и одиночный щелчок работает как раньше.

Повторите быстрый сценарий: «Остров», через полторы секунды — «Драконья почта». Второе уведомление исчезнет примерно через секунду — когда сработал таймер **первого** щелчка. Второй щелчок произошёл уже в новом рендере, где `let toastTimer` снова `null`: отменять нечего. Верните `useRef`.

## Эксперимент: ссылка не снимок

В главе 4 мы видели, что состояние — снимок: внутри обработчика `toast` не меняется после `setToast`. Ссылка ведёт себя иначе. Добавьте в `showToast` две строки — до и после записи в ссылку:

```tsx App.tsx
    console.log('до:', toastTimer.current, toast);
    toastTimer.current = setTimeout(
      () => setToast(null),
      TOAST_MS,
    );
    console.log('после:', toastTimer.current, toast);
```

Нажмите «В корзину» у «Острова», затем сразу у «Нардов». В консоли:

```
до: null null
после: 1 null
до: 1 Добавлено: Остров сокровищ
после: 2 Добавлено: Остров сокровищ
```

Числа — номера таймеров, у вас они могут быть другими. Новое значение `current` видно **сразу**, на следующей строке. А `toast` в обоих щелчках — снимок рендера, в котором был вызван обработчик: при первом щелчке `null`, при втором — текст первого уведомления, хотя `setToast` уже вызван. Уберите логи.

## Правила для ссылок

- **В ссылке — то, что не рисуется.** Если значение нужно на экране, это состояние. Ссылку на экране React не обновит: её изменение не вызывает рендер.
- **Не читайте и не пишите `ref.current` во время рендера.** Рендер должен быть чистым (глава 3): одни и те же props и состояние — одна и та же разметка. Значение ссылки меняется в обход React, и рендер, который от него зависит, перестаёт быть предсказуемым. Ссылки читают и меняют в обработчиках событий и в эффектах (шаг 4). Исключение — ленивое создание: `if (ref.current === null) ref.current = new Something()`.

## Как в настоящем проекте

- В ссылках держат id таймеров и интервалов, `AbortController` запроса, который можно отменить, экземпляр сторонней библиотеки (карты, графика, плеера), флажок «уже отправили аналитику».
- `App` никогда не уходит со страницы, поэтому таймер уведомления безопасен. Таймер компонента, который может исчезнуть, нужно отменять при его уходе — это работа для эффекта с очисткой (шаг 4).
- В настоящем проекте `eslint-plugin-react-hooks` подсказывает правилом `refs`, если ссылку читают при рендере.

::: deep
Внутри React `useRef` — один из самых простых хуков. При первом рендере (`mountRef` в `react-dom-client.development.js`) React создаёт объект `{ current: initialValue }` и кладёт его в ячейку хука у файбера — там же, где лежит состояние `useState` (глава 4). При следующих рендерах он возвращает объект из ячейки, а аргумент `useRef` уже не смотрит. Никакой подписки на `current` нет — поэтому запись и не вызывает рендер.
:::
