У «Острова сокровищ», «Ночного экспресса» и «Нардов» скидка по акции. Покажем на странице такой игры, сколько ещё действует скидка: «Скидка действует ещё 1:59:58» — и пусть цифры идут каждую секунду.

В старте уже есть:

- `data/sale.ts` — `SALE_ENDS`, конец акции в миллисекундах. В настоящем магазине дата пришла бы с сервера, здесь — через два часа после запуска приложения;
- `formatDuration(ms)` в `shared/format.ts` — «1:05:09»;
- стили `shared/Countdown.module.css` и заготовка `shared/Countdown.tsx`.

## Где запустить таймер

Оставшееся время — это `deadline - now`, а `now` должно меняться раз в секунду. Текущее время на экране — значит, состояние `now`. Менять его будет `setInterval`. Вопрос — где его запустить.

- **В теле компонента** нельзя. Рендер должен быть чистым (глава 3): React вызывает компонент когда захочет и сколько захочет — в строгом режиме дважды, на каждое изменение состояния снова. Каждый вызов запускал бы новый интервал.
- **В обработчике события** некуда. Таймер нужен не потому, что покупатель что-то нажал, а потому, что **компонент на экране**. Ни одного события, к которому его можно привязать, нет.

Для такого кода в React есть **эффект** (effect) — функция, которую React вызывает **после фиксации**, когда компонент уже в DOM. Эффект синхронизирует компонент с **внешней системой** — всем, что живёт вне React: таймером браузера, подпиской на события окна, сетевым соединением, сторонней библиотекой.

## useEffect

```tsx
useEffect(() => {
  // настройка: подключиться к внешней системе
  return () => {
    // очистка: отключиться
  };
}, [зависимости]);
```

[`useEffect`](https://react.dev/reference/react/useEffect) принимает функцию настройки и массив **зависимостей** — значений из компонента (props, состояние, вычисленное из них), которые использует эффект. Функция настройки может вернуть **функцию очистки**.

Жизнь эффекта в компоненте:

```
появился на странице → настройка
рендер, зависимости те же → ничего
рендер, зависимость изменилась →
            очистка (старая) → настройка (новая)
ушёл со страницы → очистка
```

Массив зависимостей решает, когда эффект перезапускается:

| Запись | Когда выполняется настройка |
|---|---|
| `useEffect(fn, [a, b])` | после первой фиксации и когда изменились `a` или `b` (`Object.is`) |
| `useEffect(fn, [])` | только после первой фиксации |
| `useEffect(fn)` | после каждой фиксации |

## Таймер скидки

```tsx shared/Countdown.tsx
import { useEffect, useState } from 'react';
import { formatDuration } from './format';
import styles from './Countdown.module.css';

type CountdownProps = {
  // Когда закончится, мс (как Date.now())
  deadline: number;
};

// Обратный отсчёт до конца акции: «Скидка действует ещё 1:59:58»
export function Countdown({ deadline }: CountdownProps) {
  // Текущее время: обновляем раз в секунду
  const [now, setNow] = useState(() => Date.now());
  const finished = now >= deadline;

  // Синхронизация с внешней системой — таймером браузера
  useEffect(() => {
    // Акция закончилась — таймер больше не нужен
    if (finished) return;
    const id = setInterval(() => setNow(Date.now()), 1000);
    // Очистка: перед следующим запуском и при уходе со страницы
    return () => clearInterval(id);
  }, [finished]);

  return (
    <p className={styles.countdown}>
      {finished
        ? 'Акция закончилась'
        : `Скидка действует ещё ${formatDuration(deadline - now)}`}
    </p>
  );
}
```

Разберём решения:

- **С чем синхронизируем?** С таймером браузера: пока компонент на странице и акция идёт, интервал должен работать; ушёл компонент или акция закончилась — интервал нужно остановить. Ответ на этот вопрос — первое, что стоит сформулировать для любого эффекта.
- **Очистка** — `clearInterval(id)`. Без неё интервал продолжал бы вызывать `setNow` после ухода со страницы.
- **Зависимость `finished`**. Эффект читает `finished` — значит, `finished` в массиве. Каждую секунду `now` меняется, но `finished` остаётся `false`, и эффект не перезапускается: один интервал на всё время акции. Когда время выйдет, `finished` станет `true`: React вызовет очистку (интервал остановлен), затем настройку — а она сразу выходит.
- **`setNow` в зависимостях не нужна**: функция-сеттер у состояния не меняется между рендерами, React это гарантирует.
- **`useState(() => Date.now())`** — функция-инициализатор (глава 5): время берётся один раз, при создании состояния. `useState(Date.now())` вызывал бы `Date.now()` на каждом рендере впустую, а правило линтера `react-hooks/purity` отметит его ошибкой «Cannot call impure function during render».

На странице игры таймер нужен только при скидке:

```tsx game/GameDetails.tsx {4-6}
          <p className={styles.price}>
            {formatPrice(game.price)}
          </p>
          {game.oldPrice !== undefined && (
            <Countdown deadline={SALE_ENDS} />
          )}
```

Откройте «Остров сокровищ»: под ценой «Скидка действует ещё 2:00:00» (или чуть меньше — смотря сколько прошло с запуска), и каждую секунду время уменьшается. «Следующая игра →» — у «Драконьей почты» скидки нет, нет и таймера. Ещё раз — у «Ночного экспресса» таймер снова идёт.

## Эксперименты

Добавьте в эффект логи — строку перед `setInterval` и строку в очистку:

```tsx shared/Countdown.tsx
  useEffect(() => {
    if (finished) return;
    console.log('таймер: старт');
    const id = setInterval(() => setNow(Date.now()), 1000);
    return () => {
      console.log('таймер: стоп');
      clearInterval(id);
    };
  }, [finished]);
```

1. **Жизнь эффекта.** Откройте «Остров сокровищ»: `таймер: старт`, `таймер: стоп`, `таймер: старт`. Три строки вместо одной — работа строгого режима, ей посвящён следующий шаг. Подождите несколько секунд: новых строк нет, хотя компонент рендерится каждую секунду, — `finished` не меняется. Нажмите «← К каталогу»: `таймер: стоп`, страница ушла. Откройте «Остров» снова и нажмите «Следующая игра →» дважды: при переходе на «Драконью почту» — `таймер: стоп` (там таймера нет), на «Ночной экспресс» — снова `старт`, `стоп`, `старт`: у страницы другой `key`, это новый компонент.
2. **Без массива зависимостей.** Уберите `[finished]` — эффект выполняется после каждой фиксации. Каждую секунду в консоли `таймер: стоп`, `таймер: старт`: каждый тик интервала даёт рендер, а рендер — перезапуск интервала. Таймер работает, но создаётся заново каждую секунду. Верните `[finished]`.
3. **Конец акции.** В `data/sale.ts` замените два часа на `3 * 1000` и откройте «Остров» сразу после запуска. Через пару секунд — «Акция закончилась» и последняя строка `таймер: стоп`: зависимость изменилась, React вызвал очистку, а новая настройка вышла сразу. Верните два часа.
4. **async-эффект.** Напишите `useEffect(async () => { … })`. Редактор подчеркнёт: `Type 'Promise<(() => void) | undefined>' is not assignable to type 'void | Destructor'.` А в превью при открытии игры — ошибка React «useEffect must not return anything besides a function, which is used for clean-up. It looks like you wrote useEffect(async () => ...) or returned a Promise.», и приложение падает: асинхронная функция возвращает промис, а React ждёт от настройки функцию очистки или ничего. Асинхронный код пишут внутри эффекта: `useEffect(() => { async function load() { … } load(); }, […])`. Верните код.

Уберите логи.

## Правила зависимостей

- **В массиве — всё реактивное, что читает эффект**: props, состояние и всё, что из них вычислено в теле компонента. Не вы выбираете зависимости — их диктует код эффекта. Хотите, чтобы эффект перезапускался реже, — меняйте код эффекта (как здесь: читаем `finished`, а не `now`).
- Значения вне компонента (константы модуля, импорты) и сеттеры состояния в массив не входят: они не меняются между рендерами.
- В настоящем проекте за этим следит правило линтера `react-hooks/exhaustive-deps`: «React Hook useEffect has a missing dependency: 'deadline'. Either include it or remove the dependency array.»

## Как в настоящем проекте

- Эффекты — для синхронизации с внешними системами: таймеры, подписки на события `window` и `document`, `WebSocket`, сторонние виджеты (карта, график, редактор), ручные изменения DOM, аналитика показа. Если внешней системы нет — эффект, скорее всего, лишний (шаг 6).
- Загрузку данных тоже можно написать в эффекте, но у неё много ловушек: гонки ответов, отмена, кэш. Её разберём в главе 11 и там же перейдём на библиотеку.
- Логику «таймер скидки» в главе 7 вынесем в собственный хук `useCountdown`.

::: tip
Если вы пришли из Angular: эффект с `[]` похож на пару `ngOnInit` + `ngOnDestroy`, а с зависимостями — на реакцию на `ngOnChanges`. Но мыслить «событиями жизненного цикла» в React неудобно. Думайте о каждом эффекте отдельно: «пока зависимости такие — внешняя система настроена так». Настройка и очистка — две половины одной синхронизации.
:::
