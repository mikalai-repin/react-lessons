Маркетологи просят аналитику: засчитывать **просмотр** игры, если покупатель пробыл на её странице 3 секунды, и передавать, сколько штук игры у него в корзине в этот момент. Функция `track(event, data)` уже есть в `shared/analytics.ts`; в настоящем проекте она отправила бы событие на сервер, здесь — пишет в консоль.

## Эффект для аналитики

Просмотр засчитывается потому, что страница **показана**, а не потому, что покупатель что-то нажал. Это синхронизация с внешней системой — сервисом аналитики, — значит, эффект. Таймер на 3 секунды; ушёл покупатель раньше — очистка отменит таймер, просмотра не было.

Первый вариант:

```tsx game/GameDetails.tsx
  useEffect(() => {
    const id = setTimeout(
      () => track('просмотр', { gameId: game.id, inCart: quantity }),
      VIEW_DELAY,
    );
    return () => clearTimeout(id);
  }, [game.id]);
```

`VIEW_DELAY = 3000` — константа над компонентом. Попробуйте: откройте «Остров сокровищ» и **в первую же секунду** нажмите «В корзину». Через 3 секунды после открытия в консоли:

```
[аналитика] просмотр { gameId: 1, inCart: 0 }
```

На странице «В корзине: 1 шт.», а аналитика получила `0`.

## Устаревшее замыкание

Функция настройки эффекта — замыкание (closure): она «видит» переменные того рендера, в котором создана. Эффект запустился после первого рендера, когда `quantity` было `0`, и стрелочная функция в `setTimeout` запомнила именно этот `0`. Следующие рендеры создают новые функции с новым `quantity`, но эффект с зависимостью `[game.id]` не перезапускается — таймер держит функцию из первого рендера. Это **устаревшее замыкание** (stale closure) — то самое, о котором шла речь в главе 4: состояние в рендере — снимок, и каждая функция видит свой снимок.

Линтер в настоящем проекте предупредил бы сразу: `React Hook useEffect has a missing dependency: 'quantity'. Either include it or remove the dependency array.`

## Добавить в зависимости?

Послушаемся линтера: `[game.id, quantity]`. Повторите опыт — откройте «Остров», через секунду «В корзину», подождите, а потом нажмите «В корзину» ещё раз:

```
[аналитика] просмотр { gameId: 1, inCart: 1 }   ← через 4 с
[аналитика] просмотр { gameId: 1, inCart: 2 }   ← после второго щелчка
```

Число теперь свежее, но появились две ошибки. Первый просмотр пришёл через 4 секунды, а не через 3: изменение `quantity` вызвало очистку и перезапуск, отсчёт начался заново. А второй щелчок засчитал **второй просмотр** — страницу никто не открывал повторно.

Проблема в том, что эффект смешивает две роли:

- **реактивная** часть — то, на что эффект должен реагировать: открыта другая игра → новый отсчёт. Это `game.id`;
- **нереактивная** часть — то, что нужно лишь **прочитать** в момент отправки: сколько штук в корзине сейчас. Изменение `quantity` не повод засчитывать новый просмотр.

## useEffectEvent

[`useEffectEvent`](https://react.dev/reference/react/useEffectEvent) выносит нереактивную часть в отдельную функцию — **событие эффекта** (Effect Event). Её можно вызывать из эффекта, и она всегда видит **последние** props и состояние, но в зависимости эффекта не входит.

```tsx game/GameDetails.tsx {1,3,7-8,10-13,15-19}
import { useEffect, useEffectEvent, useState } from 'react';
…
import { track } from '../shared/analytics';
…
// Самый длинный отзыв, символов
const REVIEW_MAX = 300;
// Просмотр засчитываем, если покупатель пробыл на странице 3 с
const VIEW_DELAY = 3000;
…
  // Событие «просмотр»: читает свежее quantity, но не зависит от него
  const onView = useEffectEvent((gameId: number) => {
    track('просмотр', { gameId, inCart: quantity });
  });

  // Синхронизация с аналитикой: страница игры показана 3 с
  useEffect(() => {
    const id = setTimeout(() => onView(game.id), VIEW_DELAY);
    return () => clearTimeout(id);
  }, [game.id]);
```

- `onView` читает `quantity` в момент вызова — через 3 секунды, а не в момент запуска эффекта.
- `onView` в зависимости не входит: линтер знает про `useEffectEvent` и не требует её.
- `game.id` передаём аргументом: эффект зависит от него, и так видно, какой именно просмотр отправляется.

`useEffectEvent` стабилен с React 19.2 (в `@types/react` 19.3 объявлен в основном `index.d.ts`, а не в `canary.d.ts`).

::: task
1. В `GameDetails` добавьте константу `VIEW_DELAY = 3000` и импорт `track` из `../shared/analytics`.
2. Объявите событие эффекта `onView = useEffectEvent((gameId: number) => …)`, которое вызывает `track('просмотр', { gameId, inCart: quantity })`.
3. Напишите эффект: `setTimeout` на `VIEW_DELAY`, который вызывает `onView(game.id)`, очистка — `clearTimeout`, зависимость — `[game.id]`.
:::

## Что получилось

Откройте «Остров сокровищ» и в первую секунду нажмите «В корзину». Через 3 секунды после открытия — `[аналитика] просмотр { gameId: 1, inCart: 1 }`. Нажмите «В корзину» ещё раз — новых событий нет. Откройте игру и уйдите в каталог раньше 3 секунд — событий нет тоже. В строгом режиме событие одно: таймер первой настройки снят очисткой.

## Эксперимент: вызов при рендере

Вызовите `onView(game.id);` прямо в теле компонента, перед эффектом, и откройте игру. Ошибка: `A function wrapped in useEffectEvent can't be called during rendering.` — и приложение пропадает. Событие эффекта вызывают только из эффектов (в том числе из таймеров и подписок, которые эффект создал). Уберите вызов.

## Как в настоящем проекте

- Типичные события эффекта: аналитика с текущими настройками, уведомление с текущей темой оформления, обработчик сообщения из `WebSocket`, который читает текущий фильтр, колбэк из props, который подписка вызывает при событии.
- Не прячьте зависимости в `useEffectEvent`, чтобы «заткнуть» линтер. Вопрос всегда один: **должен ли эффект перезапускаться**, когда меняется это значение? Да — зависимость. Нет, его нужно только прочитать — событие эффекта.
- Событие эффекта не передают в другие компоненты и хуки и не вызывают из обработчиков щелчков — для этого есть обычные функции.

::: legacy
До `useEffectEvent` ту же задачу решали ссылкой: `const quantityRef = useRef(quantity);` и запись `quantityRef.current = quantity` в отдельном эффекте без зависимостей, а в таймере читали `quantityRef.current`. Так вы встретите это в старом коде. `useEffectEvent` делает то же самое, но без ручной синхронизации и с поддержкой линтера.
:::
