Этот шаг необязательный. Мы уже знаем, что эффект выполняется «после фиксации», а `useLayoutEffect` — «до отрисовки». Разберём точнее: в каком порядке React проходит по компонентам, когда подключает ссылки, когда очищает старые эффекты и в какой момент браузер получает шанс нарисовать кадр. Всё — по логу.

## Датчик

Замените содержимое `main.tsx` маленьким приложением. Компонент `Probe` пишет в консоль всё, что с ним происходит: рендер, ссылку на свой `<div>`, layout-эффект и обычный эффект с очистками. `Demo` рисует два датчика — `Parent` и вложенный в него `Child` — и три кнопки. Функция `markers` ставит метки: когда выполнится ближайшая **микрозадача** и когда браузер начнёт готовить **кадр** (`requestAnimationFrame` вызывается перед отрисовкой). Строгого режима нет — так лог короче.

```tsx main.tsx
import { useEffect, useLayoutEffect, useState } from 'react';
import type { ReactNode } from 'react';
import { createRoot } from 'react-dom/client';

type ProbeProps = { name: string; n: number; children?: ReactNode };

// Датчик: пишет в консоль рендер, ref и оба вида эффектов
function Probe({ name, n, children }: ProbeProps) {
  console.log(`render ${name}`);
  useLayoutEffect(() => {
    console.log(`  layout ${name}`);
    return () => console.log(`  layout: очистка ${name}`);
  }, [n]);
  useEffect(() => {
    console.log(`  effect ${name}`);
    return () => console.log(`  effect: очистка ${name}`);
  }, [n]);
  return (
    <div
      ref={() => {
        console.log(`  ref ${name}`);
        return () => console.log(`  ref: очистка ${name}`);
      }}
    >
      {children}
    </div>
  );
}

function Demo() {
  const [n, setN] = useState(0);
  const [child, setChild] = useState(true);
  // Метки: ближайшая микрозадача и ближайший кадр
  function markers(label: string) {
    console.log(label);
    queueMicrotask(() => console.log('  · микрозадача'));
    requestAnimationFrame(() => console.log('  · кадр'));
  }
  return (
    <>
      <button
        onClick={() => {
          markers('— щелчок');
          setN(n + 1);
        }}
      >
        +1
      </button>
      <button
        onMouseEnter={() => {
          markers('— наведение');
          setN(n + 1);
        }}
      >
        наведи
      </button>
      <button
        onClick={() => {
          markers('— убрать Child');
          setChild(false);
        }}
      >
        убрать
      </button>
      <Probe name="Parent" n={n}>
        {child && <Probe name="Child" n={n} />}
      </Probe>
    </>
  );
}

createRoot(document.getElementById('root')!).render(<Demo />);
```

## Запуск

```
render Parent
render Child
  ref Child
  layout Child
  ref Parent
  layout Parent
  effect Child
  effect Parent
```

Видно три фазы:

1. **Рендер** — сверху вниз: сначала `Parent`, потом `Child`. React вызывает компоненты и строит новое дерево; DOM ещё не тронут.
2. **Фиксация** (commit) — React вносит изменения в DOM, а затем проходит дерево **снизу вверх**: подключает ссылки и выполняет layout-эффекты. `ref Child` раньше `layout Child`: `<div>` — ребёнок компонента `Child`, а дети всегда раньше родителей. Поэтому в layout-эффекте ссылки на собственный DOM уже готовы.
3. **Пассивные эффекты** — обычные `useEffect`, тоже снизу вверх: `Child` раньше `Parent`. Родитель может рассчитывать, что эффекты детей уже выполнены.

## Щелчок

Нажмите «+1». Изменился `n` — зависимость обоих датчиков:

```
— щелчок
  · микрозадача
render Parent
render Child
  ref: очистка Child
  layout: очистка Child
  ref: очистка Parent
  layout: очистка Parent
  ref Child
  layout Child
  ref Parent
  layout Parent
  effect: очистка Child
  effect: очистка Parent
  effect Child
  effect Parent
  · кадр
```

- Во время фиксации React сначала **отключает**: старые ссылки (колбэк-ref при каждом рендере новый, шаг 2) и старые layout-эффекты. Затем **подключает** новые — снова снизу вверх.
- Пассивные эффекты — тоже двумя проходами: сначала **все** очистки, потом **все** новые настройки. Ни один новый эффект не встретит «неубранный» старый эффект соседа.
- Всё это случилось до `· кадр`. Щелчок — **дискретное** событие (как ввод, нажатие клавиши, отправка формы), и после него React выполняет пассивные эффекты сразу, в той же задаче, что и фиксацию. Пользователь не должен увидеть кадр, где щелчок уже обработан, а эффект ещё нет.

## Наведение

Наведите мышь на «наведи»:

```
— наведение
  · микрозадача
  · кадр
render Parent
…
```

Порядок фаз тот же, но сам рендер начался **после** кадра. Наведение и движение мыши — **непрерывные** события: их обновления React не обрабатывает сразу, а планирует отдельной задачей, давая браузеру отрисовать то, что уже было. Пассивные эффекты после таких обновлений, а также после первого запуска, таймера и ответа сервера React тоже выполняет **отдельной задачей** — браузер может успеть нарисовать кадр между фиксацией и эффектом. Именно поэтому замер для подсказки в шаге 8 делали в `useLayoutEffect`: он выполняется до любого кадра всегда.

Проверить, в той же ли задаче выполняются эффекты, можно микрозадачей. Добавьте в layout-эффект датчика строку:

```tsx main.tsx
    if (name === 'Parent')
      queueMicrotask(() => console.log('  · микрозадача из layout'));
```

Микрозадача выполняется, как только закончится текущая задача. После щелчка `effect Child` в логе **раньше** `· микрозадача из layout` — та же задача. После наведения и при запуске — **позже**: эффекты выполнились отдельной задачей.

## Удаление компонента

Нажмите «убрать»:

```
— убрать Child
  · микрозадача
render Parent
  layout: очистка Child
  ref: очистка Child
  ref: очистка Parent
  ref Parent
  effect: очистка Child
  · кадр
```

`Child` исчез — React вызвал его очистки: layout-эффекта и ссылки во время фиксации, обычного эффекта — следом. У `Parent` `n` не изменился, и его эффекты не тронуты, перевыполнилась только колбэк-ссылка (новая функция при рендере).

## Схема

```
 рендер (чистый, можно повторить)
   ↓
 фиксация: изменения DOM
   отключить старые ref, layout-очистки
   подключить ref, layout-эффекты
   (снизу вверх)
   ↓
 пассивные эффекты: очистки, настройки
   — щелчок, ввод: сразу, до кадра
   — иначе: отдельной задачей
   ↓
 браузер рисует кадр
```

В `react-dom-client.development.js` это видно в функции фиксации: после layout-фазы пассивные эффекты выполняются сразу, если обновление было на синхронной полосе (`pendingEffectsLanes & 3` — так React помечает дискретные события), иначе планируются через `scheduleCallback`.

## Что из этого следует

- **Эффект не обязан ждать отрисовки и не обязан опережать её.** Если важно, что увидит пользователь в первом кадре, — `useLayoutEffect`. Во всех остальных случаях — `useEffect`, и не стройте логику на том, был ли кадр.
- **Дети раньше родителей.** Эффект родителя может пользоваться тем, что подготовили эффекты детей (например, их DOM-ссылками), но не наоборот.
- **Очистка — перед новой настройкой** того же эффекта и перед уходом компонента, в том же порядке снизу вверх.
- В строгом режиме к этой схеме добавляется имитация «ухода и возвращения» при первом появлении (шаг 5) — поэтому строгий режим здесь и отключён.
