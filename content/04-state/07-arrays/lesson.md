Одного числа корзине мало: карточка должна знать, сколько штук **её** игры уже выбрано, — чтобы показать «В корзине: 2 шт.» и не дать положить больше, чем есть на складе. Корзине нужны **позиции**: какая игра и сколько штук. Это массив объектов, и с ним в React есть главное правило: состояние не изменяют, а заменяют.

## Позиция корзины

Тип — к остальным моделям:

```ts api/models.ts
/** Позиция корзины: какая игра и сколько штук */
export interface CartItem {
  gameId: number;
  quantity: number;
}
```

В позиции хранится `gameId`, а не копия игры: название и цену знает каталог, а корзина помнит только выбор покупателя.

## Обновить — значит создать новый

Как добавить игру в корзину? Если её там нет — нужен массив с новой позицией в конце. Если есть — массив, где у этой позиции `quantity` на 1 больше. И в обоих случаях — **новый массив**:

```tsx App.tsx {2-8,10-15,17-31}
export function App() {
  // Позиции корзины — общее состояние страницы
  const [cart, setCart] = useState<CartItem[]>([]);
  // Всего штук — считаем из позиций при рендере
  const cartCount = cart.reduce(
    (sum, item) => sum + item.quantity,
    0,
  );

  // Сколько штук игры уже в корзине
  function quantityOf(gameId: number) {
    return (
      cart.find((item) => item.gameId === gameId)?.quantity ?? 0
    );
  }

  function handleAdd(gameId: number) {
    setCart((items) => {
      const inCart = items.some(
        (item) => item.gameId === gameId,
      );
      // Новой игры ещё нет — новый массив с новой позицией в конце
      if (!inCart) return [...items, { gameId, quantity: 1 }];
      // Есть — новый массив, где у этой позиции новый объект
      return items.map((item) =>
        item.gameId === gameId
          ? { ...item, quantity: item.quantity + 1 }
          : item,
      );
    });
  }
```

- `[...items, новое]` — копия массива с элементом в конце, вместо `push`.
- `items.map(…)` — новый массив той же длины. Позицию нужной игры заменяет **новый объект** `{ ...item, quantity: … }`, остальные позиции переходят в новый массив как есть.
- `cartCount` больше не состояние: его можно вычислить из `cart` при каждом рендере. Хранить отдельно то, что выводится из другого состояния, — значит рисковать, что они разойдутся. Об этом подробно — в главе 5.

Тип состояния указан явно: `useState<CartItem[]>([])`. Из пустого массива TypeScript ничего не узнает и выведет `never[]` — массив, в котором не может быть ничего. Уберите `<CartItem[]>`, и редактор подчеркнёт каждое обращение к позиции: `Property 'quantity' does not exist on type 'never'.`

## Карточка получает своё количество

`App` передаёт каждой карточке её количество, а обработчик — стрелкой, которая знает id игры:

```tsx App.tsx {4-5}
              <GameCard
                key={game.id}
                game={game}
                quantity={quantityOf(game.id)}
                onAdd={() => handleAdd(game.id)}
              />
```

Карточке не нужно знать, как `App` хранит корзину: она получает число и функцию без аргументов. Строка «В корзине» и ограничение по остатку возвращаются, но теперь число приходит в props:

```tsx shared/GameCard.tsx {3-4,12,17-21}
type GameCardProps = {
  game: Game;
  // Сколько штук уже в корзине
  quantity: number;
  // Покупатель нажал «В корзину»
  onAdd: () => void;
};
…
      ) : (
        <Button
          onClick={onAdd}
          disabled={quantity >= game.inStock}
        >
          В корзину
        </Button>
      )}
      {quantity > 0 && (
        <p className={styles.inCart}>
          В корзине: {quantity} шт.
        </p>
      )}
```

`quantity > 0 &&` — сравнение, а не число: при нуле на экран попадёт `false`, а не `0` (ловушка из главы 2).

2. В `App.tsx` замените `cartCount` в состоянии на `cart: CartItem[]`; общее число вычисляйте через `reduce`. Напишите `quantityOf(gameId)` и перепишите `handleAdd(gameId)` так, чтобы он создавал новый массив.
3. Передайте карточкам `quantity={quantityOf(game.id)}` и `onAdd={() => handleAdd(game.id)}` — в обоих разделах.
4. В `GameCard.tsx` добавьте проп `quantity: number`, верните `disabled={quantity >= game.inStock}` и строку «В корзине: N шт.» — только если `quantity > 0`.

## Почему мутация «не работает»

Попробуем по-простому. Замените тело `handleAdd`:

```tsx App.tsx
  function handleAdd(gameId: number) {
    cart.push({ gameId, quantity: 1 });
    setCart(cart);
    console.log('позиций:', cart.length);
  }
```

Нажмите «В корзину» трижды. В консоли `позиций: 1`, `2`, `3`, а в шапке «Корзина: 0». Массив изменился, сеттер вызван — а рендера нет.

Перед рендером React сравнивает новое значение состояния со старым через `Object.is`. `push` изменил **тот же самый** массив, и `setCart(cart)` передал ту же ссылку. Для React «старое» и «новое» — один объект, значит, ничего не изменилось и рисовать нечего.

Хуже того, мутация никуда не делась. Пусть одна игра добавляется мутацией, а остальные — правильно: в `handleAdd` для `gameId === 1` оставьте `push`, для остальных — `setCart([...cart, { gameId, quantity: 1 }])`. Нажмите «Остров» дважды — на экране ничего. Нажмите «Ночной экспресс» — и сразу «Корзина: 3»: новый массив скопировал и две «тайные» позиции «Острова». Изменения, которых React не видел, всплывают в случайный момент.

Ещё одна мутация — внутри функции обновления: `const item = items.find(…); item.quantity += 1; return [...items];`. Массив новый, экран обновляется. Но три щелчка по «Острову» дают «В корзине: 5 шт.»: строгий режим вызывает функцию обновления дважды, и вторая прибавила к уже изменённому объекту. Без строгого режима было бы 3 — и ошибка всплыла бы позже, в продакшене. Верните `handleAdd` из решения.

## Как в настоящем проекте

Неизменяемые операции, которые заменяют мутирующие:

| Мутация | Без мутации |
|---|---|
| `arr.push(x)` | `[...arr, x]` |
| `arr.splice(i, 1)` | `arr.filter((x) => x.id !== id)` |
| `arr[i] = x` | `arr.map(…)` или `arr.with(i, x)` |
| `arr.sort()`, `arr.reverse()` | `arr.toSorted()`, `arr.toReversed()` |
| `obj.x = 1` | `{ ...obj, x: 1 }` |

- Spread копирует **один уровень**. Вложенный объект нужно копировать на каждом уровне, через который проходите: `{ ...game, players: { ...game.players, max: 6 } }`. Когда уровней много, берут библиотеку Immer (глава 5).
- Мутировать можно то, что вы только что создали сами: новый массив внутри обработчика можно `push`-ить и сортировать до того, как отдать в сеттер.

::: tip
Angular с OnPush и сигналами живёт по тем же правилам: `signal.update(arr => [...arr, x])`, а `arr.push(x)` без `set` ничего не перерисует. Разница в том, что в React это правило для **любого** состояния, без исключений.
:::
