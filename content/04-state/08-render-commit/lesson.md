Этот шаг необязательный. В прошлом шаге один щелчок по «В корзину» заставил React вызвать `App`, шапку и все девять карточек. Значит ли это, что React заново строит всю страницу? Нет — и сейчас мы это увидим. Разберём, что происходит между вызовом сеттера и изменением на экране.

## Три фазы

Любое обновление экрана в React проходит три фазы:

```
1. запуск    setCart(…) — в очередь
             (или root.render при старте)
2. рендер    App(), Header(), GameCard()…
             новые элементы сравниваются
             со старыми — сверка
3. фиксация  в DOM вносятся только отличия
                 ↓
         браузер рисует кадр
```

- **Запуск рендера** (trigger). Первый — `root.render` в `main.tsx`. Все следующие — вызовы сеттеров состояния. Пока сеттер не вызван, React ничего не делает (шаг 1 этой главы).
- **Рендер** (render). React вызывает компонент, чьё состояние изменилось, и всё, что этот компонент рисует, — в глубину, как в главе 3. Получает новые элементы и **сверяет** (reconciliation) их с файберами: что добавилось, что пропало, у какого элемента поменялись props. В этой фазе DOM не трогают — поэтому компонент обязан быть чистым: React вправе вызвать его лишний раз, а строгий режим так и делает.
- **Фиксация** (commit). Список отличий React применяет к DOM: создаёт, удаляет и меняет узлы. После этого браузер перерисовывает страницу.

## Эксперимент: кого вызвали

Добавьте `console.log` в начало трёх компонентов: `'render App'`, `'render Header'`, `'render GameCard', game.title`. Нажмите «В корзину» у «Острова сокровищ» в «Хитах». В консоли:

| Строка | Сколько раз |
|---|---|
| `render App` | 2 |
| `render Header` | 2 |
| `render GameCard …` | 18 |

Состояние живёт в `App`, поэтому рендер начался с `App` и прошёл по всему дереву: шапка, девять карточек — и всё, что внутри них (`Section`, `Badge`, `Rating`, `Button` мы не логировали). Каждый — дважды из-за строгого режима.

## Эксперимент: что изменилось в DOM

Теперь посмотрим, что дошло до DOM. `MutationObserver` — API браузера, которое сообщает о каждом изменении узлов. Добавьте в `main.tsx` перед `root.render(…)`:

```tsx main.tsx
new MutationObserver((records) => {
  for (const r of records) {
    if (r.type === 'characterData') {
      console.log('DOM: текст →', r.target.textContent);
    } else {
      for (const node of r.addedNodes) {
        console.log('DOM: добавлен', node.nodeName, node.textContent);
      }
    }
  }
}).observe(container, {
  subtree: true,
  childList: true,
  characterData: true,
});
```

Нажмите «В корзину» у «Острова сокровищ»:

```
DOM: текст → 1
DOM: добавлен P В корзине: 1 шт.
DOM: добавлен P В корзине: 1 шт.
```

Три изменения: число в шапке и по строке «В корзине» в двух карточках «Острова». Нажмите ещё раз — три изменения текста: `2` в шапке и `2` в двух строках «В корзине». Десятки вызовов компонентов — и три точечные правки DOM. Остальные карточки React вызвал, сравнил их новые элементы со старыми, нашёл, что всё совпадает, и DOM не тронул.

## Почему не перерисовать всё

Можно было бы после каждого рендера заменять весь `innerHTML`. Но DOM — дорогой и «с памятью»:

- создание и вставка узлов — медленнее, чем сравнение лёгких объектов-элементов;
- пересозданный узел теряет то, чего нет в JSX: фокус, позицию прокрутки, выделение текста, введённый в поле текст, состояние анимации и воспроизведения видео.

Поэтому React разделил работу: **рендер** дёшев и может повторяться, **фиксация** минимальна. Цена — правило «рендер чистый»: всё, что меняет мир снаружи, — в обработчиках (и, позже, в эффектах — глава 6).

Перерисовать девять карточек ради одной — тоже не бесплатно, хоть DOM и не трогается. В главе 16 мы научимся пропускать рендер компонентов, у которых не изменились props (`memo`, React Compiler). Пока магазин маленький, это не нужно.

## Когда рендера нет вовсе

Сравнение начинается раньше, ещё до рендера. Замените тело `handleAdd` на `setCart((items) => items)` и оставьте `console.log('render App')`. Нажмите кнопку — ни одной строки `render App`. Функция обновления вернула тот же массив, `Object.is` сказал «не изменилось», и React не стал рендерить. Так же работает `setQuantity(quantity)` с прежним числом. (Документация оговаривает, что иногда React всё же вызывает компонент один раз, прежде чем отказаться от рендера, — полагаться на «ни одного вызова» не стоит. В нашем эксперименте вызовов не было.)

Это и есть причина, по которой мутация в прошлом шаге «не работала»: тот же объект — нет изменений — нет рендера.

## Где хранится состояние

Состояние живёт в файбере компонента, в поле `memoizedState`. Посмотрим на него. Добавьте в конец `main.tsx`:

```tsx main.tsx
// После каждого щелчка — первый хук App из его файбера
document.addEventListener('click', () => {
  setTimeout(() => {
    const key = Object.keys(container).find((k) =>
      k.startsWith('__reactContainer'),
    )!;
    const app = (container as any)[key].stateNode.current.child.child;
    console.log(app.type.name, JSON.stringify(app.memoizedState.memoizedState));
  });
});
```

Путь к файберу `App`: `#root` → корень React → его текущее дерево → `StrictMode` → `App`. Нажмите «В корзину» у «Острова», у «Нард» и ещё раз у «Острова»:

```
App [{"gameId":1,"quantity":1}]
App [{"gameId":1,"quantity":1},{"gameId":10,"quantity":1}]
App [{"gameId":1,"quantity":2},{"gameId":10,"quantity":1}]
```

`memoizedState` файбера — это первый хук компонента, а его собственный `memoizedState` — значение состояния. Если хуков несколько, они связаны в список полем `next` — по порядку вызова. Поэтому порядок хуков и не должен меняться между рендерами (глава 7). Уберите эксперименты.

::: warning
Мы берём файбер от корня, а не из DOM-узла, как в главе 3, неспроста. React держит **две копии** дерева файберов: текущую (то, что на экране) и черновую, в которой готовит следующий рендер, — и после фиксации меняет их местами. Ссылка `__reactFiber$…` в DOM-узле может вести на копию, которая уже отстала на одно обновление. Как и в главе 3: это внутренности React, они могут измениться в любой версии — только для экспериментов.
:::

::: tip
Angular при проверке изменений сравнивает значения привязок шаблона с прошлыми и меняет в DOM только отличия — идея та же. Разница в том, что сравнивает: Angular — значения выражений в шаблоне, React — целые деревья элементов, которые заново возвращают компоненты.
:::
