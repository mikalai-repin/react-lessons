Магазин из главы 3 только показывает игры. Кнопка «В корзину» нарисована, но ничего не делает. В этой главе интерфейс начнёт отвечать на действия покупателя: кнопка будет считать штуки, шапка — показывать, сколько всего в корзине, а к концу главы появится мини-корзина с итогом.

Начнём с самого простого, что приходит в голову: заведём в карточке переменную и будем увеличивать её по щелчку.

## Обработчик щелчка

Чтобы кнопка реагировала на щелчок, ей передают функцию в атрибуте `onClick`. React вызовет её, когда покупатель нажмёт кнопку. Такая функция называется **обработчиком события** (event handler). Наш `Button` из главы 3 принимает всё, что принимает `<button>`, и передаёт `onClick` дальше через `...rest`.

```tsx shared/GameCard.tsx {8-15}
export function GameCard({ game }: GameCardProps) {
  …
  const discount =
    game.oldPrice === undefined
      ? 0
      : Math.round((1 - game.price / game.oldPrice) * 100);

  let quantity = 0;

  // Щелчок по «В корзину»
  function handleAddClick() {
    quantity += 1;
    console.log(`${game.title}: в корзине ${quantity}`);
  }

  return (
    …
```

Обратите внимание: в `onClick` передаётся **сама функция**, без скобок: `onClick={handleAddClick}`. Со скобками вы вызвали бы её сразу, во время рендера. Подробно о событиях — в шаге «События».

```tsx shared/GameCard.tsx {4,6}
      {game.inStock === 0 ? (
        <Button disabled>Нет в наличии</Button>

      <p className={styles.inCart}>В корзине: {quantity} шт.</p>
```

::: task
1. В `shared/GameCard.tsx` перед `return` объявите переменную `let quantity = 0` и функцию `handleAddClick`: она увеличивает `quantity` на 1 и выводит в консоль название игры и новое значение.
2. Передайте обработчик кнопке: `<Button onClick={handleAddClick}>`.
3. После кнопки, в самом конце `<article>`, выведите строку `<p className={styles.inCart}>В корзине: {quantity} шт.</p>`. Класс `inCart` уже есть в `GameCard.module.css`.
:::

## Что получилось

Под каждой кнопкой — «В корзине: 0 шт.». Нажмите «В корзину» у «Острова сокровищ» три раза. В консоли:

```
Остров сокровищ: в корзине 1
Остров сокровищ: в корзине 2
Остров сокровищ: в корзине 3
```

Обработчик работает, переменная растёт. А на экране по-прежнему «В корзине: 0 шт.».

## Почему экран не обновился

Причин две, и обе важны для всей главы.

**React не знает, что переменная изменилась.** Экран меняется, только когда React заново вызывает компонент — выполняет **рендер** — и переносит результат в DOM. Пока что рендер был один: при запуске приложения (`root.render` в `main.tsx`). React не следит за переменными: щелчок вызвал функцию, функция поменяла число, и всё. Повода рисовать заново у React нет.

**Даже если бы React перерисовал карточку, вы снова увидели бы 0.** Рендер — это вызов функции `GameCard`. Первая строка тела функции — `let quantity = 0`. Локальная переменная рождается при каждом вызове заново и умирает, когда функция вернула JSX. Между двумя рендерами её просто нет.

```
рендер 1: GameCard() → quantity = 0 → JSX с «0»
щелчок:   handleAddClick() → quantity = 1, 2, 3
          (React об этом не знает)
рендер 2: GameCard() → quantity = 0 → снова «0»
```

## Эксперимент: переменная снаружи компонента

Может, вынести переменную из функции, чтобы она не обнулялась? Перенесите `let quantity = 0;` из тела `GameCard` наверх файла, к константе `FEW_LEFT`. Нажмите «В корзину» у «Острова сокровищ» дважды, затем у «Нард»:

```
Остров сокровищ: в корзине 1
Остров сокровищ: в корзине 2
Нарды: в корзине 3
```

Стало хуже. Экран всё так же показывает нули — React по-прежнему ничего не знает. А переменная модуля одна на весь файл: все девять карточек считают в общий счётчик, и «Нарды» получили третью штуку «Острова». Компонент — функция, и он может стоять на странице сколько угодно раз. Своя память нужна каждому экземпляру отдельно. Верните переменную в тело функции.

## Что нужно на самом деле

Компоненту не хватает двух вещей:

1. **памяти между рендерами** — значения, которое не обнуляется при каждом вызове функции, причём своего у каждой карточки;
2. **способа сказать React** «данные изменились, нарисуй заново».

В React обе вещи даёт **состояние** (state) — о нём следующий шаг.

::: tip
В Angular этот код почти заработал бы: поле класса живёт столько же, сколько компонент, а после щелчка Angular сам запускает проверку изменений (через zone.js или сигналы) и перерисовывает шаблон. В React компонент — функция, а не объект: полей между вызовами у неё нет, и после событий React ничего не проверяет. Перерисовка начинается только тогда, когда вы явно сообщаете об изменении.
:::
