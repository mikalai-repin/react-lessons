Счётчик работает, но у «Ночного экспресса» на складе три штуки, а в корзину можно положить сколько угодно. Ограничим кнопку и заодно разберёмся, как устроены события в React: как передавать обработчики, что приходит в аргументе и как отменить действие браузера.

## Обработчик — это функция в пропе

У DOM-элементов в JSX есть свойства для событий: `onClick`, `onChange`, `onSubmit`, `onKeyDown`, `onPointerEnter` и другие. Имена — в camelCase, значение — функция.

Принятые имена: проп с обработчиком — `onЧто-то` (`onClick`, `onAdd`), функция внутри компонента — `handleЧто-то` (`handleAddClick`). Так по коду видно, где событие объявлено, а где обработано.

Передавать нужно **саму функцию**, а не результат её вызова:

| Запись | Что происходит |
|---|---|
| `onClick={handleAddClick}` | React вызовет функцию при щелчке |
| `onClick={() => setQuantity(0)}` | то же: новая функция-стрелка, удобно для аргументов |
| `onClick={handleAddClick()}` | функция вызвана **во время рендера**, в `onClick` попал её результат |

Попробуйте третий вариант. Редактор предупредит: `Type 'void' is not assignable to type 'MouseEventHandler<HTMLButtonElement> | undefined'.` А в превью экран станет пустым, в консоли — `Too many re-renders. React limits the number of renders to prevent an infinite loop.` Рендер вызвал `handleAddClick`, тот — `setQuantity`, сеттер запросил новый рендер, а он снова вызвал `handleAddClick`… React остановил бесконечный цикл ошибкой, и приложение упало целиком. Верните `onClick={handleAddClick}`.

## Объект события

React передаёт обработчику объект события. Добавьте параметр и выведите несколько полей:

```tsx shared/GameCard.tsx {1,4-10}
import { Fragment, useState, type MouseEvent } from 'react';
…
  // Щелчок по «В корзину»
  function handleAddClick(e: MouseEvent<HTMLButtonElement>) {
    console.log(
      e.type,
      e.constructor.name,
      e.currentTarget.tagName,
      e.nativeEvent.constructor.name,
    );
    setQuantity(quantity + 1);
  }
```

После щелчка в консоли: `click SyntheticBaseEvent BUTTON PointerEvent`. Это не событие браузера, а **синтетическое событие** (synthetic event) — обёртка React с привычным API: `type`, `target`, `currentTarget`, `preventDefault()`, `stopPropagation()`, координаты, клавиши. Настоящее событие браузера лежит в `e.nativeEvent`.

Тип `MouseEvent` здесь импортирован **из `react`**, а не взят из DOM: у синтетического события свой тип. В стрелке прямо в JSX тип выводится сам: `onClick={(e) => …}`. А параметр отдельной функции без типа — ошибка `Parameter 'e' implicitly has an 'any' type.`

Верните обработчик без параметра.

## Всплытие

События в React всплывают, как в DOM: от элемента, где произошли, вверх по родителям. Повесьте обработчик на всю карточку:

```tsx shared/GameCard.tsx
    <article
      className={styles.card}
      data-category={game.category}
      onClick={() => console.log('article', game.title)}
    >
```

Нажмите «В корзину» у «Острова»: счётчик вырос, а в консоли — `article Остров сокровищ`. Щелчок по кнопке сработал и дошёл до карточки. Щелчок по обложке тоже выводит эту строку, но счётчик не трогает.

Чтобы событие не пошло выше, его останавливают. Верните в `handleAddClick` параметр `e: MouseEvent<HTMLButtonElement>` и первой строкой вызовите `e.stopPropagation()`. Теперь щелчок по кнопке только меняет счётчик, а строку в консоли выводит лишь щелчок по обложке. Уберите эксперимент.

Так делают, когда вся карточка ведёт на страницу игры, а кнопка внутри неё должна только добавить в корзину.

## Действие браузера по умолчанию

У некоторых событий есть действие по умолчанию: ссылка уводит на другую страницу, отправка формы перезагружает страницу. Отменяет его `e.preventDefault()`. Проверим на форме подписки. Добавьте в `App.tsx` перед разделом «Хиты»:

```tsx App.tsx
<form
  onSubmit={(e) => {
    console.log('Подписка:', new FormData(e.currentTarget).get('email'));
  }}
>
  <input name="email" placeholder="Почта" />
  <button>Подписаться</button>
</form>
```

Положите что-нибудь в корзину, введите почту и нажмите «Подписаться». Счётчики под кнопками снова нули, консоль пуста, а в адресной строке превью — `/?email=…`. Браузер отправил форму и загрузил страницу заново: приложение запустилось с нуля, вместе с ним пропало состояние и очистилась консоль. Добавьте первой строкой обработчика `e.preventDefault();` и повторите: в консоли `Подписка: …`, корзина на месте. Уберите форму.

В React-приложении форму почти всегда обрабатывают сами, поэтому `preventDefault` в `onSubmit` встречается постоянно. В главе 12 появится другой способ — `<form action={…}>`, где React делает это за вас.

## Ограничение по остатку

Теперь — задача шага. Кнопку нужно выключать, когда в корзине уже столько штук, сколько на складе:

```tsx shared/GameCard.tsx {6}
      {game.inStock === 0 ? (
        <Button disabled>Нет в наличии</Button>
      ) : (
        <Button
          onClick={handleAddClick}
          disabled={quantity >= game.inStock}
        >
          В корзину
        </Button>
      )}
```

Выключенная кнопка не получает щелчков: браузер не создаёт для неё событие `click`.

::: task
В `GameCard.tsx` передайте кнопке «В корзину» `disabled={quantity >= game.inStock}`.
:::

## Что получилось

Нажмите «В корзину» у «Ночного экспресса» три раза: «В корзине: 3 шт.», кнопка стала серой и больше не нажимается. У остальных игр остаток больше, их можно добавлять дальше.

## Обработчики в props своих компонентов

`onClick` у `<Button>` — не событие React, а **проп нашего компонента**. React навешивает обработчики только на DOM-элементы: `<button onClick>` работает, потому что `Button` передал проп в `<button>`. Если бы `Button` забыл это сделать, щелчок ничего бы не делал — без ошибок.

Для своих компонентов имена событий придумываете вы: `onAdd`, `onRemove`, `onSelect`. Это обычные props-функции. В шаге «Подъём состояния» карточка получит такой проп — `onAdd`.

## Как в настоящем проекте

- Обработчики — место для побочных действий: изменить состояние, отправить запрос, записать в `localStorage`. Рендер должен оставаться чистым (глава 3), а обработчики — нет.
- Стрелку в JSX пишут, когда нужно передать аргумент: `onClick={() => onRemove(game.id)}`. Отдельную функцию `handleX` — когда в обработчике больше одной строки.
- `e.stopPropagation()` — редкость: обычно проще не вешать обработчик на родителя. `e.preventDefault()` — в каждом `onSubmit`.

::: deep Где на самом деле живут обработчики
React не вешает обработчик на каждую кнопку. Он слушает события один раз на корневом элементе (`#root`) и, когда событие всплывает туда, сам проходит по дереву файберов от цели вверх и вызывает ваши `onClick` по порядку. Это называется делегированием событий. Отсюда и синтетический объект: React создаёт его сам, когда обходит дерево. Обработчики `onClickCapture` вызываются на фазе погружения — сверху вниз, до обычных.
:::

::: tip
В Angular обработчик — выражение в шаблоне: `(click)="add()"`, Angular вызывает его сам. В React в `onClick` передают функцию, поэтому скобки — ошибка: `onClick={add()}` вызовет `add` при рендере. А `output()` из Angular в React — просто проп-функция `onAdd`.
:::
