Карточке нужна память, которая переживает рендер, и способ попросить React нарисовать её заново. Обе вещи даёт хук `useState`.

## Состояние компонента

```tsx shared/GameCard.tsx {1,7-8,12}
import { Fragment, useState } from 'react';
…

export function GameCard({ game }: GameCardProps) {
  …

  // Сколько штук этой игры в корзине — состояние карточки
  const [quantity, setQuantity] = useState(0);

  // Щелчок по «В корзину»
  function handleAddClick() {
    setQuantity(quantity + 1);
  }
```

`useState(0)` объявляет **состояние** компонента с начальным значением `0` и возвращает пару:

- `quantity` — значение состояния **в этом рендере**;
- `setQuantity` — **функция-сеттер**: она сохраняет новое значение и просит React перерисовать компонент.

Пару разбирают деструктуризацией массива, а имена выбираете вы. Принято `[что-то, setЧто-то]`: `[quantity, setQuantity]`, `[isOpen, setIsOpen]`.

Начальное значение React использует **только при первом рендере**. При следующих вызовах `GameCard` строка `useState(0)` вернёт уже сохранённое значение — 1, 2, 3. Где React его хранит? В файбере карточки — том самом объекте из шага «Под капотом» главы 3, который живёт между рендерами.

Что происходит при щелчке:

```
щелчок → setQuantity(0 + 1)
  React запоминает: у этой карточки теперь 1
  и ставит в план рендер карточки
рендер → GameCard() → useState(0) вернул 1
  → JSX с «В корзине: 1 шт.»
React меняет в DOM то, что изменилось
```

::: task
1. Импортируйте `useState` из `react`.
2. Замените `let quantity = 0` на `const [quantity, setQuantity] = useState(0)`.
3. В `handleAddClick` вместо `quantity += 1` вызовите `setQuantity(quantity + 1)`. Вывод в консоль уберите.
:::

## Что получилось

Нажмите «В корзину» — счётчик под кнопкой растёт: 1, 2, 3.

Посмотрим, кого React перерисовывает. Добавьте сразу после `useState` строку `console.log('render', game.title, quantity)` — выше `quantity` ещё не объявлена. При запуске в консоли 18 строк: девять карточек, и каждая дважды — строгий режим вызывает компонент два раза (глава 1). Нажмите «В корзину» у «Острова сокровищ» в «Хитах»:

```
render Остров сокровищ 1
render Остров сокровищ 1
```

Перерисовалась **одна карточка** — та, чьё состояние изменилось. `App` и остальные восемь карточек React не вызывал. Уберите `console.log`.

## У каждой карточки — своё состояние

Нажмите «В корзину» у «Острова сокровищ» в «Хитах» три раза и посмотрите на «Остров» в «Всех играх»: там «В корзине: 0 шт.». Игра одна, а компонентов на странице два — и состояний тоже два. Состояние принадлежит не данным, а **месту компонента в дереве**: у каждого `<GameCard>` свой файбер и своя память. Для корзины это неправильно, и в шаге «Подъём состояния» мы это исправим.

## Эксперименты

- **Локальная переменная рядом с состоянием.** Добавьте перед `handleAddClick` строку `let clicks = 0`, а в обработчик — `clicks += 1; console.log('clicks', clicks);`. Сколько ни нажимайте, в консоли `clicks 1`: каждый рендер создаёт переменную заново, а обработчик из нового рендера видит новую. Состояние же сохранилось. Уберите строки.
- **Присвоить состоянию.** Напишите в обработчике `quantity = quantity + 1`. Редактор не даст: `Cannot assign to 'quantity' because it is a constant.` `quantity` — константа этого рендера. Новое значение передают только через сеттер.
- **Не тот тип.** `setQuantity('1')` — ошибка: `Argument of type 'string' is not assignable to parameter of type 'SetStateAction<number>'.` Тип состояния TypeScript вывел из начального значения `0`.
- **Хук в обработчике.** Добавьте в начало `handleAddClick` строку `useState(0);` и нажмите кнопку. Редактор промолчит, а React бросит ошибку: `Invalid hook call. Hooks can only be called inside of the body of a function component.` Счётчик не изменился: обработчик прервался до `setQuantity`. Уберите строку.

## Правила хуков

`useState` — первый **хук** (hook) курса: функция React, которая «цепляется» за компонент. Её имя начинается с `use`. Правил два:

- вызывать хуки только **внутри компонента** (или своего хука — глава 7), а не в обработчиках, обычных функциях или вне компонентов;
- вызывать их **на верхнем уровне** тела компонента — не внутри `if`, циклов и колбэков.

React различает состояния компонента по **порядку вызовов** хуков: первый `useState` — первое состояние, второй — второе. Если порядок меняется от рендера к рендеру, React перепутает состояния. Подробно — в главе 7.

## Как в настоящем проекте

- Состояние — только то, что меняется и влияет на экран. Название игры или цену в состояние не кладут: они приходят в props.
- Если начальное значение не говорит о типе, тип указывают явно: `useState<Game | null>(null)`, `useState<string[]>([])`.
- Правила хуков проверяет линтер `eslint-plugin-react-hooks` (глава 7). В превью линтера нет — следить приходится самим.

::: tip
`useState` напоминает `signal()` в Angular: значение плюс способ его заменить. Но сигнал — объект, его читают вызовом `count()`, и он всегда отдаёт текущее значение. Состояние React — обычное число в переменной этого рендера, а новое значение появится только в следующем рендере. Это различие разберём в шаге «Состояние — снимок».
:::
