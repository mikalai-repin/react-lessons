У каждой карточки своя память, и это уже мешает. «Остров сокровищ» стоит и в «Хитах», и во «Всех играх»: нажмите «В корзину» в одном разделе — в другом так и останется 0. А шапка вообще не знает, что в корзине что-то есть. Нам нужно одно число на всю страницу, которое видят шапка и все карточки.

## Состояние — у общего родителя

Карточки не могут прочитать состояние друг друга, а шапка — состояние карточек: данные в React текут только сверху вниз (глава 3). Значит, общее состояние должно жить **выше** всех, кому оно нужно, — у их ближайшего общего родителя. Для шапки и карточек это `App`.

Перенос состояния вверх называется **подъёмом состояния** (lifting state up). Рецепт из трёх шагов:

1. убрать состояние из дочерних компонентов;
2. объявить его в общем родителе;
3. передать вниз значение (props) и функцию, которая его меняет (проп-обработчик).

```
App  [cartCount]  handleAdd
├─ Header  ◄── cartCount
├─ GameCard ── onAdd() ──► handleAdd
└─ GameCard ── onAdd() ──► handleAdd
```

Значение течёт вниз, событие — вверх: карточка не меняет состояние сама, она сообщает родителю «нажали „В корзину“», а родитель решает, что делать.

## Код

Начнём с `App`: в нём появляется состояние — сколько всего штук в корзине:

```tsx App.tsx {1,6-11,15,21}
import { useState } from 'react';
…

export function App() {
  const hits = games.filter(isHit);
  // Сколько всего штук в корзине — общее состояние страницы
  const [cartCount, setCartCount] = useState(0);

  function handleAdd() {
    setCartCount((c) => c + 1);
  }

  return (
    <>
      <Header count={games.length} cartCount={cartCount} />
      …
            {hits.map((game) => (
              <GameCard
                key={game.id}
                game={game}
                onAdd={handleAdd}
              />
            ))}
```

Во «Всех играх» — так же, `onAdd={handleAdd}`. Карточка теряет своё состояние и получает проп-обработчик:

```tsx shared/GameCard.tsx {3-4,8,15}
type GameCardProps = {
  game: Game;
  // Покупатель нажал «В корзину»
  onAdd: () => void;
};

// Карточка игры в каталоге
export function GameCard({ game, onAdd }: GameCardProps) {
  …
  return (
    …
      {game.inStock === 0 ? (
        <Button disabled>Нет в наличии</Button>
      ) : (
        <Button onClick={onAdd}>В корзину</Button>
      )}
    </article>
  );
}
```

Шапка получает число и показывает его справа (стиль `cart` уже в `Header.module.css`):

```tsx layout/Header.tsx {3,6-7,11}
type HeaderProps = {
  count: number;
  cartCount: number;
};

// Шапка магазина: логотип, подпись с числом игр и сводка корзины
export function Header({ count, cartCount }: HeaderProps) {
  return (
    <header className={styles.header}>
      …
      <p className={styles.cart}>Корзина: {cartCount}</p>
    </header>
  );
}
```

## Что получилось

Справа в шапке — «Корзина: 0». Нажмите «В корзину» у любых игр в любом разделе: число растёт на каждый щелчок. «Остров» в «Хитах» и «Остров» во «Всех играх» теперь меняют одно и то же состояние.

Теперь у числа «сколько в корзине» один **источник истины** (source of truth): состояние `App`. Шапка и карточки его не хранят, а получают — шапка значение, карточки возможность его изменить. Две копии одних данных рано или поздно расходятся, как это случилось с двумя «Островами», а у одного источника расходиться нечему.

Но мы кое-что потеряли: строку «В корзине: N шт.» под кнопкой и ограничение по остатку. Карточке нужно знать, сколько штук **этой** игры в корзине, а у `App` есть только общее число. Одного числа мало — нужны позиции корзины. Это следующий шаг.

## Эксперименты

- **Кто теперь перерисовывается.** Добавьте `console.log('render App')` в начало `App` и `console.log('render', game.title)` в начало `GameCard`. Нажмите «В корзину»: `render App` дважды и 18 строк карточек — все девять карточек, каждая дважды. Состояние поднялось в `App`, и при его изменении React вызывает `App` и всё, что он рисует. Почему это не страшно для DOM — в шаге «Под капотом». Уберите `console.log`.
- **Забыли передать обработчик.** Удалите `onAdd={handleAdd}` у карточек «Хитов». Редактор: `Property 'onAdd' is missing in type '{ key: number; game: Game; }' but required in type 'GameCardProps'.` Без TypeScript ошибки не было бы вовсе: кнопка с `onClick={undefined}` просто ничего не делает. Верните проп.

## Как в настоящем проекте

- Поднимают состояние **до ближайшего общего родителя**, а не «на всякий случай в корень». Чем выше состояние, тем больше компонентов перерисовывается при каждом изменении.
- Компонент, которым управляет родитель через props, называют **управляемым** (controlled): карточка теперь ничего не решает сама. Компонент со своим состоянием — **неуправляемый**. Подробнее об этом — в главе 5 на полях ввода.
- Когда пробрасывать значение и обработчик приходится через много уровней, на помощь приходит контекст (глава 8) и хранилища состояния (глава 9). Начинают всё равно с подъёма.

::: tip
В Angular для этого есть `output()` и `(add)="onAdd()"` в шаблоне родителя. В React событие своего компонента — обычный проп-функция: `onAdd={handleAdd}`. Никакого `EventEmitter` и подписок — карточка просто вызывает функцию, которую ей передали.
:::
