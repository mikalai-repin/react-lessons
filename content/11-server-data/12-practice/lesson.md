Каталог, страница игры и отзывы уже живут на сервере. Но главная всё ещё показывает «Хиты» из `data/games.ts` — шести локальных игр, — а «Избранное» в кабинете ищет игры там же. Отметьте сердечком «Северный путь» в каталоге и откройте кабинет: пусто, этой игры в локальном массиве нет. Доведите переезд до конца и удалите `data/games.ts`.

Что уже в проекте:

- `GamePage` за кадром перестал брать «Следующую игру» из локального массива: число игр он читает из той же записи кэша, что и шапка, — `useQuery(gamesQuery(''))`, — а id игр учебного сервера идут подряд от 1;
- `HIT_RATING` (4,6) теперь экспортирован из `shared/gameRules.ts` — с этого рейтинга игра считается хитом.

::: task
1. **«Хиты» с сервера.** На главной покажите 6 лучших игр с рейтингом от `HIT_RATING`: запрос `gamesQuery` с параметрами `rating`, `sort=rating` и `size=6`. Счётчик у заголовка — сколько хитов на сервере всего (`total`), пока грузятся — «Загружаем хиты…», при ошибке — «Не удалось загрузить хиты.». Ссылка «Весь каталог →» ведёт на каталог, отсортированный по рейтингу.
2. **«Избранное» с сервера.** На вкладке «Избранное» загрузите каждую отмеченную игру запросом `gameQuery(id)`. Пока хоть одна грузится — «Загружаем избранное…». Пустое избранное — прежний текст про сердечко.
3. **Без локального каталога.** Удалите `data/games.ts` — ни один файл больше не должен его импортировать.
:::

::: hint Подсказка 1: параметры хитов
Параметры — константа модуля, не вычисление в рендере: они не меняются. `new URLSearchParams({ rating: String(HIT_RATING), sort: 'rating', size: String(HITS_SHOWN) }).toString()` даст `rating=4.6&sort=rating&size=6` — это и параметры запроса, и часть ключа. Разметка — как у каталога в шаге «TanStack Query»: `isPending`, `isError`, иначе `GameGrid` с `hits.data.items`.
:::

::: hint Подсказка 2: много запросов сразу
Число отмеченных игр меняется, а хуки нельзя вызывать в цикле. Для переменного числа запросов есть [`useQueries`](https://tanstack.com/query/latest/docs/framework/react/reference/useQueries): `useQueries({ queries: [...] })` принимает массив опций и возвращает массив результатов — по одному на запрос, в том же порядке.
:::

::: hint Подсказка 3: из результатов — игры
`favorites.ids` — числа, а `gameQuery` ждёт строку (как `id` из адреса): `gameQuery(String(id))`. Игры — `results.flatMap((result) => (result.data ? [result.data] : []))`: только загруженные. «Загружаем…» — пока `results.some((result) => result.isPending)`. Все хуки — до ранних `return`.
:::

::: hint Подсказка 4: кэш общий
Запросы избранного — те же ключи, что у страницы игры: `['games', 'detail', '13']`. Игру, которую вы недавно открывали, вкладка «Избранное» покажет без запроса. Так кэш связывает страницы, которые друг о друге не знают.
:::

## Итоги главы

Магазин переехал на сервер: каталог, страница игры, отзывы, хиты и избранное приходят по сети, а корзина хранит снимки игр.

| Запись | Что делает |
|---|---|
| `apiGet`, `ApiError` | один клиент API: `fetch` + проверка `response.ok` + своя ошибка с кодом |
| `useEffect` + `AbortController` | загрузка руками: очистка отменяет устаревший запрос — без неё гонка |
| `<Suspense fallback>` + `use(promise)` | компонент ждёт данные, граница показывает заглушку; промис — созданный вне рендера |
| `ErrorBoundary` (`react-error-boundary`), `resetKeys` | ошибка рендера — запасная разметка блока, а не всей страницы |
| `QueryClient`, `QueryClientProvider`, `useQuery` | кэш серверного состояния: ключ, функция, статусы, дедупликация, повторы |
| `queryOptions`, фабрика ключей, `staleTime`, `keepPreviousData` | ключи в одном месте, свежесть, прежние данные на время загрузки |
| `queryClient.query`, `useSuspenseQuery`, `useQueryErrorResetBoundary` | `loader` наполняет кэш, страница читает его; повтор одного запроса |
| `useMutation`, `invalidateQueries` | изменение на сервере и сверка кэша |
| `onMutate` / `onError` / `onSettled`, `setQueryData` | оптимистичное обновление с откатом |
| `useInfiniteQuery`, `getNextPageParam` | порции с сервера одной записью кэша |
| `useQueries` | переменное число запросов |

Главная мысль главы: данные с сервера — это **кэш**, а не состояние компонента. У кэша есть ключи, свежесть, общие записи для разных экранов и правила, когда спросить сервер снова. Писать это руками в каждом эффекте — путь к гонкам; поэтому есть TanStack Query, `loader` роутера и Suspense.

Но в магазине ещё остались шероховатости, которые видны на медленной сети. Поиск по буквам перерисовывает тяжёлый каталог на каждом нажатии. Отзыв с оптимистичным обновлением требует трёх колбэков. Переходы между страницами то держат старый экран, то показывают заглушку — и мы пока не управляем этим сами. В главе 12 — **конкурентный React**: переходы (`useTransition`), отложенные значения, Actions с `useActionState` и `useOptimistic`, — то, как React 19 сам помогает с асинхронным интерфейсом.
