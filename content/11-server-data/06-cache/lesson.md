Query уже работает, но осталось три шероховатости:

1. Ключи написаны руками в двух местах: `['games', apiParams]` в каталоге и `['games', '']` в шапке. Опечатка в одном — и это уже две разные записи кэша и два запроса. А ключей скоро станет больше: игра, отзывы.
2. Каждый новый показ каталога — фоновый запрос, даже если ответ пришёл две секунды назад.
3. При смене фильтра каталог пропадает и показывает «Загружаем каталог…» — в эффекте прежний список хотя бы оставался на месте.

## queryOptions: ключ и функция вместе

Ключ и функция запроса неразделимы: ключ описывает, **что** вернёт функция. Соберём их в одном месте — в `api/games.ts`, рядом с адресами:

```tsx api/games.ts
// Ключи — от общего к частному: ['games'] накрывает все запросы игр,
// ['games', 'list'] — все списки, ['games', 'list', '…'] — один список
export const gameKeys = {
  all: ['games'] as const,
  lists: () => [...gameKeys.all, 'list'] as const,
  list: (params: string) =>
    [...gameKeys.lists(), params] as const,
};

/** Запрос списка игр: ключ и функция вместе, в одном месте */
export function gamesQuery(params: string) {
  return queryOptions({
    queryKey: gameKeys.list(params),
    queryFn: ({ signal }) => fetchGames(params, signal),
  });
}
```

- **Фабрика ключей** `gameKeys` строит ключи **иерархией**: каждый следующий начинается с предыдущего. Это пригодится, когда понадобится сказать «все списки игр устарели» — Query умеет находить записи по началу ключа (шаг «Изменения на сервере»).
- **[`queryOptions`](https://tanstack.com/query/latest/docs/framework/react/reference/queryOptions)** ничего не делает во время выполнения — возвращает тот же объект. Зато TypeScript **запоминает в ключе тип данных**: позже по одному ключу можно будет прочитать или записать кэш, и тип `Page<Game>` придёт вместе с ним.

Теперь шапка — одна строка, и ключ у неё гарантированно тот же, что у каталога без фильтров:

```tsx layout/Header.tsx
  const catalog = useQuery(gamesQuery(''));
```

## staleTime: сколько данные свежие

Запись кэша бывает **свежей** (fresh) или **устаревшей** (stale). Свежие данные Query отдаёт без запроса. Устаревшие — тоже отдаёт сразу, но при новом показе (и при возврате во вкладку браузера) тихо спрашивает сервер. Сколько данные остаются свежими, задаёт `staleTime`; по умолчанию — 0, то есть устаревают сразу.

Для каталога магазина полминуты свежести — разумно: цены и остатки не меняются каждую секунду. Зададим это всем запросам в клиенте:

```tsx api/queryClient.ts
// Сколько данные считаются свежими, мс: свежие берутся из кэша
// без запроса. По умолчанию 0 — запрос при каждом новом показе
const STALE_TIME = 30_000;

// Клиент TanStack Query — один на приложение: в нём живёт кэш
// всех запросов. Отдельный модуль: клиент понадобится и вне React
export const queryClient = new QueryClient({
  defaultOptions: { queries: { staleTime: STALE_TIME } },
});
```

Не путайте со вторым временем — `gcTime` (5 минут по умолчанию). `staleTime` — когда спросить сервер снова; `gcTime` — когда **выбросить** запись, которую больше не показывает ни один компонент. Пока запись в кэше, её можно показать мгновенно — даже устаревшую.

## Пока грузится новый ключ

Смена фильтра — новый ключ без данных. Чтобы прежний список оставался на экране, у `useQuery` есть **`placeholderData`** — что показать вместо `data`, пока у ключа нет своих данных. Готовая функция `keepPreviousData` подставляет данные прошлого ключа:

```tsx catalog/CatalogPage.tsx
  // Запрос каталога: ключ — что загружаем, queryFn — как.
  // Пока новый список грузится, показываем прежний
  const catalog = useQuery({
    ...gamesQuery(apiParams),
    placeholderData: keepPreviousData,
  });
```

Теперь `isPending` при смене фильтра — `false`: данные есть, хоть и чужие. Отличить их помогает флаг `isPlaceholderData`. Сделаем прежний список бледным — стиль `.results[aria-busy='true']` уже в `CatalogPage.module.css`:

```tsx catalog/CatalogPage.tsx
        // Прежний список — бледнее: новый ещё в пути
        <div
          className={styles.results}
          aria-busy={catalog.isPlaceholderData}
        >
          <GameGrid games={catalog.data.items} />
        </div>
```

::: task
1. В `api/games.ts` создайте фабрику `gameKeys` (`all`, `lists`, `list`) и функцию `gamesQuery(params)` через `queryOptions`.
2. Используйте `gamesQuery` в `CatalogPage` и в `Header` вместо ручных ключей.
3. В `api/queryClient.ts` задайте всем запросам `staleTime: 30_000` через `defaultOptions` (число — в константу).
4. В `CatalogPage` добавьте `placeholderData: keepPreviousData` и оберните сетку в `<div className={styles.results} aria-busy={catalog.isPlaceholderData}>`.
:::

## Что получилось

У шага задержка 600 мс — чтобы было видно, что происходит. Выберите «Детские»: прежний список бледнеет и остаётся на месте, через полсекунды его сменяют детские игры. Верните «Все» — список сразу, и во «Сети» **ни одного** запроса: данные моложе 30 секунд. Откройте игру и вернитесь — то же самое.

## Эксперименты

1. **Ключ без параметров.** В `gamesQuery` замените ключ на `gameKeys.lists()` — без `params`. Выберите «Детские»: адрес поменялся на `?category=kids`, а список — нет, и во «Сети» тишина. Для Query это тот же ключ, а у него уже есть свежие данные. Самая частая ошибка с Query: функция зависит от значения, которого нет в ключе. Верните `gameKeys.list(params)`.
2. **Свежесть.** Поставьте `STALE_TIME = 0` и повторите «Детские» → «Все»: «Все» появляется сразу (из кэша), но во «Сети» — фоновый запрос. Верните 30 000.
3. **Без `keepPreviousData`.** Уберите `placeholderData` — при смене фильтра снова «Загружаем каталог…» на полсекунды. Верните.

## Как в настоящем проекте

- Фабрики ключей и `queryOptions` в одном модуле на сущность (`api/games.ts`, `api/orders.ts`) — общепринятая схема: компоненты не знают ни адресов, ни ключей.
- `staleTime` подбирают под данные: справочники, которые не меняются, — `Infinity` или `'static'`; каталог — десятки секунд или минуты; остаток на складе в корзине — 0. Значение по умолчанию задают в клиенте, особые — у конкретного запроса.
- Ключ должен содержать **всё**, от чего зависит ответ: фильтры, номер страницы, язык, id пользователя. Есть официальный плагин ESLint для Query с правилом `exhaustive-deps` для ключей — он ловит эксперимент 1.

::: legacy keepPreviousData: true
В React Query 4 и раньше был флаг `keepPreviousData: true` прямо у запроса. В v5 его заменили общим механизмом `placeholderData`, а прежнее поведение — функция `keepPreviousData` из пакета.
:::
