Каталог — главный экран магазина, и он всё ещё фильтрует локальный массив. Переведём его на сервер. Фильтры уже живут в адресе (глава 10), сервер умеет фильтровать и сортировать сам — осталось при каждой смене фильтров запросить `GET /api/games?…` и показать ответ.

Сделаем это так, как это десять лет делали в React-проектах: `useState` для ответа и `useEffect` с `fetch`. А потом найдём в этом коде гонку.

## Параметры для сервера

Имена фильтров в адресе магазина и в API сервера разные: у нас `sort=cheap` и `inStock=1`, у сервера `sort=price` и `inStock=true`. Перевод уже лежит в `catalog/filters.ts` — функция `filtersToApi(filters)` возвращает `URLSearchParams` для сервера. А в `api/games.ts` появилась `fetchGames(params, signal)` — `GET /api/games?<params>`, ответ — страница `Page<Game>` (`items`, `total`, `page`, `size`).

Строку параметров удобно получить прямо при рендере — это вычисление, а не состояние:

```tsx catalog/CatalogPage.tsx
  // Параметры запроса — строкой: её удобно сравнивать в зависимостях
  const apiParams = filtersToApi({
    ...filters,
    query,
  }).toString();
```

Строка, а не объект: эффект сравнивает зависимости через `Object.is`, и новый объект `URLSearchParams` на каждом рендере перезапускал бы запрос.

## Эффект загрузки

С чем синхронизируем эффект? С сервером: «на экране — ответ для текущих параметров».

```tsx catalog/CatalogPage.tsx
  // Последний ответ сервера; null — ответа ещё не было
  const [catalog, setCatalog] = useState<Page<Game> | null>(
    null,
  );
  const [failed, setFailed] = useState(false);

  // Синхронизация с сервером: новые параметры — новый запрос
  useEffect(() => {
    const controller = new AbortController();
    fetchGames(apiParams, controller.signal)
      .then((page) => {
        setCatalog(page);
        setFailed(false);
      })
      .catch(() => {
        // Отменили сами — это не ошибка сервера
        if (!controller.signal.aborted) setFailed(true);
      });
    // Параметры сменились или страница закрыта: ответ уже не нужен
    return () => controller.abort();
  }, [apiParams]);
```

Главное здесь — **очистка**. Каждый запуск эффекта создаёт свой `AbortController`. Сменились параметры — React сначала вызовет очистку прошлого запуска: `abort()` отменит старый запрос, и его `.then` уже не выполнится. Отменённый `fetch` отклоняется с ошибкой `AbortError` — это не сбой сервера, поэтому в `.catch` проверяем `signal.aborted`.

В разметке — три состояния вместо прежнего списка:

```tsx catalog/CatalogPage.tsx
      {failed ? (
        <p className="muted">Не удалось загрузить каталог.</p>
      ) : catalog === null ? (
        <p className="muted">Загружаем каталог…</p>
      ) : catalog.items.length === 0 ? (
```

Счётчик в заголовке — `catalog.total`: сколько игр подошло всего. А карточек — первая страница сервера, 12 штук. Порции «Показать ещё» пока уходят: `limit`, `PAGE_SIZE` и `LoadMore` из `CatalogPage` удалите, как и `filterGames` из `filters.ts` — фильтрует теперь сервер. Догрузку порциями с сервера вернём в шаге «Бесконечный список».

1. В `CatalogPage` вычислите `apiParams` и замените локальную фильтрацию состоянием `catalog` и `failed` с эффектом загрузки (с `AbortController` и очисткой).
2. Нарисуйте три состояния: ошибка, «Загружаем каталог…», пусто — как раньше, иначе `<GameGrid games={catalog.items} />`; счётчик — `catalog.total`.
3. Удалите `limit`, `PAGE_SIZE`, `LoadMore` из `CatalogPage` и функцию `filterGames` (с `COMPARE`) из `filters.ts`.

## Что получилось

Каталог показывает «Все игры 40» и 12 карточек. Во «Сети» при запуске — **два** запроса `GET /api/games`: первый «отменён», второй — 200. Это StrictMode: в разработке он монтирует компонент, размонтирует и монтирует снова (глава 6). Очистка отменила первый запрос — так StrictMode и проверяет, что она есть.

Смените категорию — новый запрос с `category=…`, а пока он идёт, на экране прежний список.

## Гонка

У этого шага сервер отвечает на `category=family` **медленно** — 1,8 с вместо 0,3. Так бывает и в жизни: у разных запросов разная цена.

Выберите «Семейные» и, не дожидаясь ответа, сразу «Детские». Через секунду — детские игры, а во «Сети» запрос семейных — «отменён». Всё верно.

Теперь уберите из эффекта строку `return () => controller.abort();` и повторите. Сначала появятся детские игры, а ещё через секунду их **заменят семейные** — хотя в списке выбраны «Детские» и адрес `?category=kids`. Во «Сети» оба запроса — 200: ответ на старый вопрос пришёл последним и победил. Это и есть **гонка** (race condition): несколько запросов в полёте, и на экране — не последний заданный, а последний пришедший. Верните очистку.

Вместо `abort()` можно завести флаг `let ignore = false`, в очистке ставить `true`, а в `.then` проверять его. Так гонку чинит документация React. `abort()` лучше: ненужный запрос ещё и прекращается.

## Чего этот код не умеет

Гонку мы закрыли, но посмотрите, сколько осталось:

1. **Нет кэша.** Откройте любую игру и нажмите «← Назад». Снова «Загружаем каталог…» и новый запрос — хотя секунду назад список был на экране. Ответ жил в состоянии компонента и умер вместе с ним.
2. **Нет общего доступа.** Шапке тоже нужно число игр — ей придётся делать свой запрос с тем же адресом.
3. **Нет повторов.** Сервер ответил 500 один раз — покупатель видит «Не удалось загрузить», хотя повтор через секунду, скорее всего, удался бы.
4. **Нет обновления.** Остатки на складе меняются, а список висит таким, каким пришёл.
5. **Всё вручную.** Три состояния, контроллер, проверка `aborted` — и так в каждом компоненте с данными.
6. **Водопады.** Эффект запускается после отрисовки: сначала рисуем пустое, потом спрашиваем. Вложенный компонент со своим эффектом спросит сервер только после ответа родителю.

Дальше в главе мы решим всё это по очереди: Suspense и границы ошибок — как React ждёт данные и показывает сбои, затем TanStack Query — кэш, который знает ответы на пункты 1–5.

## Как в настоящем проекте

- Загрузка данных в `useEffect` — самый частый код в старых проектах и самый частый источник гонок. Документация React прямо советует брать для данных фреймворк или библиотеку с кэшем.
- Если эффект всё же нужен (свой источник данных, нет библиотеки), обязательны очистка с `abort()` или флагом и обработка трёх состояний.

::: legacy Без отмены
В старом коде часто встречается эффект без очистки — с той самой гонкой — и с `async`-функцией внутри эффекта: `useEffect(() => { (async () => { … })(); }, [id])`. Сама функция эффекта не может быть `async`: она вернула бы промис, а React ждёт от неё функцию очистки или ничего.
:::
