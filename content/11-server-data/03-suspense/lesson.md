На странице игры не хватает отзывов — сервер отдаёт их по `GET /api/games/:id/reviews`. Отзывы — второстепенная часть страницы, и в этом шаге сервер отвечает на них медленно: 1,8 с для «Острова сокровищ». Как их загрузить?

- **Дождаться в `loader`.** Тогда переход на игру будет ждать самый медленный запрос: покупатель смотрит на старую страницу почти две секунды, хотя сама игра пришла за 0,3.
- **Эффект в компоненте отзывов** — как в прошлом шаге. Ручные состояния, а запрос стартует только после отрисовки страницы — то есть после ответа на игру. Две задержки подряд.
- **Начать запрос в `loader`, но не ждать.** Отдать странице **промис** — обещание данных, — а React пусть сам подождёт его там, где данные нужны, и покажет заглушку.

Третий способ и есть Suspense.

## Промис из loader

Загрузчик может вернуть объект, в котором часть полей — ещё не выполненные промисы. Роутер ждёт сам загрузчик, но не промисы внутри результата:

```tsx game/GamePage.tsx
export async function gameLoader({
  params,
  request,
}: LoaderFunctionArgs) {
  // Отзывы не ждём: запрос уходит сейчас, а промис — странице
  const reviews = fetchReviews(params.id!, request.signal);
  const game = await fetchGame(params.id!, request.signal);
  return { game, reviews };
}
```

Порядок строк важен: запрос отзывов уходит **до** `await` — оба запроса летят одновременно. Тип результата — `{ game: Game; reviews: Promise<Review[]> }`, и `useLoaderData<typeof gameLoader>()` его знает. (`fetchReviews` и модель `Review` уже в проекте.)

Данные загрузчика изменили форму, поэтому крошке в `routes.tsx` теперь нужна `data?.game.title`:

```tsx routes.tsx
              crumb: (data: { game: Game } | undefined) =>
                data?.game.title ?? 'Игра не найдена',
```

## use и Suspense

Компонент `Reviews` получает промис и читает его хуком [`use`](https://react.dev/reference/react/use):

```tsx game/Reviews.tsx
// Отзывы об игре. use ждёт промис: пока он не выполнен,
// компонент «приостановлен», и ближайший Suspense показывает заглушку
export function Reviews({ reviews }: ReviewsProps) {
  const list = use(reviews);
  if (list.length === 0) {
    return <p className="muted">Отзывов пока нет.</p>;
  }
```

`use(promise)` возвращает значение выполненного промиса. Если промис ещё в пути, React **приостанавливает** (suspend) компонент: прерывает его рендер, а вместо ближайшей обёртки [`<Suspense>`](https://react.dev/reference/react/Suspense) показывает её `fallback`. Когда промис выполнится, React отрендерит компонент заново — и `use` вернёт данные. В коде компонента нет ни состояния «загружается», ни эффекта: к строке после `use` данные уже есть.

Обёртку ставит страница — она решает, **какую часть** заменить заглушкой, пока данных нет:

```tsx game/GamePage.tsx
      <Section title="Отзывы">
        {/* Пока Reviews ждёт промис — заглушка вместо него */}
        <Suspense fallback={<ReviewsSkeleton />}>
          <Reviews reviews={reviews} />
        </Suspense>
      </Section>
```

Граница `<Suspense>` прячет **всё** своё содержимое, пока хоть один компонент внутри приостановлен. Поэтому её ставят вокруг блока, который осмысленно показать или скрыть целиком. `ReviewsSkeleton` (уже в `Reviews.tsx`) — «скелет»: серые полосы на месте отзывов, чтобы страница не прыгала, когда они придут.

`use` — необычный хук: его можно вызывать в условиях и циклах (как и `use(Context)` в главе 8). А вот промис он ждёт **кэшированный** — созданный вне рендера. Почему — в экспериментах.

::: task
1. В `gameLoader` запустите `fetchReviews` до `await fetchGame(…)` и верните `{ game, reviews }`.
2. В `GamePage` возьмите `{ game, reviews }` из `useLoaderData` и под `GameDetails` нарисуйте `<Section title="Отзывы">` с `<Suspense fallback={<ReviewsSkeleton />}>` вокруг `<Reviews reviews={reviews} />`. Обёртку из двух элементов сделайте фрагментом `<>…</>`.
3. В `game/Reviews.tsx` напишите `Reviews`: `use(reviews)`, «Отзывов пока нет.» для пустого списка, иначе `<ul className={styles.list}>` с автором (`styles.author`), датой (`formatDate` из `shared/format.ts`), `Rating size="sm"` и текстом.
4. В `routes.tsx` поправьте `crumb` игры под новую форму данных.
:::

## Что получилось

Превью открывается на «Острове сокровищ». Игра появляется сразу, а на месте отзывов — две мерцающие полосы. Через полторы секунды их сменяют отзывы Ани и Игоря. Во «Сети» запросы игры и отзывов начались одновременно, отзывы шли дольше.

Перейдите на «Драконью почту» («Следующая игра →») — у неё отзывов нет: «Отзывов пока нет.».

## Эксперименты

1. **Без `Suspense`.** Уберите обёртку `<Suspense>` (оставьте `<Reviews reviews={reviews} />`) и нажмите ⟳. Почти две секунды на экране только «Загружаем…» — `HydrateFallback` вместо всего магазина: приостановленный компонент ищет ближайшую границу вверх по дереву, и ею оказался корень. Теперь откройте каталог и щёлкните «Остров сокровищ»: адрес уже `/games/1`, а на экране ещё каталог — и так до прихода отзывов. Роутер обновляет страницу как **переход** (transition): React не прячет то, что уже показано, а держит старый экран, пока новый не готов. Подробно о переходах — в главе 12. Верните `Suspense`.
2. **Водопад.** Поставьте задержку 1000 мс и откройте `/games/2` — «Драконья почта» отвечает без добавки: «Отзывов пока нет.» видно примерно через секунду. Поменяйте местами две строки загрузчика — сначала `await fetchGame(…)`, потом `fetchReviews(…)` — и нажмите ⟳: теперь через две секунды. Запрос отзывов стартует только после ответа на игру. Верните порядок и задержку 300.
3. **Промис в рендере.** Пусть `Reviews` сам создаёт промис: проп `gameId: string` вместо `reviews`, внутри — `use(fetchReviews(gameId))`, а `GamePage` передаёт `gameId={String(game.id)}`. Откройте «Сеть»: запросы отзывов идут один за другим без конца, а на странице вечный скелет. Каждый раз, когда промис выполняется, React рендерит `Reviews` заново — и рендер создаёт **новый** промис, который снова в пути. Консоль при этом молчит. Промис для `use` создают вне рендера — в загрузчике, в обработчике события или в библиотеке с кэшем (TanStack Query — дальше в главе). Верните как было.

## Как в настоящем проекте

- «Важное — ждём, второстепенное — потом» — обычная схема страницы: `loader` ждёт главные данные, а медленные отдаёт промисами в `<Suspense>`. В React Router вместо `use` встречается компонент `<Await resolve={promise}>` — он делает то же самое; `use` появился только в React 19, и в коде под React 18 будет `<Await>`.
- Границы `<Suspense>` расставляют по смыслу: одна на всю страницу — одна большая заглушка; по одной на блок — блоки появляются по мере готовности.
- Сам по себе `use(promise)` не загружает и не кэширует — он только ждёт. Кэш и повторные запросы — дело загрузчика или библиотеки.
