У этого шага сервер «сломал» один адрес: отзывы «Драконьей почты» всегда отвечают ошибкой 500. Превью открыто на этой игре — и вместо страницы видно «Что-то пошло не так. Сервер ответил ошибкой 500.». Сама игра пришла без ошибки, сломались только отзывы, а покупатель не видит ни цены, ни кнопки «В корзину».

Что произошло? Промис отзывов **отклонён**. `use` в `Reviews` в этом случае не возвращает значение, а **бросает** ошибку — прямо во время рендера. Ошибка рендера летит вверх по дереву до ближайшей **границы ошибок** (error boundary). Своей границы у отзывов нет, и ближайшей оказалась граница маршрута (`ErrorBoundary: RouteError` в `routes.tsx`, глава 10) — она и заменила всю страницу. Нужна граница поменьше — вокруг одних отзывов.

## Граница — только класс

Граница ошибок — единственное место в современном React, где нужен **классовый компонент**. Хука «поймать ошибку рендера потомков» нет. Граница — это класс с одним или двумя особыми методами:

```tsx
type BoundaryProps = { fallback: ReactNode; children: ReactNode };
type BoundaryState = { failed: boolean };

// Граница ошибок — только класс: у функций нет нужных методов
class OwnBoundary extends Component<BoundaryProps, BoundaryState> {
  state: BoundaryState = { failed: false };

  // Ошибка в рендере потомка → следующий рендер — с запасной разметкой
  static getDerivedStateFromError(): BoundaryState {
    return { failed: true };
  }

  // После фиксации: место для отправки ошибки в мониторинг
  componentDidCatch(error: unknown, info: ErrorInfo) {
    console.log('Поймана ошибка:', String(error), info.componentStack?.length);
  }

  render() {
    return this.state.failed ? this.props.fallback : this.props.children;
  }
}
```

- `static getDerivedStateFromError` — React вызывает его, когда потомок бросил ошибку при рендере, и берёт возвращённое как новое состояние границы. Рендер границы с `failed: true` показывает запасную разметку вместо потомков.
- `componentDidCatch` — вызывается после фиксации: сюда пишут отправку ошибки в мониторинг.

Писать такой класс в каждом проекте не нужно: его давно оформили в библиотеку [`react-error-boundary`](https://github.com/bvaughn/react-error-boundary) — тот же класс плюс то, что понадобится сразу: повтор, сброс при смене данных, хук для ошибок из обработчиков.

## react-error-boundary

```tsx game/GamePage.tsx
        {/* Отзывы не загрузились — ошибка остаётся в этом блоке,
            а не роняет страницу. Новый промис — сбросить ошибку */}
        <ErrorBoundary
          resetKeys={[reviews]}
          fallbackRender={() => (
            <p className="muted">
              Не удалось загрузить отзывы.{' '}
              <Button
                onClick={() => revalidator.revalidate()}
                disabled={revalidator.state === 'loading'}
              >
                Повторить
              </Button>
            </p>
          )}
        >
          {/* Пока Reviews ждёт промис — заглушка вместо него */}
          <Suspense fallback={<ReviewsSkeleton />}>
            <Reviews reviews={reviews} />
          </Suspense>
        </ErrorBoundary>
```

- Запасную разметку библиотека принимает тремя способами: `fallback` — готовый элемент, `fallbackRender` — функция, `FallbackComponent` — компонент. Функция и компонент получают `{ error, resetErrorBoundary }`; `error` у шестой версии — `unknown`, как и в `useRouteError`.
- **Порядок обёрток.** `ErrorBoundary` снаружи, `Suspense` внутри: пока промис в пути — скелет, отклонён — сообщение. Обе границы закрывают один и тот же блок.
- **Повтор.** Промис отзывов создал загрузчик — получить новый можно, только вызвав загрузчик снова. Это и делает `revalidator.revalidate()` (как «Попробовать снова» в `RouteError`). Новый вызов — новый объект промиса в данных страницы.
- **`resetKeys`** — массив значений: если хоть одно изменилось (сравнение `Object.is`), граница сбрасывает ошибку и снова рисует потомков. Ключ — сам промис `reviews`: новый промис после повтора или после перехода на другую игру — новая попытка.

`useRevalidator()` — в начале `GamePage`, рядом с `useLoaderData`.

## Необработанный промис

Остался один нюанс. Промис отзывов может отклониться **раньше**, чем его прочитает `use`: здесь отзывы и игра отвечают одновременно, и React ещё не успел отрендерить `Reviews`. Отклонённый промис, на который никто не подписан, браузер считает **необработанной ошибкой** (unhandled rejection) — и в консоли появится вторая, лишняя ошибка. Пометим промис обработанным пустым `catch` в загрузчике:

```tsx game/GamePage.tsx
  // Отзывы могут отклониться раньше, чем их прочитает use, — такую
  // ошибку браузер сочтёт необработанной. Покажет её граница в
  // странице, а пустой catch помечает промис «обработанным»
  reviews.catch(() => {});
```

`catch` создаёт **новый** промис, а странице мы отдаём прежний — `use` по-прежнему получит ошибку и передаст её границе.

::: task
1. В `GamePage` оберните `Suspense` с отзывами в `ErrorBoundary` из `react-error-boundary` с `resetKeys={[reviews]}` и `fallbackRender`: «Не удалось загрузить отзывы.» и кнопка «Повторить» (`Button`), которая вызывает `revalidator.revalidate()` и выключена, пока `revalidator.state === 'loading'`.
2. В `gameLoader` после запуска `fetchReviews` добавьте `reviews.catch(() => {})`.
:::

## Что получилось

На `/games/2` — игра целиком, а в блоке «Отзывы» — «Не удалось загрузить отзывы. Повторить». Шапка, цена, «В корзину» — на месте. В консоли одно сообщение:

```
Error: Сервер недоступен (ошибка этого адреса включена в настройках шага)
    at apiGet (api/client.ts:23:11)

The above error occurred in the <Reviews> component.

React will try to recreate this component tree from scratch using the error boundary you provided, C.
```

React пишет о каждой пойманной ошибке: в какой компонент она прилетела и какая граница её поймала. `C` — так класс `ErrorBoundary` называется в собранном коде библиотеки.

Нажмите «Повторить» — во «Сети» снова `GET /api/games/2` и `/reviews` (снова 500: у этого шага адрес сломан навсегда). Загрузчик перезапустился целиком, хотя нужны были одни отзывы. Повторить **один** запрос без всей страницы мы научимся с TanStack Query.

Нажмите «Следующая игра →» — «Ночной экспресс» с тремя отзывами: новый промис, `resetKeys` сбросил ошибку.

## Эксперименты

1. **Без `resetKeys`.** Уберите `resetKeys={[reviews]}`, вернитесь на `/games/2` и нажмите «Следующая игра →». У «Ночного экспресса» отзывы в порядке, а на экране — «Не удалось загрузить отзывы.». `GamePage` не пересоздаётся при смене `:id` (тот же маршрут — тот же компонент), граница внутри него тоже, и её состояние `failed` пережило переход. Верните.
2. **Без `catch`.** Уберите `reviews.catch(() => {})` и нажмите ⟳. В консоли теперь две ошибки: к сообщению React добавилась та же `Error: Сервер недоступен …` — необработанное отклонение промиса. Верните.
3. **Своя граница.** Вставьте класс `OwnBoundary` из начала шага в конец `GamePage.tsx` (импорты: `Component` из `react`, типы `ErrorInfo` и `ReactNode`) и замените `<ErrorBoundary …>` на `<OwnBoundary fallback={<p className="muted">Не удалось загрузить отзывы.</p>}>`. Сообщение в блоке то же, в консоли React называет границу `OwnBoundary`, а следом — ваше «Поймана ошибка: Error: Сервер недоступен …» из `componentDidCatch`. Повтора и сброса у неё нет: их пришлось бы писать самим. Верните библиотеку.

## Что граница не ловит

Граница ловит ошибки **рендера** потомков (а значит, и отклонённые промисы в `use`). Не ловит:

- ошибки в обработчиках событий — `onClick` выполняется не во время рендера;
- асинхронный код — `setTimeout`, `.then` после рендера;
- ошибки в самой границе.

Для первых двух у библиотеки есть хук `useErrorBoundary()`: `showBoundary(error)` передаёт ошибку ближайшей границе вручную.

## Как в настоящем проекте

- Границы ставят на нескольких уровнях: корневая (всё приложение — «что-то сломалось, перезагрузите»), у маршрутов (страница) и вокруг независимых блоков (отзывы, рекомендации, виджеты). Ошибка блока не должна ронять страницу.
- В `onError` границы или в `onCaughtError` у `createRoot` ошибки отправляют в мониторинг.
- Граница — по-прежнему класс; хука вместо неё в React 19 нет. Других причин писать классовые компоненты нет.
