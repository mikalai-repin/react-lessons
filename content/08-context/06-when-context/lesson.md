Теперь мы знаем цену контекста: все потребители рендерятся при каждом новом значении, а значение сравнивается по ссылке. Из этого и следует, для чего контекст подходит лучше всего.

## Для чего контекст

| Данные | Контекст? | Почему |
|---|---|---|
| тема, язык, валюта | да | нужны везде, меняются редко |
| текущий пользователь | да | нужен многим, меняется при входе и выходе |
| настройки, флаги функций | да | читают многие, почти не меняются |
| корзина | да, с оговорками | меняется по действиям покупателя; потребителей десяток — шаг «Цена контекста» |
| текст поиска, позиция курсора, таймер | нет | меняются много раз в секунду — каждый раз рендерятся все потребители |
| данные с сервера | нет | для них есть кэш запросов (глава 11) |
| состояние одного компонента или пары соседей | нет | хватает состояния и props |

Контекст — это **доставка** значения вглубь дерева, а не хранилище. Хранит состояние по-прежнему `useState` или `useReducer` в провайдере. Если значение часто меняется и нужно многим компонентам, но каждому — своя часть, удобнее внешнее хранилище с селекторами (глава 9).

Идеальный пример — **тема оформления**: её читают многие, меняет покупатель раз в жизни. Сделаем магазину тёмную тему.

## Что уже в проекте

- В `styles.css` цвета магазина — переменные CSS (`--text`, `--bg`, `--surface`, `--border`…), а блок `:root[data-theme='dark']` задаёт им тёмные значения. Компонентам ничего не нужно знать про тему: достаточно поставить атрибут `data-theme="dark"` на `<html>`. Цвета в CSS-модулях переведены на те же переменные.
- В `Header.module.css` — класс `.theme` для кнопки-переключателя.
- Заготовки `theme/ThemeContext.ts` и `theme/ThemeProvider.tsx`.

## Контекст темы

По образцу корзины — тип, контекст и хук:

```tsx theme/ThemeContext.ts
import { createContext, use } from 'react';

export type Theme = 'light' | 'dark';

/** Тема оформления и её переключатель */
export type ThemeContextValue = {
  theme: Theme;
  toggleTheme: () => void;
};

// Тема для всего приложения; null — компонент вне провайдера
export const ThemeContext =
  createContext<ThemeContextValue | null>(null);

// Тема из ближайшего провайдера выше по дереву
export function useTheme() {
  const value = use(ThemeContext);
  if (value === null) {
    throw new Error('useTheme: выше по дереву нет провайдера темы');
  }
  return value;
}
```

## Провайдер темы

```tsx theme/ThemeProvider.tsx
import { useEffect } from 'react';
import type { ReactNode } from 'react';
import { useLocalStorage } from '../hooks/useLocalStorage';
import { ThemeContext } from './ThemeContext';
import type { Theme, ThemeContextValue } from './ThemeContext';

type ThemeProviderProps = {
  children: ReactNode;
};

// Тема оформления: выбор покупателя переживает перезапуск
export function ThemeProvider({ children }: ThemeProviderProps) {
  const [theme, setTheme] = useLocalStorage<Theme>(
    'theme',
    'light',
  );

  // Синхронизация с <html>: его рисует не React, а страница.
  // По атрибуту data-theme styles.css выбирает цвета
  useEffect(() => {
    document.documentElement.dataset.theme = theme;
  }, [theme]);

  const value: ThemeContextValue = {
    theme,
    toggleTheme: () =>
      setTheme(theme === 'light' ? 'dark' : 'light'),
  };

  return <ThemeContext value={value}>{children}</ThemeContext>;
}
```

- Выбор хранится в `useLocalStorage` из главы 7. Хук делит код, а не состояние — но здесь он вызван **один раз**, в провайдере, и контекст раздаёт это одно значение всем. «Хук + провайдер» — обычный способ сделать состояние хука общим.
- Эффект синхронизирует тему с внешней системой — атрибутом `<html>`, который React не рисует (глава 6: «с чем синхронизируем?»).
- Значение — новый объект при каждом рендере провайдера, и `useMemo` здесь не нужен. Почему — увидим в эксперименте.

Провайдер темы оборачивает всё приложение — в `main.tsx`:

```tsx main.tsx {3,5}
root.render(
  <StrictMode>
    <ThemeProvider>
      <App />
    </ThemeProvider>
  </StrictMode>,
);
```

(импорт: `import { ThemeProvider } from './theme/ThemeProvider';`). А переключатель — в шапке, после сводки корзины:

```tsx layout/Header.tsx
  const { theme, toggleTheme } = useTheme();
  …
      <button
        type="button"
        className={styles.theme}
        aria-pressed={theme === 'dark'}
        onClick={toggleTheme}
      >
        ☾ Тёмная тема
      </button>
```

`aria-pressed` превращает кнопку в **переключатель**: программы чтения с экрана объявляют её именно так и сообщают, нажата ли она. Подпись при этом не меняется — меняется состояние. Тесты главы 17 найдут её так же: по роли `button`, имени и состоянию `pressed`.

::: task
1. В `theme/ThemeContext.ts` объявите тип `Theme`, тип значения, `ThemeContext` и хук `useTheme`.
2. В `theme/ThemeProvider.tsx` напишите провайдер: тема в `useLocalStorage` с ключом `'theme'`, эффект ставит `data-theme` на `<html>`, значение — тема и `toggleTheme`.
3. Оберните `App` в `ThemeProvider` в `main.tsx`.
4. В `Header` добавьте кнопку «☾ Тёмная тема» с `aria-pressed` и классом `styles.theme`.
:::

## Что получилось

Под сводкой корзины — кнопка «☾ Тёмная тема». Нажмите: магазин темнеет целиком — фон, карточки, баннер акции, мини-корзина, подсказка «Хит», окно «Очистить корзину?». Нажмите ⟳ в адресной строке превью — тема осталась тёмной: выбор в `localStorage` под ключом `theme`. Нажмите кнопку ещё раз — снова светлая.

## Эксперименты

1. **Кто рендерится.** Добавьте лог в начало `ThemeProvider`, `App`, `Header` и `GameCard`. Переключите тему:

   ```
   render ThemeProvider ×2
   render Header        ×2
   ```

   Только провайдер и единственный потребитель — шапка. Карточки и `App` не тронуты: тему они не читают, а `<App />` в `children` провайдера — тот же элемент, что был. Теперь наберите букву в поиске: `App`, шапка и карточки рендерятся (как и раньше — изменилось состояние `App`), а `render ThemeProvider` нет ни одной: провайдер стоит **выше** `App`, его рендерит только смена темы. Поэтому новый объект `value` при каждом рендере здесь ничего не стоит: рендер провайдера и так означает, что тема изменилась. Уберите логи.

2. **Атрибут.** Откройте инструменты разработчика и найдите `<html>` превью: `data-theme="dark"`. Удалите атрибут руками — магазин светлый, а кнопка по-прежнему «нажата»: React не знает, что внешнюю систему поменяли в обход него. Эффект поставит атрибут обратно при следующей смене темы.

## Как в настоящем проекте

- Начальную тему часто берут из настроек системы: `matchMedia('(prefers-color-scheme: dark)')` — `useMediaQuery` из главы 7 пригодится.
- Наш эффект ставит атрибут после первого рендера, а перед этим страница успевает показаться светлой. В настоящем проекте тему ставят маленьким скриптом прямо в `index.html`, до загрузки React, — иначе при запуске тёмная тема «мигает» светлой.
- Тему, язык, пользователя кладут в контекст почти всегда; корзину и другие часто меняющиеся данные, которые нужны многим, — чаще во внешнее хранилище (глава 9). В Ant Design (глава 15) тему задаёт тоже провайдер — `ConfigProvider`.

::: tip
Если вы пришли из Angular: контекст ближе всего к `InjectionToken` с `providers` у компонента — значение, а не класс. Сервис с сигналами внутри (`ThemeService` с `theme = signal('light')`) в React выглядит как провайдер с `useState` и хук `useTheme()`.
:::
