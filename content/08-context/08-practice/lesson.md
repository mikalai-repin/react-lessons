Покупатели просят «отложить» игры, чтобы вернуться к ним позже. Сделайте **избранное**: сердечко на обложке каждой карточки и счётчик «♥ 2» в шапке. Избранное должно пережить перезапуск, а сердечко «Острова сокровищ» в «Хитах» и во «Всех играх» — гореть одновременно.

Что уже в проекте:

- `favorites/FavoritesContext.ts` и `favorites/FavoritesProvider.tsx` — заготовки;
- в `GameCard.module.css` — класс `.favorite`: круглая кнопка в правом верхнем углу обложки, закрашенная цветом магазина при `aria-pressed="true"`;
- в `Header.module.css` — класс `.favorites`: плашка счётчика слева от корзины;
- `useLocalStorage` из главы 7.

::: task
1. В `favorites/FavoritesContext.ts` объявите тип значения — `ids` (id игр в избранном) и `toggle(gameId)`, создайте `FavoritesContext` и хук `useFavorites()` с проверкой провайдера.
2. В `favorites/FavoritesProvider.tsx` напишите `FavoritesProvider({ children })`: id хранятся в `useLocalStorage` под ключом `'favorites'`; `toggle` убирает игру из избранного, если она там есть, и добавляет, если нет. Значение контекста не должно меняться, пока не изменилось избранное.
3. Оберните приложение в `FavoritesProvider` в `main.tsx` — внутри `ThemeProvider`.
4. В `GameCard` на обложке (после `<img>`) — кнопка-переключатель с классом `styles.favorite`, `aria-label="В избранное"` и `aria-pressed`; внутри `♥`, если игра в избранном, иначе `♡`.
5. В `Header` перед сводкой корзины — `<p className={styles.favorites} title="Избранное">` с текстом «♥ N».
:::

::: hint Подсказка 1: с чего начать
Повторите путь темы из шага «Когда нужен контекст»: тип + контекст + хук в одном файле, провайдер с состоянием — в другом. Значение по умолчанию — `null`, хук бросает ошибку, если провайдера нет.
:::

::: hint Подсказка 2: провайдер
```tsx
const [ids, setIds] = useLocalStorage<number[]>(
  'favorites',
  [],
);
```

Тип `number[]` задайте явно: из `[]` TypeScript выведет `never[]` (глава 4).

`toggle` — без изменения массива на месте: `filter`, чтобы убрать, spread, чтобы добавить.
:::

::: hint Подсказка 3: значение не меняется
`toggle` зависит от `ids`, поэтому и объект `{ ids, toggle }` должен обновляться вместе с ними — и только с ними. Это `useMemo` с зависимостями `[ids, setIds]` (шаг «Цена контекста»). `setIds` из `useLocalStorage` стабильна: в главе 7 мы обернули её в `useCallback`.
:::

::: hint Подсказка 4: кнопка на карточке
```tsx
const favorites = useFavorites();
const favorite = favorites.ids.includes(game.id);
…
<button
  type="button"
  className={styles.favorite}
  aria-label="В избранное"
  aria-pressed={favorite}
  onClick={() => favorites.toggle(game.id)}
>
  {favorite ? '♥' : '♡'}
</button>
```

У кнопки-значка нет текста, понятного программе чтения с экрана, поэтому имя задаёт `aria-label`, а состояние — `aria-pressed`.
:::

## Итоги главы

Корзина, тема и избранное доставляются компонентам без проброса props: `App` больше не знает о корзине ничего, кроме того, что её провайдер оборачивает магазин.

| Запись | Что делает |
|---|---|
| `createContext<T \| null>(null)` | объект контекста; значение по умолчанию — когда провайдера нет |
| `<XContext value={…}>` | провайдер: значение для всего поддерева |
| `use(XContext)` / `useContext(XContext)` | значение ближайшего провайдера; `use` — и в условиях |
| `function useX() { … use … }` | хук над контекстом: проверка провайдера в одном месте |
| `XProvider({ children })` | компонент-провайдер: состояние + контекст |
| два контекста + `useMemo` | меньше лишних рендеров потребителей |

И главные идеи:

- контекст — доставка значения вглубь дерева, а не хранилище: состояние живёт в провайдере (`useState`, `useReducer`), контекст только раздаёт его;
- сначала композиция (`children`), потом контекст: проброс на один-два уровня — нормален;
- при новом значении провайдера (сравнение `Object.is`) рендерятся **все** потребители этого контекста — даже те, кому нужна неизменившаяся часть. Против лишних рендеров — разделение контекстов и стабильное значение (`useMemo`, `useCallback`);
- контекст хорош для того, что нужно многим и меняется редко: тема, язык, пользователь, настройки. Часто меняющееся — во внешнее хранилище;
- «ближайший провайдер» — не поиск: провайдер кладёт значение в контекст на входе в поддерево и возвращает прежнее на выходе, а потребителей при изменении React находит по `fiber.dependencies`.

Корзина осталась в контексте с оговоркой: при каждом изменении рендерятся все карточки, хотя изменилась одна. В главе 9 мы вынесем её во **внешнее хранилище**: сначала своё — на `useSyncExternalStore` из главы 6, потом Zustand. Компоненты подпишутся каждый на свою часть, а провайдер станет не нужен.
