В прошлом шаге мы увидели: после «В корзину» `App` не рендерится. Но кто-то же обновил шапку и карточки? Посчитаем рендеры — и найдём рендеры, которых быть не должно.

## Кто рендерится

Добавьте лог в начало `Header`, `MiniCart` и `GameCard` (в карточке — сразу после строки с `}: GameCardProps) {`):

```tsx
console.log('render GameCard');
```

Нажмите «В корзину» у «Острова сокровищ»:

```
render Header       ×2
render MiniCart     ×2
render GameCard     ×12
```

(Консоль сворачивает повторы в счётчик.) Шесть карточек на экране, по два вызова в строгом режиме. `App`, `Section`, `GameGrid` не рендерились: они не читают контекст.

Это главное правило контекста: **когда значение провайдера меняется, React рендерит всех, кто этот контекст читает**, где бы они ни были, — даже если их родители пропущены. Изменилась одна позиция «Острова», а рендерятся все шесть карточек: контекст не знает, какая часть значения нужна каждому потребителю. Он сообщает «значение другое» — и всё.

Как React решает, что значение «другое»? Сравнивает новый `value` со старым через `Object.is` — как состояние в главе 4. Для объекта это сравнение ссылок.

## Лишние рендеры

Теперь подождите, пока погаснет уведомление «Добавлено» (2,5 секунды):

```
render Header       ×2
render MiniCart     ×2
render GameCard     ×12
```

Те же 16 строк — хотя корзина не изменилась! Погасло уведомление: `setToast(null)` рендерит `CartProvider`, а он при каждом рендере собирает значение заново — `const value = { items, add: …, … }`. Новый объект — другая ссылка — `Object.is` говорит «изменилось» — все потребители рендерятся.

Корзина у нас маленькая, и шестнадцать вызовов ничего не стоят. Но провайдер, который рендерится часто (таймер, ввод, анимация), с сотней потребителей — уже заметно. Исправим двумя приёмами.

## Приём 1: разделить контекст

Шапке нужны только позиции, а действия ей ни к чему. Разделим значение на два контекста — то, что меняется с каждым действием, и то, что не меняется вообще:

```tsx cart/CartContext.ts
/** Что можно сделать с корзиной */
export type CartActions = {
  add: (gameId: number) => void;
  decrease: (gameId: number) => void;
  remove: (gameId: number) => void;
  clear: () => void;
};

// Позиции корзины: меняются с каждым действием.
// null — значение по умолчанию: компонент нарисован вне провайдера
export const CartContext = createContext<CartItem[] | null>(null);

// Действия: функции не меняются — свой контекст, чтобы те,
// кому нужны только действия, не рендерились от новых позиций
export const CartActionsContext =
  createContext<CartActions | null>(null);
```

И два хука: `useCart()` теперь возвращает массив позиций, `useCartActions()` — действия (тот же код с `use` и проверкой на `null`, только контекст и текст ошибки свои). Провайдер вкладывает один контекст в другой:

```tsx cart/CartProvider.tsx
  return (
    <CartContext value={items}>
      <CartActionsContext value={actions}>
        {children}
        …уведомление
      </CartActionsContext>
    </CartContext>
  );
```

`items` — массив из редьюсера. Когда гаснет уведомление, это **тот же** массив: редьюсер не вызывался. Значит, `Object.is` скажет «не изменилось», и шапка, которая читает только `useCart()`, рендериться не будет. Карточке и мини-корзине нужны оба:

```tsx shared/GameCard.tsx
  const items = useCart();
  const { add } = useCartActions();
  const quantity = quantityInCart(items, game.id);
```

Так же — в `MiniCart` (`useCart()` и `useCartActions()` для `add`, `decrease`, `remove`, `clear`) и в `GameDetails`; в `Header` — `const items = useCart();`.

Проверьте логом: после «В корзину» — те же 16 строк, а когда гаснет уведомление:

```
render MiniCart     ×2
render GameCard     ×12
```

Шапки нет. Но карточки по-прежнему рендерятся: объект `actions` всё ещё новый при каждом рендере провайдера.

## Приём 2: сохранить значение между рендерами

Действия не зависят ни от позиций, ни от уведомления: им нужны только `dispatch` и `showToast`. Создадим объект один раз — хуком [`useMemo`](https://react.dev/reference/react/useMemo):

```tsx cart/CartProvider.tsx
  // Действия: объект создаём один раз — пока не сменились
  // dispatch и showToast, а они не сменятся
  const actions = useMemo<CartActions>(
    () => ({
      add: (gameId) => { … },
      decrease: (gameId) =>
        dispatch({ type: 'decreased', gameId }),
      remove: (gameId) => dispatch({ type: 'removed', gameId }),
      clear: () => dispatch({ type: 'cleared' }),
    }),
    [dispatch, showToast],
  );
```

`useMemo(вычисление, зависимости)` при первом рендере вызывает функцию и запоминает результат в ячейке хука. При следующих рендерах сравнивает зависимости с прошлыми (`Object.is` по каждой): совпали — возвращает **прошлый** результат, не вызывая функцию; нет — вычисляет заново. Родственник `useCallback` из главы 7: `useCallback(fn, deps)` — это `useMemo(() => fn, deps)`.

Зависимости должны быть стабильными, иначе `useMemo` бесполезен:

- `dispatch` редьюсера React сохраняет между рендерами — это та же функция всё время жизни компонента (`useImmerReducer` возвращает `dispatch` обычного `useReducer`, это видно в его исходниках);
- `showToast` объявлена в теле провайдера — новая при каждом рендере. Оберните её в `useCallback` с пустыми зависимостями: внутри только `setToast` (тоже стабильна) и ссылка на таймер (тот же объект).

```tsx cart/CartProvider.tsx
  // useCallback: та же функция во всех рендерах —
  // setToast и ссылка на таймер не меняются
  const showToast = useCallback((text: string) => {
    … // тело без изменений
  }, []);
```

Импорт: `import { useCallback, useMemo, useRef, useState } from 'react';`. Тип значения `CartContextValue` больше не нужен — его место заняли `CartActions` и `CartItem[]`.

::: task
1. В `CartContext.ts` разделите контекст на `CartContext` (позиции, `CartItem[]`) и `CartActionsContext` (тип `CartActions`), к `useCart()` добавьте `useCartActions()`.
2. В `CartProvider` оберните `showToast` в `useCallback`, действия соберите в `useMemo` и предоставьте два контекста.
3. Переведите потребителей: шапке — только `useCart()`, карточке, мини-корзине и странице игры — оба хука.
:::

## Что получилось

Магазин работает как раньше. С логами: «В корзину» — шапка, мини-корзина и 12 строк карточек (изменились позиции, им всем нужно знать). Погасло уведомление — **ни одной строки**: `items` тот же массив, `actions` — тот же объект из ячейки `useMemo`, сравнивать нечего. Уберите логи.

| Когда | Без приёмов | Разделение | + `useMemo` |
|---|---|---|---|
| «В корзину» | 16 строк | 16 | 16 |
| уведомление погасло | 16 | 14 | 0 |

## Эксперименты

1. **Без `useCallback`.** Верните `showToast` в обычную функцию (`function showToast(text: string) { … }`), зависимости `useMemo` не трогайте. Нажмите «В корзину» и подождите — когда гаснет уведомление, снова 12 строк `render GameCard`. `showToast` новая при каждом рендере, значит, зависимость изменилась, и `useMemo` каждый раз вычисляет новый объект. Линтер это видит:

   ```
   The 'showToast' function makes the dependencies of useMemo Hook (at line 60) change on every render. Move it inside the useMemo callback. Alternatively, wrap the definition of 'showToast' in its own useCallback() Hook
   ```

   Два честных выхода он и предлагает: перенести функцию внутрь `useMemo` или обернуть в `useCallback`. Убрать `showToast` из зависимостей — нечестный: если бы функция читала что-то из рендера, действия запомнили бы её старую версию — устаревшее замыкание (глава 6). Верните `useCallback`.

2. **Все карточки — всё равно.** После «В корзину» рендерятся все шесть карточек, хотя изменилась одна. Разделение и `useMemo` этого не исправят: карточка читает весь массив `items`, а он новый. Контекст не умеет «подписать компонент на часть значения». Это умеют внешние хранилища с **селекторами** — глава 9: компонент подписывается на часть хранилища и рендерится, только если изменилась она.

## Как в настоящем проекте

- Рецепт для провайдера: состояние и функции — в разных контекстах; функции — стабильные (`dispatch` из `useReducer` уже стабилен, свои — через `useCallback`/`useMemo`); объект значения, если он нужен, — в `useMemo`.
- Мерить, а не угадывать: React DevTools (вкладка Profiler) показывает, какие компоненты рендерились, а с настройкой «Record why each component rendered» — и почему. В превью курса DevTools нет — мы считали логом.
- В главе 16 появится **React Compiler**: он сам запоминает значения и функции в компонентах, и ручные `useMemo`/`useCallback` в провайдерах станут не нужны. Но причину лишних рендеров — новый объект в `value` — понимать нужно и с ним.
- Часто меняющееся состояние, которое нужно многим (ввод, позиция курсора, цены в реальном времени), в контекст не кладут — следующий шаг.
