Этот шаг необязательный. В шаге про правила мы сказали, что React раздаёт хукам ячейки по порядку вызова, а в главе 4 видели первую ячейку `App` в поле `memoizedState` его файбера. Теперь посмотрим на весь список — и на то, во что превращаются свои хуки.

## Датчик

Добавьте в конец `main.tsx` функцию, которая находит файбер компонента по имени и печатает его ячейки. Путь к корню дерева файберов — как в главе 4, дальше — обход в глубину: `child` — первый ребёнок, `sibling` — следующий сосед. Имена хуков React в режиме разработки хранит в поле `_debugHookTypes` — из него же строится таблица из шага про правила.

```tsx main.tsx

// Что лежит в ячейке хука — коротко, по типу хука
function describe(type: string, state: any): string {
  const json = (value: unknown) =>
    JSON.stringify(value, (_, v) =>
      typeof v === 'function' ? 'ƒ' : v,
    );
  if (type === 'useEffect') return `эффект, deps ${json(state.deps)}`;
  if (type === 'useCallback' || type === 'useMemo')
    return `[ƒ, deps ${json(state[1])}]`;
  if (type === 'useEffectEvent') return 'событие эффекта';
  if (type === 'useRef') return 'ссылка';
  return json(state);
}

// Ячейки хуков компонента name: ищем его файбер от корня
function printHooks(name: string) {
  const key = Object.keys(container!).find((k) =>
    k.startsWith('__reactContainer'),
  )!;
  // Обход в глубину: child — первый ребёнок, sibling — сосед
  const stack = [(container as any)[key].stateNode.current];
  while (stack.length > 0) {
    const fiber = stack.pop();
    if (fiber.type?.name === name) {
      console.log(`— хуки ${name}`);
      let hook = fiber.memoizedState;
      fiber._debugHookTypes.forEach((type: string, i: number) => {
        console.log(i + 1, type, describe(type, hook.memoizedState));
        hook = hook.next;
      });
      return;
    }
    if (fiber.sibling) stack.push(fiber.sibling);
    if (fiber.child) stack.push(fiber.child);
  }
}

// После каждого щелчка — ячейки страницы игры
document.addEventListener('click', () => {
  setTimeout(() => printHooks('GameDetails'));
});
```

## Ячейки страницы игры

Откройте «Остров сокровищ»:

```
— хуки GameDetails
1 useState ""
2 useCallback [ƒ, deps ["review-draft:1"]]
3 useState false
4 useEffectEvent событие эффекта
5 useEffect эффект, deps [1]
```

Напишите в отзыве «Да» и щёлкните по описанию игры — в первой строке `useState "Да"`, остальное то же.

Посмотрите, чего в списке **нет**: `useLocalStorage`. Первые две ячейки — `useState` и `useCallback` из его тела, они стоят в списке `GameDetails` так, будто написаны прямо в компоненте. Для React своего хука не существует: это обычная функция, которая вызвала два хука во время рендера `GameDetails`. Отсюда всё, что мы видели в главе:

- **состояние не общее** (шаг про `useLocalStorage`): хук в `App` создаёт ячейки в списке `App`, хук в `GameDetails` — в списке `GameDetails`;
- **правила те же**: хуки внутри своего хука — часть порядка компонента. Свой хук в условии сдвигает все ячейки ниже, как встроенный.

Замените в датчике `'GameDetails'` на `'App'` и нажмите «В корзину» у «Острова»:

```
— хуки App
1 useState {"query":"","category":"all","inStockOnly":false,"sort":"default"}
2 useState ""
3 useEffect эффект, deps ["",300]
4 useState 3
5 useRef ссылка
6 useMemo [ƒ, deps ["ƒ"]]
7 useReducer [{"gameId":1,"quantity":1}]
8 useState null
9 useState "Добавлено: Остров сокровищ"
10 useRef ссылка
```

Ячейки 2–3 — `useDebouncedValue(filters.query, 300)`: состояние с задержкой и эффект с таймером, deps `["", 300]` — это `[value, delay]`. Ячейки 6–7 — `useImmerReducer` из библиотеки `use-immer`: свой хук библиотеки устроен так же, как наши, — `useMemo` и встроенный `useReducer`. Библиотечные хуки не волшебные: это функции поверх тех же встроенных хуков.

## Почему по порядку, а не по имени

Можно представить API, где ячейки получают имена: `useState('review', '')`. React так не делает, и причина — свои хуки. Вызовите `useLocalStorage` в одном компоненте дважды — для отзыва и, например, для оценки:

```tsx game/GameDetails.tsx
const [rating, setRating] = useLocalStorage(
  `review-rating:${game.id}`,
  0,
);
```

Внутри хука оба раза вызывается `useState` — с одними и теми же строками кода. С именами ячеек два вызова столкнулись бы, и автору хука пришлось бы придумывать уникальные имена. С порядком — просто ещё две ячейки: в датчике после первых двух появятся `3 useState 0` и `4 useCallback […]`, а остальные сдвинутся. Порядок делает свои хуки **составляемыми**: хук можно вызвать сколько угодно раз и внутри других хуков, не зная, что у него внутри.

## Как React идёт по списку

React держит две копии дерева файберов (глава 4): текущую — то, что на экране, — и черновую, в которой готовит рендер. Ячейки хуков — тоже в обеих.

```
первый рендер компонента:
  хук → новая ячейка в конец списка
следующие рендеры:
  хук → следующая ячейка из текущей копии
        → копия в черновую, обновления
  ячеек в текущей копии не хватило:
        «Rendered more hooks than…»
  после рендера ячейки остались:
        «Rendered fewer hooks than…»
```

В `react-dom-client.development.js` это две функции: `mountWorkInProgressHook` создаёт ячейку и цепляет её в конец списка, `updateWorkInProgressHook` берёт `next` у ячейки текущей копии. Обе ошибки из шага про правила бросаются здесь и в проверке после рендера.

## Диспетчер

Почему хук работает только во время рендера? `useState`, который вы импортируете из `react`, сам ничего не умеет. Он берёт **диспетчер** — объект с настоящими реализациями хуков — из внутреннего поля `ReactSharedInternals.H` и вызывает его метод. Перед вызовом компонента React кладёт туда один из диспетчеров:

- **монтирования** — если у компонента ещё нет ячеек: каждый хук создаёт новую;
- **обновления** — если ячейки есть: каждый хук берёт следующую.

После рендера в поле кладётся диспетчер, у которого каждый хук бросает `Invalid hook call`. Его и вызвал `useState` в обработчике щелчка в главе 4: рендера нет — нет и списка ячеек, к которому можно привязать хук.

Выбор диспетчера объясняет и тихий `MiniCart` из шага про правила. Условие — «у компонента в прошлом рендере не было ни одной ячейки» (`current.memoizedState === null`). У пустой корзины хуков не было, и React взял диспетчер монтирования: `useRef` после `return` просто создал новую ячейку — без ошибки, но и без прежнего значения.

## Что из этого следует

- Свой хук — не сущность React, а соглашение: функция `use…`, которая вызывает хуки в рендере компонента. Его ячейки — ячейки компонента.
- Порядок вызова — единственный «адрес» ячейки. Поэтому хуки — только на верхнем уровне, а условия — внутри хуков.
- Хуки можно составлять: хук в хуке в хуке — всё равно плоский список ячеек одного компонента.

Это внутренности React (`_debugHookTypes` есть только в режиме разработки), они могут измениться в любой версии — только для экспериментов. Нажмите «Сброс», чтобы вернуть `main.tsx`.
