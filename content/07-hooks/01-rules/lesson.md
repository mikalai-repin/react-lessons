В магазине уже десяток хуков: `useState`, `useReducer`, `useRef`, `useEffect`, `useEffectEvent`, `useSyncExternalStore`… Все они встроенные. В этой главе мы будем писать **свои**: вынесем таймер скидки, подписку на сеть и наблюдение за прокруткой из компонентов в функции, которые можно переиспользовать.

Но сначала — правила, по которым живут все хуки, встроенные и свои. Мы уже нарушали одно из них: в главе 4 вызвали `useState` в обработчике и получили «Invalid hook call». А в шаге про `useImperativeHandle` поставили `useRef` в `MiniCart` выше раннего `return` и пообещали объяснить почему. Пора.

## Два правила

**Хук** — функция, имя которой начинается с `use`. Хуки дают компоненту то, чего нет у обычной функции: память между рендерами, эффекты, подписки.

1. **Только на верхнем уровне.** Хук вызывается в теле компонента — не внутри `if`, цикла, `&&`, тернарного оператора, не после раннего `return`, не во вложенной функции (обработчике, колбэке `map` или эффекта).
2. **Только из компонентов и хуков.** Не из обычных функций, не из обработчиков, не из кода модуля вне компонента.

Смысл обоих правил один: **при каждом рендере компонент вызывает одни и те же хуки в одном и том же порядке**.

## Почему порядок

Посмотрите на начало `GameDetails`:

```tsx game/GameDetails.tsx
const [review, setReview] = useState('');
const [sent, setSent] = useState(false);
const onView = useEffectEvent((gameId: number) => { … });
useEffect(() => { … }, [game.id]);
```

Хуки не передают React никаких имён: `useState('')` не сообщает, что это «отзыв». Как же при следующем рендере React понимает, какое значение вернуть первому `useState`, а какое — второму? **По порядку вызова.** У каждого компонента на странице есть список ячеек, и React раздаёт их по очереди:

```
вызов  хук              ячейка
1      useState         review: ''
2      useState         sent: false
3      useEffectEvent   onView
4      useEffect        таймер просмотра
```

При первом рендере React создаёт ячейки, при следующих — идёт по тому же списку: первый вызов хука получает первую ячейку, второй — вторую. Если между рендерами порядок изменится, хук получит чужую ячейку.

## Эксперимент: хук в условии

Допустим, на странице игры хочется эффекта, но только когда игра уже в корзине. Добавьте в `GameDetails` после `useEffect` с аналитикой:

```tsx game/GameDetails.tsx
if (quantity > 0) {
  useEffect(() => {
    console.log('в корзине', quantity);
  });
}
```

TypeScript молчит. Откройте «Остров сокровищ» и нажмите «В корзину». Страница пропала, в консоли:

```
React has detected a change in the order of Hooks called by GameDetails. This will lead to bugs and errors if not fixed. …

   Previous render            Next render
   ------------------------------------------------------
1. useState                   useState
2. useState                   useState
3. useEffectEvent             useEffectEvent
4. useEffect                  useEffect
5. undefined                  useEffect
   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

и ошибка `Rendered more hooks than during the previous render.` Таблица — ровно список ячеек: в прошлом рендере их было четыре, в новом компонент попросил пятую, а её нет.

Теперь обратный путь. Перезапустите превью, нажмите «В корзину» у «Острова» в каталоге и только потом откройте его страницу — в консоли дважды `в корзине 1` (эффект в строгом режиме), всё работает. Нажмите «−» в мини-корзине: `quantity` стал 0, и — `Rendered fewer hooks than expected. This may be caused by an accidental early return statement.` Ячеек пять, а компонент вызвал четыре хука. React прямо подсказывает частую причину: хук после раннего `return`.

## Эксперимент: хук в середине

Хук в конце компонента хотя бы даёт понятную ошибку. Уберите эксперимент из `GameDetails` и поставьте похожий в `App` — после подсчёта `cartCount`, перед `selectedId`:

```tsx App.tsx
if (cartCount > 0) {
  useEffect(() => {
    document.title = `Корзина: ${cartCount}`;
  });
}
```

(и `useEffect` в импорт). Нажмите «В корзину». Таблица снова есть, но расхождение уже в шестой строке: на месте `useState` для `selectedId` теперь `useEffect`. А ошибка — `TypeError: Cannot read properties of null (reading 'inst')`: эффект получил ячейку состояния `selectedId` (там `null`) и попытался прочитать её как ячейку эффекта. Все хуки ниже тоже сдвинулись бы на одну ячейку.

Заметьте строки 4 и 5 таблицы: `useMemo` и `useReducer`, хотя в `App` таких вызовов нет. Это хуки внутри `useImmerReducer` из библиотеки `use-immer` — у них такие же ячейки в том же списке. К этому вернёмся в шаге «Под капотом».

Таблица порядка — только в режиме разработки. В продакшен-сборке её нет: вы увидите только непонятную ошибку — или вообще никакой, а хук тихо прочитает чужое значение.

Уберите эксперимент.

## Как писать условие правильно

Условие — **внутри** хука, а хук — всегда:

```tsx
useEffect(() => {
  if (cartCount === 0) return;
  document.title = `Корзина: ${cartCount}`;
}, [cartCount]);
```

Ранний `return` — **после** всех хуков. Именно поэтому в `MiniCart` `useRef` стоит перед `if (lines.length === 0) return …`.

::: deep А если перенести useRef в MiniCart ниже return?
Попробуйте: перенесите две строки со ссылкой `confirmRef` ниже `if` и добавьте после них `console.log('MiniCart: ссылка', confirmRef.current);`. Ни ошибки, ни таблицы. Добавьте игру в корзину — `ссылка null`, ещё одну — `ссылка { open: ƒ open() }`. «Очистить корзину», снова «В корзину» — опять `null`: ссылка создана **заново**.

React заметил бы лишний хук, только если у компонента в прошлом рендере были хуки. У пустой корзины их ноль, и React считает, что компонент создаёт хуки впервые, — механизм разберём в шаге «Под капотом». Правило нарушено, а сообщения нет: состояние в такой ячейке молча сбрасывалось бы, а второй хук в `MiniCart` превратил бы тишину в ошибку. Поэтому правила хуков проверяют не по тому, ругается ли React, а по коду — и делает это линтер (следующий шаг). Верните строки на место.
:::

## Второе правило

Хук работает, только пока React рендерит компонент: именно тогда он знает, чей список ячеек раздавать. Вызов из обработчика — в момент щелчка, когда никакого рендера нет, — даёт `Invalid hook call` (глава 4).

А обычная функция, которую компонент вызывает **во время рендера**, сработает:

```tsx
function readDraft(key: string) {
  return useState(() => localStorage.getItem(key) ?? '');
}
```

Технически её хук займёт ячейку в компоненте, который её вызвал. Но по имени `readDraft` не видно, что внутри хук: её легко вызвать в условии или в обработчике — и получить ошибки выше. Поэтому договорённость такая: **функция, которая вызывает хуки, сама называется `use…`** — и подчиняется тем же правилам. Это и есть **свой хук** (custom hook), им посвящена глава.

## Как в настоящем проекте

- Правила хуков проверяет правило линтера `react-hooks/rules-of-hooks`. В настоящем проекте нарушение подчёркивается ещё до запуска — в следующем шаге посмотрим, как.
- Исключение одно — `use` (глава 8): этот встроенный хук можно вызывать в условиях и циклах. Остальные, включая ваши, — только на верхнем уровне.

::: tip
Если вы пришли из Angular: сигналы и `inject()` тоже требуют «правильного контекста» — `inject()` работает только при создании компонента или сервиса. Ограничения хуков строже: важен не только момент вызова, но и порядок.
:::
