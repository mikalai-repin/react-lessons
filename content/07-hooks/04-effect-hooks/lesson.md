Самая ценная часть своих хуков — не `useState` с парой строк вокруг, а **синхронизация с внешним миром**. Эффект с таймером, подписка на события браузера — это код, который легко написать с ошибкой в очистке. Написали один раз в хуке, проверили — и компоненты дальше пользуются им, не думая о таймерах и подписках.

В этом шаге — два таких хука: поиск с задержкой (новый) и «есть ли сеть» (вынесем из `OfflineBanner`). В старте — заготовки `hooks/useDebouncedValue.ts` и `hooks/useOnlineStatus.ts`.

## Поиск с задержкой

Сейчас каталог фильтруется на каждую букву: «о» — одна выборка, «ос» — другая, «ост» — третья. Шесть игр в памяти это выдержат. Но в главе 11 поиск пойдёт на сервер, и каждая буква станет запросом: покупатель набрал «остров» — шесть запросов, из которых нужен последний.

Обычное решение — **задержка** (debounce): искать, только когда покупатель перестал печатать, например на 300 мс. Поле при этом меняется сразу, на каждую букву, — иначе ввод «тормозит». Значит, нужно два значения: то, что в поле, и то, по которому ищем, — оно «догоняет» первое после паузы.

```tsx hooks/useDebouncedValue.ts
import { useEffect, useState } from 'react';

// Значение с задержкой: догоняет value, когда оно не менялось delay мс.
// Пока value меняется чаще, хук возвращает прежнее значение
export function useDebouncedValue<T>(value: T, delay: number) {
  const [debounced, setDebounced] = useState(value);

  // Синхронизация с таймером: новое value — новый отсчёт
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);

  return debounced;
}
```

Вся работа — в очистке. Каждая новая буква меняет `value`: React вызывает очистку прошлого эффекта (таймер прошлой буквы отменён) и запускает новый. До `setDebounced` доживает только таймер последней буквы — если за 300 мс новой не пришло.

Хук возвращает одно значение, а не пару: менять его снаружи незачем.

В `App` поле по-прежнему управляется `filters.query`, а ищем по значению с задержкой:

```tsx App.tsx {1-2,7-12}
// Пауза в наборе, после которой ищем, мс
const SEARCH_DELAY = 300;

export function App() {
  const hits = games.filter(isHit);
  const [filters, setFilters] = useState(INITIAL_FILTERS);
  // Поле поиска меняется на каждую букву, а поиск — после паузы
  const query = useDebouncedValue(filters.query, SEARCH_DELAY);
  // Что показать — вычисляем при каждом рендере
  const visibleGames = filterGames(games, {
    ...filters,
    query,
  });
```

Импорт: `import { useDebouncedValue } from './hooks/useDebouncedValue';`. Объект фильтров для `filterGames` — копия `filters`, в которой `query` заменён значением с задержкой.

## «Есть ли сеть» — в хук

В `OfflineBanner` (глава 6) функции `subscribe` и `getSnapshot` и вызов `useSyncExternalStore` — это ответ на вопрос «есть ли сеть». Сама полоса — только разметка. Перенесите функции в `hooks/useOnlineStatus.ts` без изменений (вместе с импортом `useSyncExternalStore`) и добавьте хук:

```tsx hooks/useOnlineStatus.ts
// …subscribe и getSnapshot из OfflineBanner…

// Есть ли сеть: значение браузера с подпиской на изменения
export function useOnlineStatus() {
  return useSyncExternalStore(subscribe, getSnapshot);
}
```

`OfflineBanner` становится компонентом из одной строки логики:

```tsx layout/OfflineBanner.tsx
import { useOnlineStatus } from '../hooks/useOnlineStatus';
import styles from './OfflineBanner.module.css';

// Полоса «Нет сети» над магазином
export function OfflineBanner() {
  const online = useOnlineStatus();
  if (online) return null;
  return (
    <p className={styles.banner} role="alert">
      Нет сети — проверьте подключение к интернету
    </p>
  );
}
```

`subscribe` и `getSnapshot` остались вне хука, на уровне модуля: как и раньше, они одни на все рендеры, и React не переподписывается при каждом рендере.

::: task
1. В `hooks/useDebouncedValue.ts` напишите хук `useDebouncedValue(value, delay)`: состояние с начальным `value` и эффект, который через `delay` мс записывает в него `value`; в очистке — `clearTimeout`.
2. В `App` заведите константу `SEARCH_DELAY = 300` и фильтруйте каталог по `useDebouncedValue(filters.query, SEARCH_DELAY)`, а не по `filters.query`.
3. Перенесите `subscribe` и `getSnapshot` из `layout/OfflineBanner.tsx` в `hooks/useOnlineStatus.ts` и напишите хук `useOnlineStatus()`. `OfflineBanner` берёт значение из хука.
:::

## Что получилось

Наберите в поиске «ост» быстро: буквы появляются в поле сразу, а витрина меняется через долю секунды после последней — остаётся «Остров сокровищ». Наберите «zzz» — через паузу «Ничего не нашлось». Нажмите «Сбросить фильтры»: поле очистилось и получило фокус сразу, а витрина вернулась через 0,3 с — она тоже ждёт паузу. Категория и остальные фильтры работают без задержки: она только у текста поиска. Полоса «Нет сети» работает как раньше (инструменты разработчика → «Сеть» → «Офлайн»).

## Эксперименты

1. **Таймеры.** Добавьте в эффект хука логи:

   ```tsx hooks/useDebouncedValue.ts
   useEffect(() => {
     console.log('таймер:', value);
     const id = setTimeout(() => setDebounced(value), delay);
     return () => {
       console.log('отмена:', value);
       clearTimeout(id);
     };
   }, [value, delay]);
   ```

   При запуске — `таймер: `, `отмена: `, `таймер: ` (строгий режим, значение пустое). Быстро наберите «ост»:

   ```
   отмена:
   таймер: о
   отмена: о
   таймер: ос
   отмена: ос
   таймер: ост
   ```

   Каждая буква отменяет таймер предыдущей. Сработал только последний. Уберите логи.

2. **Сколько раз искали.** Добавьте в `App` после `query` эффект-датчик (и `useEffect` в импорт):

   ```tsx App.tsx
   useEffect(() => {
     console.log('ищем:', query);
   }, [query]);
   ```

   При запуске — дважды `ищем: `. Быстро наберите «ост» — одна строка `ищем: ост`. Сотрите и наберите медленно, с паузой больше 0,3 с между буквами, — три строки: `ищем: о`, `ищем: ос`, `ищем: ост`. Задержка работает по паузам, а не по числу букв.

3. **Без очистки.** Замените в хуке две строки с `id` одной: `setTimeout(() => setDebounced(value), delay);`. Быстро наберите «ост» — через 0,3 с три строки подряд: `ищем: о`, `ищем: ос`, `ищем: ост`. Витрина трижды перестроилась — по разу на каждую букву. Без очистки задержка превратилась в «то же самое, только позже». Верните очистку и уберите датчик.

4. **Один хук — общее значение?** В прошлом шаге два вызова `useLocalStorage` дали два независимых состояния. Добавьте в шапку `const online = useOnlineStatus();` и замените «Корзина» на `{online ? 'Корзина' : 'Офлайн'}`. Включите «Офлайн» в инструментах разработчика: одновременно появилась полоса и шапка показала «Офлайн: 0». Здесь значение общее — но не потому, что хук его делит: оно живёт в браузере (`navigator.onLine`), а каждый вызов хука на него подписан. Уберите эксперимент.

::: deep Лишний рендер на первой букве
Если добавить в `App` строку `console.log('render App')`, на первую букву вы увидите четыре строки, а на каждую следующую — две. Лишняя пара — от таймера, запущенного при старте: через 0,3 с он вызывает `setDebounced('')` с тем же значением. Рендера сразу нет: React сравнил значения и не стал рендерить. Но само обновление осталось в очереди с приоритетом таймера, ниже, чем у ввода. Первая буква рендерит `App` по срочному вводу, обновление таймера в этот рендер не попадает, и React делает ещё один рендер — чтобы обработать и его. Без строгого режима — две строки вместо одной. Вреда нет: DOM не меняется. Но это ещё одна причина не опираться на число рендеров в логике.
:::

## Как в настоящем проекте

- `useDebouncedValue` — частый хук: поиск, автосохранение черновика, подсказки адреса. В главе 12 мы встретим встроенный `useDeferredValue`: он тоже отделяет срочное значение (поле) от отложенного (список), но без фиксированной паузы — React сам решает, когда догнать.
- По образцу `useOnlineStatus` пишут хуки для любых значений браузера с подпиской: размер окна, видимость вкладки, `matchMedia` (тема ОС, ширина экрана — `useMediaQuery`), адрес страницы. У `useMediaQuery` есть тонкость: `subscribe` зависит от запроса и уже не может жить на уровне модуля — её разберём в следующем шаге.
- Хук прячет механизм, а не смысл: имя говорит, что вы получаете (`useOnlineStatus` — есть ли сеть), а не как (`useSubscribeToOnlineEvents`).
