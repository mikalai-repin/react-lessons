Маркетологи просят: пусть обратный отсчёт акции будет виден не только на странице игры со скидкой, но и в баннере над каталогом — «До конца акции — 1:59:58». А когда акция закончится, баннер должен исчезнуть сам.

Отсчёт уже есть — в `Countdown` (глава 6): состояние `now`, интервал, `finished`. Но баннеру нужна та же логика с другой разметкой. Копировать эффект с интервалом во второй компонент — значит дважды писать очистку и дважды её проверять. Вынесите логику в хук `useCountdown`.

Что уже в проекте:

- `hooks/useCountdown.ts` — заготовка;
- `layout/PromoBanner.tsx` — заготовка, `layout/PromoBanner.module.css` — готовые стили: `.promo` (жёлтая плашка) и `.timer` (строка отсчёта);
- `SALE_ENDS` в `data/sale.ts` и `formatDuration` в `shared/format.ts` — как в главе 6.

::: task
1. В `hooks/useCountdown.ts` напишите хук `useCountdown(deadline)`: обратный отсчёт до `deadline` с обновлением раз в секунду. Хук возвращает объект `{ remaining, finished }`: сколько осталось (мс, не меньше 0) и вышло ли время. Тип результата объявите явно.
2. Перепишите `Countdown` на `useCountdown`: в компоненте не остаётся ни состояния, ни эффекта.
3. В `layout/PromoBanner.tsx` напишите компонент `PromoBanner`: перенесите в него `PROMO_HTML` из `App` и выведите текст акции и строку «До конца акции — 1:59:58» (`styles.timer`) внутри `<div className={styles.promo}>`. Когда акция закончилась, баннера нет.
4. В `App` нарисуйте `<PromoBanner />` на месте абзаца с акцией. Константа `PROMO_HTML` и класс `.promo` в `App.module.css` больше не нужны — удалите их.
:::

::: hint Подсказка 1: с чего начать
Хук — это код из `Countdown` без разметки. Перенесите в функцию `useCountdown(deadline: number)` строки с `now`, `finished` и эффектом, а в конце верните то, что нужно разметке. Импорты `useEffect` и `useState` переедут вместе с кодом.
:::

::: hint Подсказка 2: что вернуть
Два значения, и не всем нужны оба — это объект, а не пара (шаг «API хука»). Тип результата — рядом с хуком:

```tsx
type Countdown = {
  // Сколько осталось, мс; 0 — время вышло
  remaining: number;
  finished: boolean;
};

export function useCountdown(deadline: number): Countdown {
  …
  return { remaining: Math.max(deadline - now, 0), finished };
}
```

`Math.max` — чтобы после конца акции не было отрицательного времени: последний тик интервала может прийти чуть позже `deadline`.
:::

::: hint Подсказка 3: Countdown
```tsx
export function Countdown({ deadline }: CountdownProps) {
  const { remaining, finished } = useCountdown(deadline);
  return (
    <p className={styles.countdown}>
      {finished
        ? 'Акция закончилась'
        : `Скидка действует ещё ${formatDuration(remaining)}`}
    </p>
  );
}
```
:::

::: hint Подсказка 4: баннер
`PromoBanner` вызывает `useCountdown(SALE_ENDS)`, а после хука — ранний `return null`, если `finished` (хук — до `return`, правило из начала главы). Текст акции — по-прежнему через `dangerouslySetInnerHTML` (глава 2) в своём `<p>`, строка отсчёта — во втором `<p className={styles.timer}>`. Импорты: `SALE_ENDS` из `../data/sale`, хук из `../hooks/useCountdown`, `formatDuration` из `../shared/format`.
:::

## Проверьте себя

- Над корзиной — жёлтый баннер: «Неделя семейных игр: скидки до **20%** на „Остров сокровищ“ и „Нарды“» и под ним «До конца акции — 2:00:00» (или чуть меньше). Каждую секунду время уменьшается.
- На странице «Острова сокровищ» — «Скидка действует ещё …», баннер над ней тоже на месте. Присмотритесь: секунды в баннере и на странице иногда расходятся на одну. Это не ошибка, а свойство хука: у каждого вызова `useCountdown` — своё состояние `now` и свой интервал, запущенный в свой момент. Хотите одни часы на всех — значение должно жить вне компонентов (внешнее хранилище, глава 9).
- В `data/sale.ts` замените два часа на `3 * 1000`. Через три секунды после запуска баннер исчез, а на странице «Острова» — «Акция закончилась». Верните два часа.
- **Где живёт таймер.** Добавьте в начало `GameCard` строку `console.log('render GameCard');`. Подождите пару секунд — новых строк нет: каждую секунду рендерится только `PromoBanner`. Теперь вызовите хук прямо в `App` — добавьте в его начало `useCountdown(SALE_ENDS);` (и импорты). Каждую секунду — **12 строк** `render GameCard`: шесть карточек, по два вызова в строгом режиме. Состояние хука живёт в компоненте, который его вызвал (шаг «Под капотом»), и каждый тик рендерит `App` со всем деревом. Поэтому часто меняющееся состояние держат в маленьком компоненте внизу дерева — как `PromoBanner`. Уберите строку из `App` и лог.
- Консоль пуста, ошибок типов нет.

## Итоги главы

Логика магазина переехала из компонентов в хуки: черновик отзыва переживает перезапуск, поиск ждёт паузу в наборе, «Нет сети», «Показать ещё» и таймер акции стали короткими компонентами поверх `useOnlineStatus`, `useInView` и `useCountdown`.

| Запись | Что делает |
|---|---|
| `function useX() { … useState … }` | свой хук: функция `use…`, которая вызывает хуки |
| хуки на верхнем уровне, условие — внутри хука | одинаковый порядок вызовов в каждом рендере |
| `reactHooks.configs.flat.recommended` | правила хуков и правила компилятора в ESLint |
| `return [value, set] as const` | пара, как у `useState` |
| `return { remaining, finished }` | объект, когда значений больше или нужны не все |
| `useEffectEvent(onEnter)` внутри хука | хук принимает любую функцию и не перезапускается |
| `useCallback(fn, [deps])` | та же функция между рендерами, пока зависимости те же |

И главные идеи:

- React находит ячейки хуков **по порядку вызова**: у каждого компонента — список в файбере. Отсюда правила: хуки только на верхнем уровне, только в компонентах и хуках. Линтер проверяет их по коду, а React — только когда нарушение случилось, и не всегда;
- свой хук — не сущность React, а функция: его хуки — ячейки компонента, который его вызвал. Хук делит **код**, а не **состояние**: два вызова — два независимых состояния, а общее значение бывает только у внешнего хранилища;
- лучшие хуки прячут **синхронизацию с внешним миром**: таймеры, подписки, наблюдателей — с очисткой, проверенной один раз;
- у хука есть API: ответ (значение, пара, объект или ничего), функции на входе (могут быть любыми — `useEffectEvent`) и на выходе (стабильные — `useCallback`);
- хук не нужен, если в функции нет хуков, если он оборачивает один `useState`, прячет зависимости эффекта или возвращает разметку;
- состояние хука рендерит компонент, который его вызвал: часто меняющееся — пониже в дереве.

Корзина магазина по-прежнему живёт в `App`, и `App` передаёт её вниз через props: `cartCount` — шапке, `items` и четыре обработчика — мини-корзине, `quantity` и `onAdd` — каждой карточке. Хук здесь не поможет: он делит код, а не данные. В главе 8 мы разберём **контекст** — способ передать данные вглубь дерева без проброса props — и узнаем, во что он обходится.
