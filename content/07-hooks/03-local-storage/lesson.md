Покупатель открыл «Остров сокровищ» и начал писать длинный отзыв. Отвлёкся, закрыл вкладку — или просто нажал ⟳ в превью. Вернулся — поле пустое, текст пропал. Сохраним черновик отзыва так, чтобы он пережил перезапуск.

Состояние React живёт, пока живёт компонент, а после перезапуска приложение начинается с нуля. Переживёт перезапуск только то, что хранит браузер, — например, [`localStorage`](https://developer.mozilla.org/ru/docs/Web/API/Window/localStorage): строки по ключам, привязанные к сайту.

## Сначала — прямо в компоненте

С тем, что мы знаем, черновик в `GameDetails` выглядел бы так:

```tsx
const key = `review-draft:${game.id}`;
const [review, setReview] = useState(
  () => localStorage.getItem(key) ?? '',
);

function handleReviewChange(text: string) {
  setReview(text);
  localStorage.setItem(key, text);
}
```

- Начальное значение — из хранилища: функция-инициализатор (глава 5) читает его один раз, при создании состояния.
- Записываем в хранилище там же, где меняем состояние, — в обработчике. Эффект не нужен: запись — реакция на действие покупателя, а не синхронизация «пока компонент на экране» (глава 6).

Работает. Но завтра то же понадобится для выбранных фильтров, послезавтра — для «Недавно смотрели»: каждый раз те же пять строк, с теми же ошибками. Логику, в которой есть хуки, выносят в **свой хук**.

## Свой хук

Свой хук — обычная функция, имя которой начинается с `use` и которая вызывает другие хуки. Никакого специального API нет: это просто вынесенный кусок компонента.

```tsx hooks/useLocalStorage.ts
import { useState } from 'react';

// Состояние, которое переживает перезапуск: значение хранится
// в localStorage браузера под ключом key
export function useLocalStorage<T>(
  key: string,
  initialValue: T,
) {
  // Начальное значение — из хранилища, если там что-то есть
  const [value, setValue] = useState<T>(() => {
    const saved = localStorage.getItem(key);
    return saved === null
      ? initialValue
      : (JSON.parse(saved) as T);
  });

  // Новое значение — и в состояние, и в хранилище
  function setStoredValue(next: T) {
    setValue(next);
    localStorage.setItem(key, JSON.stringify(next));
  }

  return [value, setStoredValue] as const;
}
```

- **Обобщённый тип `T`**: хук хранит любое значение — строку, число, объект фильтров. TypeScript выводит `T` из `initialValue`.
- **`JSON.stringify` и `JSON.parse`**: `localStorage` хранит только строки, а значение может быть объектом.
- **Возвращаем пару**, как `useState`: `[значение, функция записи]`. Имена у пары даёт тот, кто вызывает хук: `const [review, setReview] = …`.
- **`as const`** нужен, чтобы TypeScript понял возвращаемое значение как кортеж «сначала `T`, потом функция», а не как массив, где каждый элемент — «то ли `T`, то ли функция». Без него ниже будут ошибки — проверим в эксперименте.
- Хуки — в отдельной папке `hooks/`, один хук — один файл `useX.ts`.

В `GameDetails` вместо `useState('')` для отзыва:

```tsx game/GameDetails.tsx {1-5}
  // Черновик отзыва — свой у каждой игры, переживает перезапуск
  const [review, setReview] = useLocalStorage(
    `review-draft:${game.id}`,
    '',
  );
  // Отправлен ли отзыв
  const [sent, setSent] = useState(false);
```

Импорт: `import { useLocalStorage } from '../hooks/useLocalStorage';`. Остальной код страницы не меняется: `review` и `setReview` — те же строка и функция, что давал `useState`. После отправки `setReview('')` очищает и черновик.

Ключ — свой у каждой игры: черновик отзыва о «Нардах» не должен появиться на странице «Острова». А страница игры получает `key={selectedGame.id}` (глава 5) — при смене игры это новый компонент, и хук заново читает хранилище со своим ключом.

::: task
1. В `hooks/useLocalStorage.ts` напишите хук `useLocalStorage(key, initialValue)`: состояние с начальным значением из `localStorage` (или `initialValue`, если там пусто), функция записи — в состояние и в хранилище, результат — пара `as const`.
2. В `GameDetails` храните текст отзыва в `useLocalStorage` с ключом `` `review-draft:${game.id}` `` и начальным значением `''`.
:::

## Что получилось

Откройте «Остров сокровищ», напишите в отзыве «Отличная игра» — счётчик «13 / 300». Нажмите ⟳ в адресной строке превью и снова откройте «Остров»: черновик на месте. «Следующая игра →» — у «Драконьей почты» поле пустое; «← К каталогу», снова «Остров» — черновик вернулся. Нажмите «Отправить» — поле очистилось, и после ⟳ оно пустое.

Загляните в хранилище: инструменты разработчика → «Приложение» (Application) → «Локальное хранилище» (Local Storage). Под ключом `review-draft:1` — `"Отличная игра"` в кавычках: это строка JSON. У превью и платформы курса один адрес, поэтому `localStorage` у них общий, и там же вы увидите ключи платформы. Кнопка «Сброс» хранилище не трогает: черновики переживают и её.

## Эксперименты

1. **Логика общая, состояние — нет.** Пусть шапка тоже хочет знать черновик «Острова». Добавьте в начало `App` (и импорт хука):

   ```tsx App.tsx
   const [draft] = useLocalStorage('review-draft:1', '');
   console.log('App, черновик:', draft);
   ```

   При запуске — дважды `App, черновик: ` с пустой строкой (если черновика нет). Откройте «Остров» — ещё две такие строки: изменился `selectedId`, и `App` отрендерился. Напишите в отзыве «Да» — новых строк нет: отзыв меняет состояние `GameDetails`, а не `App`. Нажмите «В корзину» — `App` рендерится, а черновик в нём по-прежнему пустой, хотя в `localStorage` уже «Да».

   Каждый вызов хука — это **свой** `useState` в том компоненте, который хук вызвал. `useLocalStorage` в `App` и в `GameDetails` — два независимых состояния, у которых общий только код. Хранилище не сообщает React о записи, а хук на изменения не подписан. Как сделать одно значение для многих компонентов — главы 8 (контекст) и 9 (внешнее хранилище на `useSyncExternalStore`). Уберите эксперимент.

2. **Без `as const`.** Уберите `as const` в хуке. Редактор подчеркнёт `GameDetails` в нескольких местах, например:

   ```
   TS2349: This expression is not callable.
     Not all constituents of type 'string | ((next: string) => void)' are callable.
       Type 'string' has no call signatures.
   ```

   Без `as const` хук возвращает массив `(string | ((next: string) => void))[]`: TypeScript не знает, что первым идёт строка, а вторым — функция. Верните `as const`.

## Как в настоящем проекте

- `localStorage` может бросить исключение: хранилище отключено в настройках браузера или переполнено. А в нём может лежать испорченный JSON — тогда бросит `JSON.parse`. Хук для продакшена оборачивает чтение и запись в `try`/`catch` и возвращается к `initialValue`.
- Наш хук читает хранилище только при создании состояния. Если ключ меняется у того же компонента, значение не перечитается, — нам это не грозит, страница игры пересоздаётся через `key`. Хук для общего случая учитывает смену ключа и слушает событие `storage`: браузер присылает его, когда хранилище изменили в другой вкладке того же сайта.
- Корзину магазина в главе 9 сохранит в `localStorage` Zustand — промежуточный слой `persist` делает то же, что наш хук, для целого хранилища.

::: tip
Если вы пришли из Angular: свой хук похож на функцию с `inject()` и сигналами внутри, а не на сервис. Сервис с `providedIn: 'root'` — один на всё приложение, и все, кто его внедрил, видят одно состояние. Свой хук — нет: каждый компонент, который его вызвал, получает собственные ячейки состояния. Общий «сервис» в React — это контекст (глава 8) или внешнее хранилище (глава 9).
:::
