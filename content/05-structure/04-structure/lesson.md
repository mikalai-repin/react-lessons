У каждой игры будет своя страница: обложка крупно, описание, кнопка «В корзину». Щелчок по названию в карточке открывает страницу вместо каталога, «← К каталогу» возвращает обратно. Значит, `App` должен помнить, какая игра открыта. Вопрос в том, **что именно** помнить: игру целиком, её id, флажок «страница открыта»? Ответ дают несколько принципов, и на них держится всё состояние в React — от `useState` до Redux.

## Пять принципов

1. **Объединяйте связанное.** Если два значения всегда меняются вместе, им место в одном объекте. Пример будет в практикуме: четыре фильтра витрины станут одним объектом.
2. **Избегайте противоречий.** Два поля, которые могут не сойтись, — источник «невозможных» состояний. `isOpen: true` и `selectedId: null` одновременно — страница открыта, а какая? Одно поле `selectedId: number | null` не может противоречить самому себе: `null` — каталог, число — страница этой игры.
3. **Не храните лишнего.** Что вычисляется из другого состояния, вычисляйте при рендере (прошлый шаг).
4. **Не дублируйте.** Одни и те же данные в двух местах рано или поздно разойдутся. Игра уже есть в каталоге `games`, — в состоянии достаточно её `id`, а саму игру найдём при рендере.
5. **Держите данные плоскими.** Глубокая вложенность делает неизменяемые обновления мучительными: каждый уровень нужно копировать. Позиция корзины — `{ gameId, quantity }`, а не копия игры с вложенными `players` и `tags` (глава 4).

## Открытая игра — это id

Компонент страницы готов: `game/GameDetails.tsx` получает игру, количество в корзине и два обработчика — `onAdd` и `onClose`. Состояние и выбор — в `App`:

```tsx App.tsx
  // Какая игра открыта: только id, null — открыт каталог
  const [selectedId, setSelectedId] = useState<number | null>(
    null,
  );
  // Саму игру находим по id при рендере
  const selectedGame = games.find(
    (game) => game.id === selectedId,
  );
```

Тип `number | null` придётся указать: из `null` TypeScript выведет тип `null`, и `setSelectedId(game.id)` не пройдёт. `selectedGame` — производное значение: `Game` или `undefined`, если ничего не открыто.

В разметке `main` одно из двух — страница игры или оба раздела каталога:

```tsx App.tsx {1-9,18,23-24}
        {selectedGame ? (
          <GameDetails
            game={selectedGame}
            quantity={quantityOf(selectedGame.id)}
            onAdd={() => handleAdd(selectedGame.id)}
            onClose={() => setSelectedId(null)}
          />
        ) : (
          <>
            <Section
              title="Хиты"
              …
                  <GameCard
                    key={game.id}
                    game={game}
                    quantity={quantityOf(game.id)}
                    onAdd={() => handleAdd(game.id)}
                    onSelect={() => setSelectedId(game.id)}
                  />
              …
            </Section>
            <Section title="Все игры">…</Section>
          </>
        )}
```

Внутри тернарного оператора нужен один элемент — два раздела обёрнуты во фрагмент `<>`. Количество и «В корзину» страница получает точно так же, как карточка: из корзины по id.

Карточке — новый проп `onSelect`, а название становится кнопкой (стиль `.titleButton` уже в `GameCard.module.css`):

```tsx shared/GameCard.tsx {3-4,9,12-18}
  // Покупатель нажал «В корзину»
  onAdd: () => void;
  // Покупатель открыл страницу игры
  onSelect: () => void;
};
…
  quantity,
  onAdd,
  onSelect,
…
      <h3 className={styles.cardTitle}>
        <button
          type="button"
          className={styles.titleButton}
          onClick={onSelect}
        >
          {game.title}
        </button>
      </h3>
```

Почему кнопка, а не `<div onClick>`? Кнопку можно нажать с клавиатуры (Tab, Enter), а программа чтения с экрана объявит её кнопкой. Когда появится роутер (глава 10), название станет ссылкой на адрес `/games/:id`.

::: task
1. В `GameCard.tsx` добавьте проп `onSelect` и сделайте название кнопкой `<button type="button" className={styles.titleButton}>`.
2. В `App.tsx` заведите `selectedId: number | null` и вычислите `selectedGame` по id.
3. Если игра выбрана, рисуйте в `main` вместо обоих разделов `<GameDetails>` (импорт из `./game/GameDetails`): игра, количество из корзины, `onAdd` и `onClose`.
4. Передайте `onSelect={() => setSelectedId(game.id)}` карточкам в обоих разделах.
:::

## Что получилось

Нажмите на название «Драконья почта»: каталог сменила страница игры — обложка, «Игроки: 2–4 · 30 мин · 7+», рейтинг, цена, описание. «В корзину» — в шапке «Корзина: 1», в мини-корзине позиция, на странице «В корзине: 1 шт.». «← К каталогу» — снова разделы, а под карточкой «Драконьей почты» — «В корзине: 1 шт.». Фильтры, если вы их меняли, остались прежними: они в состоянии `App`, а `App` никуда не исчезал.

## Эксперимент: копия вместо источника

Нарушим четвёртый принцип. Пусть `App` при щелчке запоминает не только id, но и сколько штук игры было в корзине, — «чтобы странице не искать». В начало `App`:

```tsx App.tsx
  const [selectedQuantity, setSelectedQuantity] = useState(0);
```

В обоих разделах — новый `onSelect`, а странице — копия:

```tsx App.tsx
                    onSelect={() => {
                      setSelectedId(game.id);
                      setSelectedQuantity(quantityOf(game.id));
                    }}
…
            quantity={selectedQuantity}
```

Откройте «Ночной экспресс» (на складе 3) и нажмите «В корзину» четыре раза. В мини-корзине «Ночной экспресс − 4 +» — больше, чем есть на складе. На странице ни строки «В корзине», ни выключенной кнопки: для неё в корзине по-прежнему 0. Копия сделана в момент щелчка и с тех пор не меняется, а корзина живёт дальше. С `quantityOf(selectedGame.id)` такой ошибки нет: число каждый раз берётся из единственного источника. Верните код решения.

Та же беда ждёт `useState<Game | null>` — игру целиком в состоянии. Сейчас каталог — константа, и копия совпадает с оригиналом. В главе 11 каталог придёт с сервера и будет обновляться: цена или остаток изменятся, а открытая страница покажет старые.

## Как в настоящем проекте

| Вместо | Храните |
|---|---|
| `selectedGame: Game` | `selectedId: number \| null` |
| `isOpen` + `selectedId` | `selectedId: number \| null` |
| `isSending`, `isSent`, `isError` | `status: 'idle' \| 'sending' \| 'sent' \| 'error'` |
| `items` и `itemsCount` | `items`, а количество — `items.length` |
| вложенные `{ category: { games: […] } }` | плоские списки и ссылки по id |

- Объединение в union (`status`) — тот же принцип «без противоречий»: вместо трёх флажков, которые дают восемь сочетаний, четыре осмысленных состояния. TypeScript проверит, что вы обработали каждое.
- Плоские данные с id — основа нормализации: в главе 19 Redux Toolkit предложит для неё готовый `createEntityAdapter`, а TanStack Query в главе 11 хранит ответы сервера в кэше по ключам вида `['games', id]`.
