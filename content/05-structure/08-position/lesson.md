Этот шаг необязательный. В шаге про сброс состояния отзыв «переезжал» на другую игру, пока мы не дали странице `key`. Разберём, по какому правилу React решает: оставить компоненту его состояние или начать заново, — и проверим правило на нескольких «безобидных» правках, которые незаметно сбрасывают состояние.

## Правило сверки

В главе 4 мы видели: при рендере React сверяет новые элементы со старыми файберами. Для каждого места среди детей родителя он задаёт два вопроса:

1. Совпадает ли **`key`**? (Нет ключа — значит `null`, и у старого тоже `null`.)
2. Совпадает ли **тип** — тот же тег `'main'` или та же функция-компонент `GameDetails`?

Оба ответа «да» — React берёт старый файбер и даёт ему новые props. Состояние, DOM-узлы и всё поддерево остаются. Хоть один «нет» — старый файбер удаляется вместе со всем поддеревом и состоянием, а по новому элементу создаётся новый.

В `react-dom-client.development.js` это видно почти дословно (функция `updateElement`, сокращено):

```js
if (current !== null && current.elementType === element.type) {
  // тот же тип на том же месте — обновить
  return useFiber(current, element.props);
}
// иначе — новый файбер с нуля
return createFiberFromElement(element, …);
```

`key` сравнивается ещё раньше: при другом ключе React даже не смотрит на тип.

**Место** — это порядковый номер среди детей родителя. У `<main>` в магазине три ребёнка:

```
<main>
  0  <p> акция
  1  <MiniCart>
  2  <GameDetails> или <>…</> каталога
```

Имя переменной, условие в JSX, props — ничего из этого в правило не входит. Только место, ключ и тип.

## Подготовка: датчик нового состояния

Нам нужно видеть, когда React **создаёт** состояние заново. Для этого есть форма `useState` с функцией: `useState(() => начальное)`. React вызывает такую функцию только при создании состояния, а не при каждом рендере. Замените в `GameDetails` строку с `review`:

```tsx game/GameDetails.tsx
  const [review, setReview] = useState(() => {
    console.log('новое состояние отзыва:', game.title);
    return '';
  });
```

Второй датчик — где в дереве стоит страница. Добавьте в конец `main.tsx`:

```tsx main.tsx
// Где в дереве файберов стоит компонент с таким именем
function whereIs(name: string) {
  const rootKey = Object.keys(container!).find((k) =>
    k.startsWith('__reactContainer$'),
  )!;
  const find = (fiber: any): any => {
    for (; fiber; fiber = fiber.sibling) {
      if (fiber.type?.name === name) return fiber;
      const found = find(fiber.child);
      if (found) return found;
    }
  };
  const fiber = find((container as any)[rootKey].stateNode.current);
  console.log(
    fiber
      ? `${name}: место ${fiber.index}, key ${fiber.key}, родитель ${fiber.return.type?.name ?? fiber.return.type}`
      : `${name}: нет в дереве`,
  );
}
// После каждого щелчка — когда React закончит обновление
document.addEventListener('click', () =>
  setTimeout(() => whereIs('GameDetails')),
);
```

Функция обходит дерево от корня (как в главе 4) и печатает у файбера `index` — место среди соседей, `key` и родителя. Это внутренние поля React: для экспериментов, не для кода приложения.

## Эксперимент 1: ключ решает

Откройте «Остров сокровищ», затем нажмите «Следующая игра →»:

```
новое состояние отзыва: Остров сокровищ
новое состояние отзыва: Остров сокровищ
GameDetails: место 2, key 1, родитель main
новое состояние отзыва: Драконья почта
новое состояние отзыва: Драконья почта
GameDetails: место 2, key 2, родитель main
```

Каждая строка датчика дважды — строгий режим вызывает и функцию начального значения два раза. Место то же, тип тот же, но ключ сменился с 1 на 2 — новое состояние. Напишите отзыв и нажмите «В корзину»: строки «новое состояние» нет, отзыв на месте — место, ключ и тип совпали.

Уберите `key={selectedGame.id}` в `App` и повторите: после «Следующей» строки «новое состояние» нет, `key null`, отзыв «Острова» у «Драконьей почты». «← К каталогу» — `GameDetails: нет в дереве`: на месте 2 теперь фрагмент каталога, другой тип, страница удалена. Верните ключ.

## Эксперимент 2: обёртка

Безобидная на вид правка: пусть страница игры, которая уже лежит в корзине, получает рамку. Оберните `<GameDetails … />` в `App` условием:

```tsx App.tsx
          quantityOf(selectedGame.id) > 0 ? (
            <div className="in-cart">
              <GameDetails … />
            </div>
          ) : (
            <GameDetails … />
          )
```

Откройте «Драконью почту», начните отзыв, нажмите «В корзину». Отзыв исчез, в консоли — «новое состояние отзыва: Драконья почта» и `GameDetails: место 0, key 2, родитель div`. На месте 2 у `<main>` раньше был `GameDetails`, а стал `div` — другой тип. React удалил страницу со всем состоянием и построил новую внутри `div`. Ключ тот же, но он сравнивается только среди соседей одного родителя, а родитель сменился. Верните код.

## Эксперимент 3: `false` держит место

Скроем акцию, когда в корзине что-то есть. Оберните `<p className={styles.promo} … />` условием `{cartCount === 0 && (…)}`. Откройте «Драконью почту», начните отзыв, нажмите «В корзину». Акция исчезла, а отзыв на месте, и датчик говорит: `место 2`.

Почему страница не сдвинулась на место 1? Выражение `{cartCount === 0 && …}` всегда занимает своё место среди детей — даже когда его значение `false` и рисовать нечего. `false`, `null` и `undefined` не попадают в DOM, но место за ними сохраняется. Поэтому условный рендер через `&&` и тернарный оператор не сдвигает соседей. Верните код.

## Тот же тип в обеих ветках

Последнее следствие правила — с компонентом `Field`, у которого внутри своё состояние текста:

| Запись | После переключения |
|---|---|
| `{isA ? <Field label="A" /> : <Field label="B" />}` | текст сохранился |
| `{isA && <Field label="A" />}{!isA && <Field label="B" />}` | текст сброшен |
| `{isA ? <Field key="a" … /> : <Field key="b" … />}` | текст сброшен |
| `{isA ? <Field … /> : <div><Field … /></div>}` | текст сброшен |

В первой строке у React нет способа отличить «два разных поля»: одно место, один тип — один компонент, сменился только `label`. Во второй — два места: первое опустело, второе заполнилось. Третья — ключи. Четвёртая — другой тип на месте. Всё это проверено запуском.

## Что из этого следует

- **Не объявляйте компонент внутри другого компонента.** `function Field() {}` в теле `App` — новая функция при каждом рендере `App`, то есть **новый тип**. React каждый раз удаляет старый и создаёт новый — с потерей состояния и DOM (врезка шага «Свой компонент», глава 3).
- **Обёртки по условию сбрасывают всё внутри.** Нужен условный стиль — меняйте `className`, а не структуру дерева.
- **`key` — ваш рычаг.** Сменить ключ — сбросить, сохранить ключ при переносе внутри списка — переместить вместе с состоянием (эксперимент с полями в главе 2).
- Состояние хранится в файбере, а не в функции компонента. Пока файбер на месте, хуки получают из него сохранённые значения по порядку вызова — поэтому порядок хуков и важен (глава 7).

Уберите датчики из `GameDetails` и `main.tsx`.
