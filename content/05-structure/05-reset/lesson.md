На странице игры покупатель сможет оставить отзыв, а кнопкой «Следующая игра →» листать каталог, не возвращаясь в него. Обе вещи простые, но вместе они покажут важное свойство React: состояние принадлежит не компоненту «вообще», а **месту в дереве**, где этот компонент нарисован.

## Отзыв и следующая игра

Стили формы и строки навигации готовы в `GameDetails.module.css`. В компоненте страницы — состояние отзыва:

```tsx game/GameDetails.tsx {1-3,5-9}
  // Текст отзыва и отправлен ли он
  const [review, setReview] = useState('');
  const [sent, setSent] = useState(false);

  function handleReviewSubmit(e: SubmitEvent<HTMLFormElement>) {
    e.preventDefault();
    setReview('');
    setSent(true);
  }
```

Поле отзыва — управляемое: под ним живой счётчик символов, а кнопка выключена, пока отзыв пуст. Это ровно тот случай, когда значение нужно во время ввода. У `<textarea>` в React тоже `value`, а не текст между тегами, как в HTML:

```tsx game/GameDetails.tsx
      <form
        className={styles.review}
        onSubmit={handleReviewSubmit}
      >
        <label htmlFor="review">Ваш отзыв об игре</label>
        <textarea
          id="review"
          className="search"
          maxLength={REVIEW_MAX}
          value={review}
          onChange={(e) => setReview(e.target.value)}
        />
        <div className={styles.reviewFooter}>
          <span>
            {review.length} / {REVIEW_MAX}
          </span>
          <Button type="submit" disabled={review.trim() === ''}>
            Отправить
          </Button>
        </div>
      </form>
      {sent && (
        <p className={styles.thanks}>
          Спасибо! Отзыв появится после проверки.
        </p>
      )}
```

`REVIEW_MAX = 300` — константа над компонентом. `Button` по умолчанию `type="button"` (глава 3), поэтому для отправки формы `type="submit"` указан явно.

«← К каталогу» и «Следующая игра →» стоят в одной строке `<div className={styles.nav}>`, у второй кнопки — новый проп `onNext`. Какая игра следующая, знает `App`:

```tsx App.tsx
  // Следующая игра каталога; после последней — снова первая
  function handleNext() {
    const index = games.findIndex(
      (game) => game.id === selectedId,
    );
    setSelectedId(games[(index + 1) % games.length].id);
  }
```

Странице передайте `onNext={handleNext}`.

## Ошибка: отзыв уехал на другую игру

Откройте «Остров сокровищ», начните отзыв: «Отличная игра». Нажмите «Следующая игра →». Открылась «Драконья почта» — а в поле по-прежнему «Отличная игра», счётчик «13 / 300». Отправьте отзыв и снова нажмите «Следующая»: у «Ночного экспресса» висит «Спасибо! Отзыв появится после проверки.», хотя о нём никто ничего не писал.

Почему React не сбросил состояние? Посмотрим, что он видит до и после щелчка:

```
до:                     после:
<main>                  <main>
  <p> акция               <p> акция
  <MiniCart>              <MiniCart>
  <GameDetails            <GameDetails
    game={Остров}>          game={Драконья}>
```

На третьем месте внутри `<main>` был `GameDetails` — и остался `GameDetails`. Поменялся только проп `game`. Для React это **тот же самый компонент** с новыми props, а состояние компонента сохраняется, пока он стоит на своём месте в дереве. Хуки `useState` возвращают то, что в них уже лежит, — и текст отзыва, и `sent`.

Состояние сбрасывается, когда на этом месте оказывается **другой** компонент или ничего. Проверьте: начните отзыв, нажмите «← К каталогу» и откройте ту же игру снова — поле пустое. Каталог занял место страницы, `GameDetails` исчез из дерева вместе со своим состоянием, а новый начал с `useState('')`.

## key: «это другой компонент»

Ключ знаком по спискам (глава 2): по нему React узнаёт элемент среди соседей. Но `key` работает у любого элемента: **другой ключ — другой компонент**, даже если тип и место те же. Старый React уберёт вместе с состоянием, новый создаст с нуля.

Дадим странице ключ — id игры:

```tsx App.tsx {2}
          <GameDetails
            key={selectedGame.id}
            game={selectedGame}
            quantity={quantityOf(selectedGame.id)}
            onAdd={() => handleAdd(selectedGame.id)}
            onClose={() => setSelectedId(null)}
            onNext={handleNext}
          />
```

Теперь у каждой игры своя страница со своим состоянием: сменилась игра — сменился ключ — React начинает с чистого листа. В самом `GameDetails` ничего не меняется: компонент не знает и не должен знать, что его будут сбрасывать.

::: task
1. В `GameDetails.tsx` добавьте состояния `review` и `sent`, обработчик `handleReviewSubmit` (отменить отправку, очистить поле, отметить отправку) и форму: подпись, управляемая `<textarea>` с `maxLength`, счётчик «N / 300», кнопка «Отправить» (выключена при пустом отзыве), под формой — «Спасибо! …» после отправки.
2. Оберните «← К каталогу» в `<div className={styles.nav}>` и добавьте кнопку «Следующая игра →» с новым пропом `onNext`.
3. В `App.tsx` напишите `handleNext` и передайте его странице. Проверьте ошибку из текста.
4. Исправьте её ключом `key={selectedGame.id}`.
:::

## Что получилось

Начните отзыв у «Острова сокровищ» и нажмите «Следующая игра →»: у «Драконьей почты» поле пустое. Отправьте отзыв — «Спасибо!…» — и листайте дальше: у следующей игры его нет. После «Космических котов» снова «Остров сокровищ».

## Как в настоящем проекте

- `key` для сброса — стандартный приём: форма редактирования профиля `key={user.id}`, переписка `key={chatId}`, мастер заказа, который начинают заново. Это проще и надёжнее, чем вручную обнулять каждое поле при смене props.
- Сброс через `key` пересоздаёт всё поддерево: DOM-узлы, состояние всех детей. Для формы это и нужно; для тяжёлого поддерева это заметная работа, поэтому ключ ставят на то, что действительно нужно сбросить, а не «на всякий случай» сверху.
- Бывает наоборот: черновик отзыва нужно **сохранить** для каждой игры, даже когда покупатель ушёл в каталог. Тогда состояние поднимают выше того места, которое исчезает, и хранят по id: `drafts: Record<number, string>` в `App`. Компонент страницы получает свой черновик в props.

::: warning
Не сбрасывайте состояние эффектом «при смене `game`»: `useEffect(() => setReview(''), [game.id])`. Сначала React зафиксирует в DOM страницу новой игры со старым отзывом, и только потом эффект запустит второй рендер. Эффекты — глава 6, и этот случай там разобран как лишний эффект. Правильный инструмент — `key`.
:::
