Фильтры каталога работают, но живут в `App` россыпью: четыре `useState`, тип `SortOrder`, `COMPARE` и три десятка строк разметки полей. А покупатель, который выбрал «Детские», видит пустое место и не понимает, что случилось. Соберите из этого **витрину**: отдельный компонент фильтров, одно состояние вместо четырёх, число найденных игр и понятное пустое состояние с кнопкой «Сбросить фильтры».

Что уже в проекте:

- `catalog/filters.ts` — готов: тип `Filters` (все четыре фильтра одним объектом), `INITIAL_FILTERS` (витрина без фильтров) и функция `filterGames(games, filters)` — та же фильтрация и сортировка, что сейчас в `App`;
- `catalog/CatalogFilters.module.css` — стили панели (`.toolbar`, `.field`, `.check` переехали сюда из `App.module.css`), в `App.module.css` — стиль пустой витрины `.empty`;
- `catalog/CatalogFilters.tsx` — только комментарий `TODO`.

::: task
1. В `catalog/CatalogFilters.tsx` напишите компонент `CatalogFilters` с props `filters: Filters` и `onChange: (filters: Filters) => void`. Разметку четырёх полей перенесите из `App`; каждое поле управляемое и при изменении вызывает `onChange` с **новым** объектом фильтров, где изменено одно свойство.
2. В `App.tsx` замените четыре состояния одним: `filters`, начальное значение — `INITIAL_FILTERS`. `visibleGames` — через `filterGames`. Удалите из `App` типы `CategoryFilter`, `SortOrder`, `Compare`, объект `COMPARE` и лишние импорты.
3. В разделе «Все игры» вместо панели нарисуйте `<CatalogFilters>`, а в `extra` раздела — `<Badge tone="dark">` с числом найденных игр.
4. Если не нашлось ни одной игры, вместо сетки — `<div className={styles.empty}>` с текстом «Ничего не нашлось» (класс `muted`) и кнопкой `<Button>` «Сбросить фильтры», которая возвращает `INITIAL_FILTERS`.
5. Уберите из `App.module.css` классы `.toolbar`, `.field` и `.check` — теперь они в стилях `CatalogFilters`.
:::

::: hint Подсказка 1: с чего начать
Начните с `App`: одно состояние `useState(INITIAL_FILTERS)` и `filterGames(games, filters)`. Тип TypeScript выведет из `INITIAL_FILTERS` — у константы он указан явно. Пока панели нет, проверьте, что каталог рисуется, затем переносите поля в `CatalogFilters`.
:::

::: hint Подсказка 2: одно поле — одно свойство
Каждое поле меняет одно свойство и сохраняет остальные. Это spread из главы 4:

```tsx
onChange={(e) =>
  onChange({ ...filters, query: e.target.value })
}
```

У флажка — `inStockOnly: e.target.checked`, у списков — значение с приведением типа: `e.target.value as CategoryFilter`, `e.target.value as SortOrder` (типы импортируйте из `./filters`).
:::

::: hint Подсказка 3: почему props так устроены
`CatalogFilters` не хранит фильтры у себя: он **управляемый компонент**, как поле ввода. Значение приходит сверху (`filters`), изменения уходят наверх (`onChange`), а хранит их `App`, потому что от фильтров зависит его список. Поэтому в `App` достаточно `onChange={setFilters}` — сеттер и есть функция, которая принимает новый объект фильтров.
:::

::: hint Подсказка 4: пустое состояние
Тернарный оператор по длине списка:

```tsx
{visibleGames.length === 0 ? (
  <div className={styles.empty}>
    <p className="muted">Ничего не нашлось</p>
    <Button onClick={() => setFilters(INITIAL_FILTERS)}>
      Сбросить фильтры
    </Button>
  </div>
) : (
  <div className="grid">…</div>
)}
```

`Button` импортируйте из `./shared/Button`.
:::

## Проверьте себя

- При запуске в заголовке «Все игры» бейдж «6».
- Введите в поиск «о» — бейдж «4». Отметьте «Только в наличии» и выберите «Сначала дорогие»: «Ночной экспресс», «Остров сокровищ», «Космические коты», «Драконья почта».
- Выберите категорию «Детские» — бейдж «0», вместо сетки «Ничего не нашлось» и «Сбросить фильтры». Нажмите кнопку: поиск пуст, «Все», «Как в каталоге», флажок снят, снова шесть игр. Поля сбросились сами, потому что они управляемые: их значения пришли из нового состояния.
- Выберите «Стратегии», откройте «Ночной экспресс» и вернитесь в каталог: фильтр «Стратегии» на месте. Панель исчезала из дерева вместе с каталогом, но фильтры хранятся в `App`, а не в ней.
- Консоль пуста, ошибок типов нет.

## Итоги главы

Магазин научился искать, фильтровать и сортировать, подписывать на новости, показывать страницу игры с отзывом, а корзина живёт в редьюсере. Главное в главе — не новые API, а решения: **что** класть в состояние и **где** его держать.

| Запись | Что делает |
|---|---|
| `value={query}` + `onChange={(e) => setQuery(e.target.value)}` | управляемое поле: значение — из состояния |
| `checked={on}` + `e.target.checked` | управляемый флажок |
| `defaultValue`, `defaultChecked` | неуправляемое поле: только начальное значение |
| `new FormData(e.currentTarget)` | значения формы в момент отправки |
| `const visible = games.filter(…)` | производное значение — вычислить, а не хранить |
| `useState<number \| null>(null)` | id вместо объекта; `null` — «ничего не выбрано» |
| `<GameDetails key={game.id} />` | другой ключ — другой компонент, состояние с нуля |
| `const [cart, dispatch] = useReducer(reducer, initial)` | состояние, которое меняют действия |
| `dispatch({ type: 'added', gameId })` | сообщить, что случилось |
| `useImmerReducer(reducer, initial)` | редьюсер, который меняет черновик Immer |

И несколько важных идей:

- управляемое поле — когда значение нужно во время ввода, неуправляемое — когда только при отправке;
- в состоянии — минимум: то, что нельзя вычислить. Остальное считается при рендере и потому никогда не устаревает;
- без противоречий и дублей: одно поле `selectedId` вместо пары флажков, id вместо копии объекта;
- состояние привязано к месту в дереве: тот же тип и тот же `key` на том же месте — состояние сохраняется; другой тип, другой ключ или пустое место — сбрасывается;
- редьюсер собирает все изменения состояния в одну чистую функцию, а Immer позволяет описывать их изменением черновика — без копирования каждого уровня вручную.

Всё это время мы жили внутри React: состояние, рендер, DOM, который React строит сам. Но приложению нужен и внешний мир: поставить фокус в поле поиска, запустить таймер скидки, подписаться на изменение размера окна, следить за сетью. В главе 6 появятся ссылки (`useRef`) и эффекты (`useEffect`) — и правило, которое отличает хороший эффект от лишнего.
